# 长命百岁（Live a Long Life）

长命百岁是一款本地优先的个人健康记录应用。它像聊天一样收集你每天的饮食、睡眠、心情、不适和运动，自动整理成结构化记录；把病历、检验单、检查报告变成可核对、可追溯到原件的数据；每周生成周报，帮你看清长期的变化。

数据保存在你自己的设备上。手机负责记录，电脑负责分析和归档，两者在同一个局域网内加密同步。是否使用模型、使用哪家的模型、模型跑在本机还是云端，都由你决定。

## 功能

### 日常记录（iPhone）

![首页像聊天一样记录：刚装好时和记了几天之后](docs/images/record.png)

- **像聊天一样记录**：连续发文字，每条立即保存；照片和 PDF 从病例夹或体检添加；可以修改或删除，修改历史保留。
- **主动回顾**：按你设定的时间提醒回顾当天，只问还没记下的内容（早饭吃了什么、昨晚几点睡、今天有没有运动……）。
- **自动整理**：模型把消息整理成饮食、睡眠、心情、不适、运动、笔记等记录；"昨天忘了说的"会记到昨天。每条记录都能找回原话，你改过的字段不会被再次覆盖。
- **读取苹果健康**：睡眠、步数、体能训练、活动能量作为补充，减少手动输入；你亲口说的内容优先。
- **按日查看**与逐条修正记录；不要的记录可以删除，删除时可以选择连原消息一起删。
- **个人资料**逐步收集（出生年月、性别、身高、运动偏好、慢性病、过敏等），每一项都可以跳过。
- **导出与恢复**：导出为 JSON 加文件夹（带文件清单），可以从导出恢复，包括病例夹、体检和咨询记录。安卓上也可以直接选别的设备导出后压缩成的 zip 恢复。在原应用里恢复后，手机再同步时电脑端首页会提示重建副本：确认后先自动备份，再以手机现有的数据为准重新接收；卸载重装或换手机后恢复的，在电脑上重新配对即可继续同步。
- **iCloud 备份**：在"文件"里选一个 iCloud 云盘里的文件夹，打开、离开应用时内容有变化就自动备份，也可以手动立即备份；可以选择用备份密码加密。附件只存一份、只上传新增的；每天保留最后一份，最多 4 天。换手机或卸载重装后，在首次引导或设置里选同一个文件夹、挑一份备份即可恢复，之后接着备份到这里。不含模型配置和 key。

### 病历与检查单（iPhone）

<p align="center"><img src="docs/images/archive.png" alt="健康档案页汇总病例夹、体检、长期状况、时间线、人体图、指标趋势、周报和修正建议" width="560"></p>

- **健康档案**：首页底栏的入口，病例夹、体检、长期状况、就诊时间线、人体图、指标趋势、周报、修正建议都在这一页，旁边标着几份待核对、几份未提取、几条修正建议待处理；有待处理的修正建议时底栏图标上有角标。
- **病例夹与体检**：拍照、从相册选择或导入 PDF，列表按就诊或体检日期排列。提取时模型会按单据给每次就诊起个标题（比如"膝关节扭伤复诊""急性咽炎"），列表上直接看出是为什么去的，标题也可以自己改。重复上传时会提醒；同一张纸重拍、重新导出（字节不同）也能按识别出的内容认出来。
- **先预览，再发送**：在本机完成文字识别（Apple Vision，PDF 有文字层时直接读取），自动遮蔽姓名、证件号和门诊卡号；把将要发给模型的全部文字逐行展示给你，可以修改或删行，也可以多选批量删除（修改随文件保存，下次重新提取时自动恢复），确认后才发送。页数多的体检报告会自动分批整理。除非你主动选择下面的"模型识图"，图片不会发给模型。
- **模型识图兜底**：手写、拍歪、版式复杂、本机识别不准的报告，可以手动选择"用模型识图"：先在图上框出要识别的部分，把姓名等区域留在框外，只有框里的图片会发给支持图片的模型，裁剪图用完即弃。
- **模型整理文字**：超声等报告常把同一部位的描述和结论拆成两条，体检报告的汇总和明细也会重复。可以点"用模型整理"，把已提取的诊断与检查文字发给模型，同一部位的合成一条、重复的去掉，"其他：未见异常"和"检测结果及疾病诊断，请咨询医生"这类没有内容的条目删掉，原文不改写；只发这些文字，不发图片。合并出来的条目要重新核对，可以撤销。
- **结构化提取**：检验数值（项目、结果、单位、参考范围、异常标记）、诊断与检查文字（主诉、诊断、处理意见、超声所见和结论等）、处方药品、身体状况建议。模型会根据上下文修正识别错字，并逐处列出修正供你核对。
- **逐项核对**：所有提取结果默认"未核对"，你确认或修改后才参与分析。文件顶部显示核对进度和异常数，可以只看未核对或只看异常，异常数值加粗标红；"全部确认"和删除都可以撤销。重新提取、用模型识图、整理文字、补大项收在"更多"里，各带一句什么时候用。诊断与检查文字、检验结果、处方药品里不需要的条目（比如空的备注栏）可以逐条删除。每个数值、每段文字都能跳回原件，并在对应位置显示高亮框。识别出的医疗机构、检查日期不对可以直接改，没识别出来的可以补填；改过的重新提取也不会被覆盖，检查日期改了，指标趋势和身体状况按新日期排。重新提取后，这份报告以前建议、还没核对、这次又没提取出来的身体状况会去掉，已确认的保留。
- **长期状况档案**：区分长期状况（结石、慢性病、过敏等）和临时疾病。标记已痊愈的长期状况，周报和咨询里只作为既往病史参考，不按现有疾病给建议；已痊愈的临时疾病不再参与。提取错了、本来就不是疾病的条目（比如"乙肝表面抗体阳性"）可以删除，重新提取报告也不会再建议回来。复查、康复以追加方式记录，既往诊断和当时的指标不会被改写。不同年份报告里的同一问题归成一行，显示最新那份报告的写法，也能打开以前报告的原件。档案按身体系统（消化、心血管、骨骼肌肉、皮肤等）分组，既往病史和临时疾病单独收起；同一种病的不同叫法会自动合并，拿不准的会提示你确认，也可以手动合并或取消合并。

![病例夹、体检和长期状况档案（个人信息已打码）](docs/images/files.png)

- **指标趋势与就诊时间线**：顶部可以搜索，项目名、英文缩写（ALT、HGB）、以前的写法或检查大项都能搜到。点开一项，趋势图下面有"这一项是什么"：含义、偏高（或阳性）和偏低可能意味着什么、常和哪些指标一起看；常见项目内置了说明，目录外的项目可以让模型生成一次（只发项目名称、分组和单位），身高体重、过敏原这类不需要的不显示。同一检验项目按检查日期画出变化曲线，并标出参考范围；不同医院、不同年份的写法（比如"淋巴细胞比值"与"淋巴细胞百分数"、"BMI"与"体重指数"、"谷丙转氨酶"与"丙氨酸氨基转移酶"）归为同一项，按内置指标目录的标准中文名显示；提取报告时模型会把项目对号入座到标准名或已有项目上，拿不准的（比如没标大项、可能是尿检的葡萄糖）列进"整理项目名称"等你确认，也可以让模型整理已有的项目名（只发项目名称、分组和单位，不发数值），或在详情里手动合并、拆出；项目名前表示检验结果互认的"*"也不影响，小数比值（包括写成 0.45 的红细胞压积、0.27 的大血小板比率）换算成百分数再画；尿常规、便常规的"阴性""neg""未见"按 0 画，"±"和"+"到"++++"按 0.5 和 1 到 4 画；血压写成一项"122/86"的拆成收缩压、舒张压，和分开写的、复测的画在同一条线上，没测的"-"不画。列表按检查大项（血常规、尿常规、肝功能、血脂、肿瘤标志物、过敏原检测……）分组，目录里的项目按目录分组，不同医院对同一类检查的叫法归成一组，没标大项的按项目认（血压、血型、乙肝、过敏原等），尿常规的白细胞、葡萄糖、胆红素等和血里的同名项目分开，人体图上归到肾和膀胱；早先提取的报告、或长报告分批提取时漏标的，可以在详情页用模型补上大项（只发项目名称和已有的大项，不发数值）；症状、就诊、检查按时间排列。

![指标趋势列表和单项详情](docs/images/trends.png)

- **人体图**：首页底栏正中的彩色人体入口。全身图上点头颈部、胸部、腹部或盆腔，画面拉近到这一块，器官标签排在两侧，用指引线指到对应位置；盆腔按资料里的生理性别显示男女不同的器官，右上角也可以切换。有需要关注的内容时标签上会显示条数，红色表示已核对、橙色表示待核对：包括最近一次仍异常的检验数值、报告里的异常描述、未解除的身体状况，以及近 30 天的身体不适。同一个问题只算一次：体检报告汇总和明细各写一遍的会合并，不同年份的报告写了同一个问题（比如肾囊肿从 5 毫米长到 8 毫米）按最新的算，以前的写法列在「此前」里。点标签列出具体内容，每条都能跳回原文件。血脂、血糖、血常规等不对应单个器官的，归在图下方的「血液与代谢」；认不出部位的归在「其他」。

![人体图：刚装好、有了报告之后、点头颈部拉近](docs/images/bodymap.png)

- **周报**：用默认模型总结一周的饮食、睡眠、运动、心情与不适，给出下周的饮食、运动、睡眠建议，会结合你确认过的长期状况；每条事实陈述都可以点回来源记录。在"健康档案 → 周报"里随时生成近 7 天的；在设置里打开"自动生成周报"后，每周第一次打开应用时自动生成上周（周一到周日）的，模型连不上时不会改用别的模型，下次打开再试。生成之后记录或健康数据有变化，会提示这份周报可能过期。

- **手机空间清理**：原件已在电脑上归档后，可以清理手机上的副本释放空间，提取出的数据、核对状态、来源定位全部保留；需要时再从电脑取回。

### 主动咨询（iPhone、Mac）

![咨询：从示例问题开始，回答结合你的资料](docs/images/consult.png)

- 临时想问的健康问题可以直接问模型。模型先拿到基本资料和你确认过的身体状况；需要具体数据时，它会自己查你的记录、苹果健康数据、检验指标历史和报告结论（医疗内容只查你核对过的），再根据查到的回答。在 iPhone 上，问到"昨晚睡得怎样""这次运动心率如何"这类问题时，它会实时读取"健康"App 里的心率、睡眠分期、血氧、血压、体重等数据，读到的数据不保存在应用里。查了什么列在问题下方，每一轮发出的内容都能在调用记录里看到。不想让模型查阅时，关掉"允许模型查阅我的记录"即可，这时只发基本资料和身体状况。输入框上方有按你已有数据生成的示例问题（睡眠、运动、检验指标、报告等），点一下就填进输入框，可以改了再发。
- 咨询不会变成健康记录；回答边生成边显示，按格式排版。模型不做诊断、不给用药方案，需要就医时会明确建议。

### 电脑端（Mac、Windows）

- **完整副本**：保存手机同步来的全部消息、记录和原件，只读不改。
- **周报**：查看手机生成、同步过来的周报，每条事实陈述都可以点回来源记录。
- **病例与健康档案**：只读查看病例夹、体检、长期状况档案、指标趋势、就诊时间线，并对照归档的原件。
- **加密备份**：按文件清单生成加密整包，校验通过后才算可用；可以做恢复演练。备份密码只存在本机的系统加密存储里（Mac 钥匙串；Windows 用凭据管理器保管的密钥加密）。
- **扫码配对**：手机扫描电脑上的二维码，建立双向认证的加密连接，之后在同一局域网内自动增量同步，支持断点续传。电脑换了 IP 地址时，手机会在局域网里自动找到它（Bonjour），不用重新配对。
- **常驻菜单栏 / 系统托盘**：关掉主窗口后应用留在 Mac 菜单栏或 Windows 任务栏右下角的托盘里，照常接收手机同步；菜单里显示最近一次同步，可以重新打开窗口或退出。Windows 只运行一个实例，安装时可选开机自启（只留托盘图标，不弹窗口）。

## 隐私与数据

- **本地优先**：数据存在设备本地的 SQLite 数据库里，没有应用自己的服务器。
- **同步只在局域网**：手机与电脑双向认证、全程加密。
- **云端只有你开启的备份**：iCloud 备份默认关闭，开启后只写到你自己选的 iCloud 云盘文件夹；选择加密时，没有备份密码看不到内容。
- **模型由你选择**：支持 OpenAI、Anthropic、DeepSeek、Kimi、智谱 GLM、Ollama（本机或局域网）和任意 OpenAI 兼容服务，只需填 Base URL 和 Key。每个模型标明数据边界（本机、局域网、云端），本机模型不可用时绝不会自动改用云端。模型暂时连不上时，消息照样保存，对话里会提示"当前模型不可用"，日历视图里先列出当天待整理的原文，模型恢复后自动补整理。API Key 只存在系统钥匙串里。

![模型设置：选服务商、填地址和 key、标明数据边界](docs/images/models.png)

- **发送内容可查**：每一次模型调用都会记录发送了什么、返回了什么、遮蔽了几处，可以在"模型调用记录"里查看。

<p align="center"><img src="docs/images/calllog.png" alt="模型调用记录：每次调用的时间、成败、功能和发送条数" width="560"></p>

- **未核对不算事实**：模型推断的内容在你确认前不参与分析。

## 构建与运行

需要 Flutter 3.38 或更高版本（Dart 3.10）、Xcode，以及一个 Apple 开发者账号（免费账号即可）。

```bash
cd app
flutter pub get
dart run build_runner build --force-jit --delete-conflicting-outputs  # 生成数据库代码
flutter test                                                           # 运行测试
```

**安装到 iPhone**：先在 `app/` 下运行 `cp Signing.example.xcconfig Signing.xcconfig`，填入自己的 Apple 开发者 team ID、bundle ID 和 iPhone 的设备 ID（这个文件不进 git）。之后连接手机运行 `./scripts/resign-install.sh`。脚本会构建、签名，并覆盖安装，保留原有数据。不要用 `flutter install`，它会先卸载应用、清掉数据。签名到期前，再运行一次脚本即可续期。

**运行 Mac 端**：

```bash
cd app
flutter build macos --debug
open build/macos/Build/Products/Debug/live_a_long_life.app
```

首次使用时，在 Mac 的"设置 → 手机连接"里显示二维码，用手机的"设置 → 连接电脑"扫码配对。

**运行 Windows 端**：在 Windows 上 `cd app && flutter run -d windows`。打安装包需要 VS C++ 工具和 Inno Setup 6.5+，在 Git Bash 里运行 `./scripts/windows-package.sh`，产物在 `app/build/windows/installer/`；安装到当前用户目录，不需要管理员权限，覆盖安装和卸载都不动用户数据。已安装的版本在托盘里运行时，再启动（包括 `flutter run`）只会叫回已有窗口，调试前先从托盘退出。

**常见问题**：安装时提示 framework 签名无效，或者安装后打开是空白页，一般是原生组件的构建缓存残留，在 `app/` 下运行 `flutter clean` 后重新构建即可。

## 项目结构

```
app/                 Flutter 应用（iPhone、安卓、Mac 与 Windows 共用一套代码）
  lib/data/          数据库表、仓库、时间与字段元数据
  lib/services/      整理、提取、脱敏、同步、备份、分析、咨询等服务
  lib/ui/            页面
  ios/ macos/        平台工程（Apple Vision 文字识别在这里实现）
  android/           安卓工程（ML Kit 文字识别、局域网发现）
  windows/           Windows 工程（系统托盘、局域网广播）
  test/              单元测试与组件测试
docs/                需求、设计决策、数据模型、产品规格、提示词、平台状态、开发说明；images/ 为 README 配图
scripts/             一键重签安装脚本、Windows 打包脚本、人体图抠图脚本
```

设计文档从 [docs/README.md](docs/README.md) 开始阅读；发给模型的全部提示词见 [docs/prompts.md](docs/prompts.md)。

## 说明

长命百岁只做个人健康记录和纵向趋势分析，不提供医疗诊断。任何健康问题请以医生的意见为准。
