## 🛡️ 三档权限，自己选

点「🔧 深度修复」后会弹出协议，选一档：

| 档位 | 它会做什么 | 什么时候用 |
|---|---|---|
| 👁 **只读体检** | 只看不改。想动系统一律被拦下 | 只想搞清楚病因，不敢让它动手 |
| ✋ **受限模式**（推荐） | 可能改系统的操作，每一次都弹窗问你 | 绝大多数情况都用这个 |
| ⚡ **完全模式** | 直接执行，不逐条询问 | 你已经确认问题在哪，想让它一口气改完 |

**无论哪一档，以下命令永远被硬拦，不会执行：**

## 📖 快速开始

> **适用环境**：Windows PE（Win7 ～ Win11 内核均可），**需要联网**。
> **下载**：见 [Releases 页面](https://github.com/ziyouzhiyi666888/PE_SmartFixer/releases/)，按需下精简包或完整包。

1. **解压**，把所有文件解到同一个目录（比如 U 盘的 `X:\PE_SmartFixer\`）
2. **填 Key**：用记事本打开 `config.json`，把这里换成你的 API Key：
   ```json
   "api_key": "在这里填你的 API Key"
   ```
3. **以管理员身份运行**  `PE_SmartFixer.exe`
   > 普通双击权限不够，写不进系统盘。必须右键 →「以管理员身份运行」。

4. **描述问题**：在输入框里写现象，比如「开机蓝屏 0x0000007B」；也可以点 `📷 选择截图` 选蓝屏照片（可选，最多 3 张）
5. **先试诊断**：点 `🚀 开始诊断`，等 10–60 秒，看 AI 怎么说
6. **搞不定再上深度修复**：点 `🔧 深度修复`，选一个权限档位，勾同意，点启动

## 🔄 失败几次之后会怎样

程序记得你试过什么。同一个系统盘上：

- **常规诊断 3 次没修好** → 截图和诊断按钮会被锁住，只剩深度修复
- **深度修复又 3 次没成** → 全部锁住，只剩 `📄 导出诊断报告`

**这不是在限制你，是在保护你的硬盘。** 连续这么多次修不好，通常说明是硬件坏了或者病毒太狠，继续乱试只会让情况更糟。锁住之后：

- 点 `📄 导出诊断报告`，会生成一份 `.txt`，里面是完整的诊断过程、试过什么、失败在哪
- 拿这份报告去找人帮忙，比自己瞎试强
- 想重置重来：删掉目标盘的 `X:\Windows\pe_fix_memory.json`（X 是你的系统盘）

**记录存在哪里？** 存在**目标系统盘**的 `X:\Windows\pe_fix_memory.json`，不写进 PE 自身，换台电脑自动隔离。

## ✅ 它能修什么

- 硬盘模式切换（AHCI / RAID / IDE）导致的 `0x0000007B` 蓝屏
- 关键系统服务被禁用导致的启动失败
- 缺失或损坏的系统驱动文件（如 `iaStorV.sys`）
- 第三方优化工具误改注册表导致的崩溃
- 驱动冲突、驱动加载失败导致的蓝屏
- **v1.2 新增**：以上都不符合、但确实是系统层面的问题——深度修复会自己判断该怎么弄

## ❌ 它修不了什么

- 硬件物理故障（硬盘坏道、内存损坏、主板故障）
- 引导记录损坏（MBR / UEFI 引导丢失）—— **深度的命令被硬拦，需要你手动用 PE 自带的引导修复工具**
- BIOS / UEFI 固件设置（启动顺序、硬盘模式）
- 全盘加密（BitLocker）
- 数据恢复（误删文件、格式化）
- 没网的情况下做 AI 诊断

## ❓ 常见问题

**Q1：提示「无法读取 config.json」？**
确保 `config.json` 跟 exe 在同一目录，格式没被记事本改坏。

**Q2：提示「缺少 api_key」？**
打开 `config.json` 填进去。注意别把引号删了。

**Q3：AI 请求超时或失败？**
先确认 PE 能上网（能打开网页）。国内需要能访问阿里云的接口。

**Q4：点了「深度修复」没反应 / 提示找不到智能体？**
说明你用的是精简包，或者 `reasonix`、`bash` 两个文件夹没跟 exe 放在一起。下完整包，或者把这两个文件夹挪过来。

**Q5：深度修复报到一半说「已阻塞」，是不是坏了？**
不一定是。**它可能已经改成了一部分。** 看到「已阻塞」先自己确认一下要改的东西现在什么样，别只看结论。常见原因是命令被安全规则挡住了。

**Q6：修复之后蓝屏依旧怎么办？**
程序会留备份：
- 文件备份：原文件同目录下的 `.bak`
- 注册表备份：`X:\Windows\服务名_Start_backup.reg`
- 再跑一次程序，会自动回滚上次改动的启动键值

**Q7：目标盘的 `pe_fix_memory.json` 是什么？能删吗？**
是记录本机修过几次、试过什么的文件。超过 24 小时程序会自己判定上一轮修好了并删除它。手动删 = 重置计数。

**Q8：PE 里没网能用吗？**
不能。诊断和修复都要联网。

**Q9：能在正常 Windows 里跑吗？**
能启动、能诊断，但注册表修复必须在 PE 里做。正常系统下目标注册表被占用，会提示「挂载注册表失败：客户端没有所需的特权」——这是正常现象，不是 bug。

**Q10：有 32 位版吗？**
**v1.2 暂时只有 64 位。** 深度修复依赖的智能体本身就是 64 位程序，32 位 PE 跑不起来。32 位版会作为单独的版本另外发布。

### v1.1 —— 长期记忆与多阶段自适应风险熔断版

> 从「一次性修复工具」进化为带记忆的自适应修复系统。所有新增依赖均来自 Go 标准库，编译体积基本不变（amd64 4.93 MB），依然零第三方依赖。

#### 🆕 新增：硬盘黑匣子长期记忆

- 每轮修复落地后，在目标盘写入 `X:\Windows\pe_fix_memory.json`，格式严格规范为一行 JSON：
  `{"last_repair_time":"YYYY-MM-DD HH:MM:SS","diagnose_count":X,"last_action":"REG|a;REG|b"}`
- **原子化写入**：先写 `.tmp` 再改名，杜绝断电/崩溃产生半截文件
- **多机隔离**：记录随目标硬盘走，不污染 PE 自身，也不影响其他机器
- **向前兼容**：兼容 UTF-8 BOM（记事本编辑过也不会被误判为损坏）；未知字段自动忽略
- **动作去重**：按分号逐条精确比对（修复了子串误判会把 `REG|iaStor` 误当已存在的隐患）

#### 🆕 新增：多阶段自适应风险熔断

- **24 小时主动防御**：启动时用时间差判定，超过 24 小时视为上轮已修复成功 → 自动销毁记忆、回归纯净初诊
- **3 次连续失败本地硬熔断**：24 小时内 `diagnose_count >= 3` → 本地直接拦截，完全不向大模型发起网络请求（帮你省 Token），主界面显示血红色高危安全提示，并锁定「开始诊断」按钮
- **时钟错乱保守处理**：主板电池失效导致时间跳到未来时，按「未过期」处理（保守熔断，绝不放行）

#### 🆕 新增：非对称事务前置回滚

- 启动阶段自动解析历史失败工单，提取 `REG|服务名`
- 抢在 AI 重新号脉前，自动 `reg load` 挂载目标 SYSTEM → 路径改写 → `reg import` → `reg unload`，把上次改错的启动键值复原
- ⚠️ **关键实现细节**：备份 `.reg` 里的路径是 `HKLM\SYSTEM\...`（在线路径），直接双击导入只会改到 PE 自身的注册表。本版本通过「挂载点路径改写（SYSTEM → SysTemp）」实现真正的离线回滚；改写不成功则中止回滚，绝不静默写错注册表
- **非阻塞设计**：回滚结果并入主界面提示文字，不用模态弹窗阻塞启动流程

#### 🆕 新增：内存级负向强约束提示词

- 绝不改写静态 `config.json`，而是在运行内存中动态判定历史失败工单
- 在 `systemPrompt` 末尾追加「历史重症监护记录」，强制 AI 全量封印失败路径、推翻旧假设、更换思维维度
- 历史工单含 `%`、引号、反斜杠等特殊字符也不会破坏提示词

#### 🆕 新增：四层安全白名单（防御 AI 给出错误指令）

| 防线 | 作用 | 拦截示例 |
|------|------|---------|
| 指令格式校验 | `REG\|服务名`（最多 2 段）/ `FILE\|文件名\|相对路径`（必须 3 段） | `REG\|a\|b` |
| **服务名白名单** | 仅允许字母、数字、`_`、`.`、`-` | `REG\|svc&calc`（命令注入） |
| **文件名白名单** | 禁止 `\ / : * ? " < > \|` | `FILE\|a/b.sys\|drivers` |
| **路径穿越防御** | 目标必须锁定在 `X:\Windows\` 内 | `FILE\|x\|..\..\..\Users` |

> 解析层 + 执行层双重校验，即使绕过第一层也会在创建目录/写文件前被拦下。

#### 🔧 修复：32 位版在 64 位 Windows 上完全不可用（严重）

- **现象**：386 版启动后主窗口不出现，只弹「未识别到系统盘」
- **根因**：WOW64 文件系统重定向 —— 32 位进程访问 `C:\Windows\System32` 会被透明映射到 `C:\Windows\SysWOW64`，而 `SysWOW64\config\SYSTEM` 根本不存在
- **危害**：① 找不到系统盘导致所有修复功能失效；② 即使找到，修复 System32 下的文件会写错到 SysWOW64
- **修复**：启动时调用 `Wow64DisableWow64FsRedirection()` 关闭重定向

#### 🔧 修复：AI 返回 JSON 含 Windows 路径导致解析失败

- **现象**：弹窗「解析 AI 药方失败: invalid character 'D' in string escape code」
- **根因**：AI 返回 `"SYSTEM32\DRIVERS"`，其中 `\D` 不是合法 JSON 转义
- **修复**：解析前自动修复非法转义（幂等，`\n`、`\uXXXX` 等合法转义不受影响）

#### 🔧 修复：输入框提示文字点击后不消失

- **根因**：原用 `SetWindowText` 写成真实文本；标准 Edit 控件不支持 `EM_SETCUEBANNER` 水印
- **修复**：改为「获得焦点清空 / 失焦且为空时恢复」，并同步修正读取逻辑

#### 🔧 修复：AI 收到空文本导致误报「没有输入任何内容」

- **修复**：改为先读取用户输入、再插入状态消息；文本长度改用 `GetWindowTextLengthW`；清洗逻辑补上未闭合标记过滤

#### 🔧 修复：注册表备份失败仍继续修改（安全隐患）

- 备份 `.reg` 写入失败时立即中止修改，绝不出现「改坏了却没有备份依据」

#### ✨ 增强

- **备份失败原因中文化**：自动识别 `Access is denied`（权限不足）、`write protected`（磁盘只读）、`I/O error`/`CRC`（疑似坏道）等 9 类
- **全链路超时控制**：所有注册表命令 5 秒超时、云端下载前 DNS 预检（1 秒）、HTTP 10 秒
- **消除数据竞争**：`globalAIResult` 改用 `atomic.Pointer`
- **代码质量**：全项目 `gofmt` 规范化、`go vet` 零告警

#### 📋 已知限制

- 恰好 24 小时的历史记录：因进程启动耗时，实际会被判定为「略超 24h」→ 回归初诊（阈值语义为 `>24h` 才过期）
- CRITICAL 等级由「强制熔断」调整为「人工确认后可执行」
