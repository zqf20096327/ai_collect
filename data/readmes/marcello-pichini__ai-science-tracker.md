# AI Science Tracker

Scientific discoveries and artificial intelligence models.

An English-language catalog of scientific results enabled by AI since 2020, with original sources, dates, evidence caveats and editorial relevance scores. A separate model catalog uses Epoch AI data and connects model families to discoveries by name. A family match does not establish which model version was used.

## Run locally

```sh
python3 -m http.server 8800 --bind 127.0.0.1
```

Open http://127.0.0.1:8800. The pages fetch JSON, so opening HTML through `file://` will not work.

## Languages

English at the site root is the canonical edition. Italian, German, French and Spanish are pre-generated under `/it/`, `/de/`, `/fr/` and `/es/` by `python3 scripts/generate_share.py` (or `python3 scripts/i18n_site.py` alone). A first visit to the English home page, or to another editorial page at the site root, redirects to the matching edition. The browser language list is checked first. A timezone hint is used only when that list names neither English nor a supported language. Share pages and organization profiles stay in English. A manual choice is stored in `localStorage` (`ast-lang`), never in a cookie, and is never overwritten by detection. An automatic redirect is not stored. Search-engine crawlers are not redirected. The header language control is a compact menu (a globe and the current code) and keeps the current page, query and fragment. On narrow screens the section menu collapses behind a button so the wordmark stays on one row.

Interface and editorial copy live in `i18n/messages/<lang>.json`. English is the key. Strings may contain `{n}` for numbers and `⟦…⟧` for text that sits inside a link or other inline element; `⟦*⟧` marks a discovery title that must stay unchanged. `python3 scripts/i18n_site.py --check` fails when a locale is missing a key. Optional discovery summaries, keyed by entry id, live in `i18n/discoveries/<lang>.json` and fall back to English. To add a language, copy `i18n/messages/en.json` and `i18n/discoveries/it.json`, translate them, and add the code to `LOCALES` in `scripts/i18n_site.py`.

GitHub Pages cannot read a visitor’s country. If Cloudflare proxies the domain, a Worker could read `CF-IPCountry`, but country is not language (Switzerland is the obvious case), so the site does not depend on it.

## Structure

- `index.html`: discoveries, search, filters and charts.
- `models.html`: model releases and discovery links by family.
- `profile.html`: lab and model-family profiles (`?org=NAME`, `?family=ID`) with timeline, discoveries and releases.
- `methodology.html`: selection, verification and scoring criteria.
- `security.html`: separate AI-discovered vulnerability tracker; sources and remediation context in `data/vulnerabilities.json` (`docs/vulnerability-schema.md`). These cases are not included in the scientific-discovery count.
- `styles.css`: the single shared stylesheet, including the print version; fonts are hosted locally under `assets/fonts/`. Design rules: `docs/DESIGN.md`.
- `share/`, `profiles/`, `og/`, `sitemap.xml`, `robots.txt`, `llms.txt`: generated by `scripts/generate_share.py` (see below).
- `data/discoveries.json`: curated records, documented in `docs/discovery-schema.md`.
- `data/archived-discoveries.json`: excluded historical records, with preserved share pages; omitted from active counts, profiles, feeds, CSV exports and API.
- `data/models.json`: generated model data; do not edit manually.
- `scripts/generate_models.py`: Epoch AI import and family linking.

Discovery IDs are stable identifiers: some retain historical Italian slugs so existing links continue to work. New links use `#discovery=ID`; legacy `#scoperta=ID` links remain supported. Model family links use `models.html#fam-ID`.

## Update the data

Add or correct discoveries in `data/discoveries.json`, preserving existing IDs, source links, documented date bases and evidence limitations. Verification means the source was checked; it does not mean the findings were independently replicated. After any title, technology or membership change, rerun `python3 scripts/generate_models.py` before `python3 scripts/generate_share.py` so family links and downstream outputs remain consistent. The tests check link completeness without requiring the raw Epoch CSV.

Download the Epoch AI notable models CSV to `work/epoch/notable_ai_models.csv`, then run:

```sh
python3 scripts/generate_models.py
python3 -m unittest discover -s tests
```

The CSV and research working files are excluded from Git. The generated source metadata includes the SHA-256 fingerprint of the input CSV; it does not establish a download date. Shared `styles.css` and `catalog-ui.js` asset URLs include the first 12 characters of each asset’s SHA-256 hash; update the corresponding root-page references when changing either asset; generated pages inherit the stylesheet hash. The design tests enforce matching versions, preventing cached JavaScript from breaking newly deployed pages. The pages let browsers cache the JSON files (GitHub Pages sends `max-age=600`), so a data update can take up to 10 minutes to show for a returning reader. Review generated family links before publishing; they are based on names, not independent attribution.

A GitHub Actions workflow (`.github/workflows/check.yml`, read-only permissions) runs the tests on every push and pull request, then reruns `python3 scripts/generate_share.py` and fails if `share/`, `profiles/`, `sitemap.xml` or `robots.txt` differ from what is committed. After changing data or the generator, rerun the generator and commit its output.

## Sharing, filters and printing

- Filters are kept in the query string: `index.html?q=&field=&org=&year=&family=&min=&sort=`. The "Copy filter link" button copies the current view; "Download selection" saves the listed entries as JSON or CSV, and each entry has "Copy link" and "Copy reference" buttons.
- "Copy link" on a discovery copies `share/ID.html`, a generated full, self-canonical static discovery page with Open Graph tags and a 1200x630 card (`og/ID.png`); its full text is readable without JavaScript, with a link back to `index.html#discovery=ID`.
- After changing discoveries or the design, run `python3 scripts/generate_share.py` (changed cards are detected using `og/card-hashes.json`; add `--force` to redraw every card. It needs Google Chrome, or set `CHROME=/path/to/chrome`) and commit the generated files.
- Printing or "Save as PDF" from `index.html` produces a light, control-free list with full summaries and source URLs.

## Source context, trends and contributions

Entry details distinguish source checking from independent scientific confirmation and expose the three editorial subscores without hover. The annual chart switches between catalog-entry counts and mean editorial relevance; source composition and addition dates describe the collection, not worldwide scientific activity or review freshness.

Methodology includes live annual tables for evidence-annotation coverage and primary source composition. Missing annotations do not mean missing scientific evidence. Counts describe catalog entries, which can bundle or overlap results; the 20–100 relevance scale is a coarse editorial aid with thirteen possible values, not a cross-field quality ranking. Timeline and model charts support keyboard selection and announce the selected record; dense date groups can be opened through an entry chooser.

Corrections and missing-result suggestions open public GitHub issue forms. They require GitHub sign-in, original sources and editorial review. The forms become available when `.github/ISSUE_TEMPLATE/` is published to the default branch. They never change the catalog automatically. See [CONTRIBUTING.md](CONTRIBUTING.md) for how to suggest, correct or review entries, and [Discussions](https://github.com/marcello-pichini/ai-science-tracker/discussions) for ideas.

The shared UI helper is `assets/catalog-ui.js`. The test command also exercises its metric, disclosure and correction-link behavior using Node.js (no package installation needed).

## Use it from an AI assistant

**MCP server (any MCP client, no install, no token):** `https://mcp.aisciencetracker.org/mcp` (Streamable HTTP, read-only). Tools: `search_discoveries`, `get_discovery`, `list_fields`, `search_vulnerabilities`, `get_vulnerability`. Listed in the official [MCP Registry](https://registry.modelcontextprotocol.io/) as `io.github.marcello-pichini/ai-science-tracker` and on [Glama](https://glama.ai/mcp/connectors/io.github.marcello-pichini/ai-science-tracker); Server Card at `https://mcp.aisciencetracker.org/mcp/server-card`. Source and search rules: [`mcp/`](mcp/README.md).

```sh
claude mcp add --transport http ai-science-tracker https://mcp.aisciencetracker.org/mcp
codex mcp add ai-science-tracker --url https://mcp.aisciencetracker.org/mcp
gemini extensions install https://github.com/marcello-pichini/ai-science-tracker
```

In Claude, add it from the [Connectors Directory](https://claude.ai/directory/connectors/ai-science-tracker); in ChatGPT or other clients, add it as a custom connector with the same URL.

The repository ships a skill that answers "what's new in AI science?" from the catalog instead of a general web search. It is fast and cheap in tokens: the catalog data is about 5.9 MB, but the skill filters it locally and returns a typical answer of 1-12 KB (roughly 300-3,000 tokens), so research that would need many searches and page reads becomes one short call.

- **Claude Code:** `/plugin marketplace add marcello-pichini/ai-science-tracker`, then `/plugin install ai-science-tracker@ai-science-tracker`. A second plugin, `ai-vulnerability-tracker`, covers only AI-attributed vulnerabilities (`plugins/ai-vulnerability-tracker/`).
- **Other agents that read `SKILL.md` skills (for example Codex):** copy `plugins/ai-science-tracker/skills/ai-science-tracker/` into the agent's skills folder. It needs Python 3 and no packages.
- **ChatGPT, Gemini and other assistants without skills:** point them at https://aisciencetracker.org/llms.txt, the Atom feed `feed.xml` or the JSON API under `api/v1/`.

## Dataset and API

The catalog is open data. Downloads: `data/discoveries.json`, `data/discoveries.csv`, `data/vulnerabilities.json`, `data/vulnerabilities.csv`, `data/models.json`. JSON Schemas are in `schema/`. A read-only static API lives under `api/v1/` (`index.json` plus one file per record), described for tools and agents by an OpenAPI 3.1 file at `api/v1/openapi.json`. CSV files and `api/` are generated by `python3 scripts/generate_share.py`; never edit them by hand. See the [Dataset and API page](https://aisciencetracker.org/dataset.html) and the [changelog](CHANGELOG.md).

The [catalog coverage comparison](https://aisciencetracker.org/profiles/catalog-evidence.html) provides reproducible year/field composition tables and `data/catalog-summary.csv`. [Static security case pages](https://aisciencetracker.org/profiles/security-index.html) preserve source-attributed AI involvement, CVSS/impact evidence and remediation caveats without JavaScript. These cases remain separate from scientific counts. Generation and counting rules: [search discovery](docs/search-discovery.md).
