## 13.5.0

**日程引擎里的十维也删干净了；发言裁决换成那种少而准的加权：点名 / 信息量 / 关系 / 心情 / 时机。**

用户 2026-11-18：「十维还是删除为好，不然后续维护会很麻烦」「开始布置那种少而准的 agent 的判定权重吧，
我感觉心流其实很完美，但是不够完善，把这个添加进去」。

### 一、日程引擎不再有自己的心情

- `schedule_engine` 里的 `MOOD_KEYS / MOOD_BASE / CATEGORY_MOOD` 整组删除，
  换成 `FEEL_KEYS / FEEL_BASE / CATEGORY_FEEL`（七情六欲本身的维度）。
- 日程按小时平滑的那份向量只在**内存里**存在，源头是心流、落点是提示词里的一句话
  （`item["mood"]` 只是个词），不落盘、不再是第二套心情。
- `build_context(..., feel, ...)`、`ctx["feel"]`；`_mood_text` 现在输出
  「喜34 怒34 哀34 惧34 爱34 精力65 饿35」。
- 日程里突发事件的 effects 改成心流键（`energy/fear/joy/anger/...`），
  旧数据里的十个中文键由部署脚本一次性迁移。

### 二、少而准式发言裁决（接进心流）

- 新增 `REPLY_WEIGHT_DEFAULTS`：`addressed 0.55 / concrete 0.18 / relation 0.15 /
  feel 0.15 / timing 0.20`，每项特征取 -1..1，加权后 0.5 = 不偏不倚。
  - **addressed**：点名 / @ / 接着她的话说 → +1；明确在对别人说 → -0.4。
  - **concrete**：有数字、链接、提问、说得够长 → 越高；「坏了」「确实」这种 → 0。
  - **relation**：相恋 1.0、熟识 0.6、普通 0.25、抵触 -0.4、仇恨 -0.6、陌生人 0。
  - **feel**：她此刻的七情六欲——喜/爱高就更想说，怒/累/低落高就不想理。
  - **timing**：90 秒内刚说过话 -0.8，4 分钟内 -0.3，群里正吵再 -0.3，冷场 +0.2。
- 最终分 = `(1 - rule_blend) × 模型五维分 + rule_blend × 规则分`（默认 0.55），
  再和阈值比；日志会打一行：`⚖️ 裁决 模型0.62 规则0.41（点名+0.0 具体+0.5 关系+0.0 心情-0.2 时机-0.8）→ 混合0.50 / 阈值0.62`。
- 两个新配置：`hf_reply_weights`（JSON，覆盖任意一项权重）、`hf_rule_blend`（0~1）。

测试：1040 通过。新增 `tests/test_reply_weights.py`（6 条：点名/陌生人聊技术/恋人心情好/生气累了/信息量/边界）。

**十维心情整个删掉，情绪全权交给七情六欲——每一句话都会动她，而且按关系放大。**

用户 2026-11-18：「有七情六欲还要十维干什么？本来七情六欲就是十维的高阶版本，你还留着十维，
我说怎么情况不对，原来最大的篓子在这里」，并要求「每一句话、每一次聊天都影响她的七情六欲」，
「关系越亲近/越对立，情绪变化越大；越接近陌生人，变化越小」。

### 一、十维彻底删除

- 删掉 `HumanState.mood / mood_ts / save_mood / nudge / decay_mood / dominant_mood / mood_score /
  mood_text / observe`、`MOOD_BASE`、`MOOD_KEYS` 引用，以及 `snapshot` 里的
  `mood / dominant / mood_score`。
- 所有原来往十维写的地方（日程活动、日程事件、生理期、天气、被他哄、被晾着、被打扰、股票盈亏、
  就医失败、旅行被拒）现在一律写七情六欲（`heartflow.bump`）。
- 原来读十维的地方（语气 `tone_text`、私聊概率、回复意愿、主动消息类型、`/心情` 命令、
  提示词两处、心流判定的心情字段）全部改成读七情六欲。
- 这里曾经有个致命 bug：`prompt_text` 里写的是 `getattr(self, "feelings")`，而心流挂在**插件**上，
  HumanState 上永远是 None——提示词里那句「心情」从来都是十维，七情六欲根本没进过她的话。

### 二、每一句话都算

- 拆掉 13.0.0 的「一条只推一个方向 + 900~1800 秒冷却 + 每天 14 点额度」：
  额度早上被群聊花光后，一整天怎么聊都不动，看起来就是「情绪死了」。

  群里别人之间的闲聊只算 0.03 的气氛，不是不说话就不算。

### 三、情绪随关系变

- `RELATION_FEEL_WEIGHT`：相恋/仇恨 1.8、抵触 1.5、熟识 0.9、普通 0.5、没画像的陌生人 0.3。
- 同一句骂人的话，恋人说出来能把愤怒推 3.6 分，陌生人只推 1.0 分。

测试：1033 通过。新增 `tests/test_feel_single_source.py`（十维必须消失 / 每句都动 / 关系权重）。

## 13.3.0

**「七情六欲坏了」和「我早上说过醒了，中午还问我醒了没」——一个是群聊在喂她的心情，一个是判定只认私聊。**

用户 2026-11-18：「七情六欲坏了……我早上已经跟他说我醒了，他下午还是会问我醒没，关键是上一秒我还在群里说话」。

### 一、心情被群聊噪声顶死

- 线上实测：`平静 99.5 / 郁闷 98.9 / 生气 96.8 / 疲惫 99.1`（基线 60/18/8/28）。
- 根因：`_learn()` 对**每一条群消息**都调 `state.observe()`，不管是谁说的。群里一小时
  100~230 条，光「平静 +1」就够顶满；群友骂人又给她 +9 生气、+5 委屈。
- 后果：`tone_text()` 命中「生气≥62」，往提示词里写「你现在很烦躁，说话冲、短、带刺」，
  她一整天都是同一种臭脸口气。
- 修法：`observe(text, weight, ambient)` 分档——群友之间的闲聊只算「气氛」
  （8 分钟最多一次，只落在平静/兴奋/疲惫上）；跟她说话才按原强度加减，群里说的算六成。
- 心流同理：`_chat_feel` 只被私聊和被点名的话推动，群里闲聊不再消耗当天的 14 点额度——
  以前早上一小时就把额度花光，剩下一天怎么聊都不动，看起来才是「七情六欲死了」。

### 二、他已经醒了，还在问「醒了没」

- 判定链：`_ritual_should_send_async` 拿到的行被 `_private_rows` 全过滤（群聊不算他在场），
  午饭那档又只认「午饭/吃啥/吃饭」，不认「我醒了」；兜底句还是「早上好呀，还没起来吗？」。
- 修法：
  - 新增 `_ritual_he_is_around()`：他今天在任何会话说过「早/早安/我醒了/起床了」，
    或者 45 分钟内还在群里说过话 → 这个时段的问候直接不发；
  - 新增 `_his_presence_line()`：他已经醒着时，把「他 07:35 刚说过话」当硬事实写进主动消息的
    系统提示，并明写不许问「醒了没/起来没/在吗」；
  - 生成完再过一道 `WAKE_ASK_RE`：还问「醒没」的这条直接丢弃，下一轮重写。

### 三、群聊少而准（学它的少而准，不动主体结构）

- 判定给 `reply_style=none` 时**真的不开口**了（以前被改回 comment，等于每条都硬回一句）；
- 判定规则新增「空话也算不自然」：只能说「赶紧修/别乱花钱/多喝热水」这种放哪儿都成立的话，
  就给 `none`；
- 插话提示词要求「必须接住一个具体的东西（谁、哪件事、哪个数字、哪句原话）」。

测试：1025 通过（新增 `test_mood_ambient.py` 5 条、群聊在场判定 5 条）。

## 13.2.1

**她「黑白不分」和「好像不懂股票」——两个都是上下文缺字段。**

用户 2026-11-17：「他好像黑白不分，拍的是黑丝，但是非说是白丝……是她梭哈苹果，他说我梭哈，
他好像并不知道股票？怎么回事」。

### 一、袜子颜色说错（不是生图的问题）

- 事实核查：衣柜 `JK·藏青` 这套配的是 **及膝黑袜**，生图提示词也是黑袜，照片确实是黑的；
  她嘴上说成「白丝」。
- 根因是**她说话时没有「我此刻穿的是什么颜色」这个事实**：
  1. 衣柜件名「及膝黑袜」的颜色没有被单独提出来当事；
  2. 记忆里有两条 `他喜欢JK制服和白丝`，进上下文时被加上「他：」前缀，
     读起来像她自己的现状——一提到丝袜就被他的偏好带跑。
- 修法：
  - 上下文新增 **【穿戴事实】**：列出身下这套每件的颜色（`黑（及膝黑袜）、白（长袖白衬衫）…`），
    并明写「黑的不能说成白的」「他喜欢什么颜色是他的事，不等于你此刻穿的」。
  - 新增 `_outfit_colors()`：**按件**判色（白衬衫和白袜都算白，不会被一个「白」吃掉）。
  - 记忆注入补一句定性：「记忆里『他喜欢…』说的是他的口味，不是你现在穿的东西；
    你现在穿什么颜色，只看【穿戴事实】那一条。」

### 二、她「不知道自己在炒股」

- 根因：`_sync_finance()` 只给 `state.invest` 同步了 13 个字段，
  而 `_invest_line()` 要读的 **`leverage` / `savings` / `buying_power` / `margin_debt` / `futures`
  一个都没给** → 她看到的杠杆永远是 1 倍，储蓄、保证金、期货全是 0，拿着残缺账本聊股票。
- 修法：补齐这 5 个字段 + `equity`；持仓明细补上 `symbol/last/market_value/pnl`；
  `_invest_line` 报持仓时带上**现价和浮盈金额**，不再只说「股数+百分比」。
- 附带澄清：「梭哈苹果」那句是**他**说的（`14862 | user | 小股神梭哈买苹果…`），
  她只是接话（`14869 | bot | 你还真梭哈了？`），这件事她没记错。

- 测试：终端 **1019 绿**（新增 8 条：穿戴颜色 4 条 + 股票字段同步 4 条）。

**四个线上病象一次修完：群聊爆代码、承诺记反方向、重复「收尾就发你」、拍照衣服前后不一。**

- **拍照衣服前后不一**（14:01 交领 → 抹胸）：两个原因。① 提示词里有两处衣服描述——

## 13.0.0

**七情六欲重做成「人该有的起落」：不再几句话就开心上天、怂恿两句贪欲拉满。**

线上实测抓到的问题：喜 98.5、爱 97.9、耳 98.5、眼/身 96.9、意 88.9，
七天里一直顶在天花板；而衰减只有「每小时往 30 拉 8%」，15 小时才能落回常态，
中间聊天每隔两分钟又加回去。增益也太大（被夸 +10 喜、聊吃的 +12 舌、撩一下 +11 身）。

现在改成：

- **单次有量**：一次事件最多推动 `MAX_GAIN=10`，表里单条都在 2–6 之间。
- **向上饱和**：越过「常态 + 18」之后，同样的刺激逐级打折，贴着 100 只剩三成。
  连夸十几次到 75–83 就上不去了——想更高得靠真的事（礼物、旅行、被哄很久）。
- **分档回落**：离常态越远落得越快（40 以上每小时落 45%）。100 分的开心
  一小时落到 74、三小时到 57，不再整天挂在天花板上。
- **基线会走**：`drift_baseline()` 按钟点给「此刻正常水平」（凌晨 26 → 下午 45 → 深夜 27），
  再叠当天固定的 ±4 心情波动。她不是恒定 30 的机器，每天自己的心情也不一样。
- **六欲比情绪散得快**：单独的回落速度（1.7 小时掉一半）+ 硬顶 92；
  被撩起来的馋劲和想被抱会自己下去，不会整天挂着。
- **睡一觉能缓，但不会换脑子**：睡眠按小时累计回落，睡 8 小时落掉七成左右，
  醒来还带着昨天的余味（起床气 / 余欢）。
- **聊天侧三条闸**：一条消息只推**一个**方向（取最先命中的那类）；每类独立冷却
  （夸 15 分钟、撩/吃 30 分钟、普通聊天 20 分钟）；**每天聊天带来的总涨幅上限 14 分**。
  光靠嘴说，一天也推不到天上。
- 提示词里补「此刻心里的常态大约 N 分」+「情绪会慢慢散掉，不用一直挂在刚才那件事上」，

## 8.8.0（日程里不再有他 + 他的今天进记忆 + 生图留痕）

## 8.7.4（幂等号对不上金额就报冲突）

- `charge()` 的幂等缓存把金额一起存：同一个 `request_id` 换了金额，返回 `idempotency_conflict`，不再把旧流水当这笔的结果（内存和落库两条路都校验）。
- 老流水没有金额可比时照旧按「重复」返回，不误报。

## 8.7.3（说的地点和画的地点必须是同一处）

- 新增「每轮活动快照」：`_dynamic_context` 注入给模型的那份「她在哪/在干嘛」，出图时原样复用（`_activity_snapshot(umo)`，3 分钟有效）。日程刚好在聊天和出图之间翻页，也不会出现「她说酒店、照片在景区」。
- 出图调用带齐 `place / activity / zone`：地点不再由生图插件自己再读一遍状态。
- 主动分享同样用这份快照（概率判定、提示词、出图三者同一处地点）。

## 8.7.2（不再往群里爆代码 + 出去玩要花钱）

- 幂等号同时交给金融（`request_id`），账本自己也认这笔扣过没有；
- 命中重复时不再重复写记忆（同一笔只记一次支出）；
- **身体状态以医疗插件为准**：以前治好就写「健康」，把医疗的「恢复中」覆盖掉；
  现在终端只同步 `medical.status()`，不再自己掷骰子也不会前后矛盾；
- 新增 6 条用例（失败可重试、并发短挡、重启不重扣、重复不写记忆、状态同步）。

## 7.6.4（心流判定：上游 503 不再刷屏，叫她还是应）

- 判定模型的上游在整片 503（`API node is temporarily unavailable`），旧实现每条消息
  都打一条 `ERROR` 然后一律不回复——日志全是噪音，她还会在这段时间里变成哑巴；
- 失败日志改成「60 秒最多一条 + 连续 N 次」，`ERROR` 降为 `WARNING`；
- 连败 3 次熔断 60 秒：期间不再打上游，直接走兜底判断；
- 兜底不是一律沉默：**名字/别名被叫到、或连续被打扰**，照样回复；
- 5xx/429/超时这类瞬时错误重试一次（间隔 0.4s），解析错不重试；
- 新增 `tests/test_heartflow_resilience.py` 7 条用例：限频、熔断、熔断过期、

## 它是怎么工作的

群聊：

```
用户消息
  → 心流引擎（五维评分 + 动态阈值 + 沉浸模式 + 防抖 + 群聊独立配置）
  → 达到条件时设置 event.is_at_or_wake_command = True
  → AstrBot 原生 LLM 生成回复（人格、上下文都走 AstrBot）
  → on_decorating_result 交给守护（Astrbot_Amo_Guard）
  → 守护排版分条，逐条发送、打字延迟、群聊按概率引用
```

私聊：

```
健康 / 生理期 / 日程门控
  → 通过则走 AstrBot 原生回复
  → 交给守护排版分条后逐条发送（私聊不引用）
```

没有修改 AstrBot 核心代码，也没有替换它的回复链路；终端只决定“说什么”，守护只负责“怎么发出去”。

## 功能

- **完整心流（内置）**：五维评分、动态阈值、沉浸模式、判断暂停、防抖、群聊独立阈值、白名单、自定义评分规则、详细日志、心流命令。
- **生理期**：28 天周期可配置，月经期、卵泡期、排卵期、黄体期；影响心情、体力、疼痛、回复概率与主动求安慰。
- **九维心情**：开心、平静、郁闷、生气、委屈、疲惫、焦虑、兴奋、依恋；直接影响语气。
- **世界观与日程**：基于 AstrBot 人格生成世界观，再由世界观生成每日日程；天气、健康、生理期共同参与。
- **天气**：和风天气；未配置 Key 时本地模拟。
- **长期记忆**：本插件不再自带记忆库，只读写外挂记忆插件（天使之魂 / 我会牢牢记住你 / livingmemory）；记忆会注入回复与主动消息。
- **用户档案**：自动建立，记录名字、称呼、生日、关系、好感；相恋仅管理员可设。
- **用户画像界面**：状态 / 用户画像 / 设置三个页签；可搜索、编辑画像、查看记忆、同步陪伴插件档案，直接调整关系（仇恨/抵触/普通/熟识/相恋）。
- **全部开关进 WebUI**：设置页加载完整 `_conf_schema.json`，布尔开关、数字、文本、列表/模板列表都可直接改，保存后写入插件配置并重建心流引擎。
- **主动私聊**：概率、频率、每日上限；难受时找相恋的人撒娇，遇到有趣的事分享。
- **九维面板**：查看心情雷达、生理期、健康、天气、日程、阈值。

## 挂载记忆插件

本插件不带记忆库，记忆来自你装的其他插件。市面上记忆类插件很多，**面板会直接列出你已安装的所有插件**，
选哪个就用哪个的记忆和画像，不用改代码：

| 配置 | 说明 |
|---|---|
| `companion_memory_plugin_name` | 挂载的记忆插件；留 `auto` 自动检测，面板下拉列出已安装插件 |
| `companion_memory_include_profile` | 读取挂载插件的画像（强记忆、边界、表达习惯、偏好、兴趣） |
| `companion_memory_include_important` | 读取挂载插件的长期记忆（不限条数） |
| `companion_profile_sync` | 从挂载插件自动补全用户画像（只补名字/生日/关系） |

**检索是按 `uid` 查的**（QQ 号 / 平台用户 ID）：召回时带着当前说话人的 uid 去插件里查，
查不到再按名字/称呼兜底；画像也以 uid 为主键（同名不同号不会串）。

能自动读取的结构（有哪个读哪个，都不限制条数）：

- `users[uid]["companion_memory"]["items"]` 的 `text` / `weight`；
- `companion_memory["profile"]` 里的 `strong_memories`、`boundaries`、`speaking_style`、`weak_preferences`、`interests`；
- `users[uid]["important_memories"]`；
- `worldbook_member_profiles[uid]["important_memories"]`；
- 实现了 `search_for_event` / `recall_for_event` / `search_memory` 等检索接口的插件（直接调用它的检索）。

只读，不修改挂载插件的数据；没有可用的记忆插件时就不注入记忆（本插件不再自带记忆库）。

> 注意：陪伴插件本身也会回复消息。如果两个插件同时接管聊天，可能出现双回复；建议只保留一个负责回复，另一个作为记忆源。

## 用户画像与设置

- “用户画像”页：列出所有档案，支持搜索、编辑名字/称呼/生日/关系/好感/备注、查看记忆；
- “同步陪伴档案”会从 `astrbot_plugin_private_companion` 的 `users` 读取名字、生日、关系分数，补全本插件画像；

> 不再内置默认管理员。请在 `admin_uids` 填自己的 QQ，或使用 AstrBot 全局 `admins_id`；留空则聊天指令没有管理员。

## 版本号规则

- 三段：`x.y.z`，**第二位和第三位只能是 0-9，逢十进一**：3.8.9 → 3.9.0，3.9.9 → 4.0.0；
- **首位不做限制**，可以是多位数：9.9.9 再进一位是 10.0.0（不是 1.0.0.0）；
- **测试版**：动第三位（7.4.0 → 7.4.1）；
- **发布版**：动第二位、第三位归零（7.4.1 → 7.5.0）；
- **大版本**：首位 +1（7.5.0 → 8.0.0）；
- `python3 tools/check_version.py` 校验四处一致与规则，
  `python3 tools/check_version.py --next test|release|major` 直接算下一个号。
