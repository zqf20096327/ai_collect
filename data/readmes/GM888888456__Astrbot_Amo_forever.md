## 9.3.1（JK 固定搭配写死）

- 衣柜新增 `SLOT_EXCLUSIVE` / `pair_ok()`：JK 衬衣只配 JK 格裙、格裙只配 JK 衬衣、连衣裙独占；袜子/鞋/配饰不算冲突。

## 9.3.0（每天 23:55 收尾：总结 + 备份）

- 新增 `_maybe_night_close()`：23:55 把当天「记录」里买/没买/拍照/股票整理成一条 `daily_digest` 记忆（幂等 `night_close:<日期>`），随后调用记忆插件 `backup_now(7)` 做整库备份（含日程与世界观缓存）。

## 9.2.1（买东西真的扣钱：amo_buy）

- 新增 `amo_buy(item, kind)`：从市场查价 → `charge()` 扣钱 → 衣服/首饰直接进衣柜（带槽位），并写 `buy` 记录。
- 之前市场只有目录、没有购买流程，所以「买了没扣钱」；现在买任何东西都走同一个账本入口。

## 9.2.0（记录接线：买 / 拍 / 没买）

- 新增 `_record()`：直接写记忆插件的 `records` 表（只增不改）。
- `charge()` 成功 → `buy`（金额、收款方、来源）；发照片 → `photo`；衣柜没有 → `skip`（想穿什么、为什么没买）。

## 9.1.5（照片记录不再静默失败）

- 线上核对：`memories` 里 `photo_record` 一条都没有，说明 `_remember_photo` 一直被拦、只打了 debug。现在写不进去会 **降级成 `event`（前缀【照片】）**，并打 info；两边都失败才 warning。

## 9.1.4（日程读写统一清洗「他」）

- `_strip_his_presence` 之前只在部分生成路径调用，状态同步/面板写库会绕过它，所以日程里还能看到「他」。现在所有 `kv_set("schedule")` 与启动加载都过 `_sanitize_schedule`。

## 9.1.3（发出去的每张图都记账）

- 照片记忆以前靠调用方自觉，私聊自拍/表情图/面板之外发的图会漏记。现在 `_send_image_to_umo()` 成功发图后统一写一条 `photo_record`（带标签，7 天降权 / 14 天删除）。
- 失败只打 debug，不影响发图。

## 9.1.2（换装先查衣柜）

- 用户喊「穿 XX」时先看衣柜里有没有：有就走原来的换装；没有就回一句「等我哪天去市场买」，并记进 `outfit_wish`（最多留 50 条）。

## 9.0.9（雷达切换 + 吃饭补扣 + 换设备欲望）

- **面板雷达**：七情七轴雷达图；双击（或手机上连点两次）切到六欲，再双击切回；只读。
- **吃饭补扣**：日程里正在吃饭/点外卖/做饭的那一格，按地点自动扣一次（做饭 ¥22 / 外卖 ¥36 / 下馆子 ¥58），幂等号 `meal:<日期>:<开始时间>`，同一天同一格只扣一次；之前「显示在吃、金融没扣钱」的洞补上了。
- **换设备欲望**：`devices` 记录手机/电脑型号与开始使用日期；`desire_eye ≥ 70` 且手机用满 240 天（`desire_mind ≥ 75` 且电脑满 400 天）→ 每天最多念一次，写记忆并把「想换什么、多少钱」注入聊天上下文；真买调用新工具 `amo_buy_device(kind=phone|pc)`，走 `charge()` 记账并更新设备。

## 9.0.8（日程分类/区域走枚举归一，容错大小写）

- `amo_enums.coerce()` 增加大小写兼容：`"Sleep"`/`"SCENIC"` 这种历史脏数据也能认出来。
- `HumanState._normalize_items()` 在日程两条出口统一归一 `category`/`zone`：能认的修成枚举值，认不出的原样保留（不静默改写语义）。
- 这样生图场景映射、日程判断不会再因为一个空格或大小写走错分支。

## 9.0.7（聊天里的夸/凶接进心流）

- `_chat_feel()`：私聊/群里夸她（好可爱/辛苦了/抱抱…）→ `CHAT_PRAISE`（喜+10、爱+5、耳+8）；凶她（滚/烦死了/讨厌你…）→ `CHAT_INSULT`（怒+12、哀+6、爱-6）。各 10 分钟最多一次，避免刷分。
- 至此「心流只读 + 事件驱动」闭环：聊天、转账、吃饭、照片、语音、医疗、生理期、旅游、改行程都只发事件。

## 9.0.6（私密照片：害羞→判定→出图，边界写死）

- 新增 `private_shots.py`：只私聊、只主人。第一次要 → **害羞拒绝**并记住；再问 → 按心情判定（心情差直接开怼、不判定；平静/好才答应）；每天默认 2 张上限，失败不占次数。
- 提示词写死边界：成年、单人、不露点、不拍性行为，永远附负面词；衣物/姿势按她说的取（内衣/睡裙/制服/丝袜 + 躺/趴/坐/跪/回头…）。
- 出图走现有链路：终端判定 → 生图插件 `draw_for` → 终端发送；答应/拒绝/开怼都记 `event` 记忆（7/14 天）。
- 新配置：`private_shot_enable`、`private_shot_daily_cap`。

## 9.0.5（模块三：手填配置下线，人格自动提取）

- 配置表删掉 12 个手填键：`schedule_city`（角色城市）、`schedule_home`（住址）、`schedule_workplace`（公司）、`schedule_car`（角色资产）、6 个 `usage_price_*`（单价）以及 `weather_city`/`weather_city_name`。城市/住址/公司/车全部改由人格解析（`schedule_profile`），单价用内置官方价格表。
- 吃饭（`amo_eat`）成功 → `MEAL` 事件：饥饱、舌欲、心情一起变。
- 人格城市也推给金融（`set_persona_city`），房车与房租按人格城市重算。

## 9.0.4（事件总线：挂载只发事件，心流只读数）

- 新增 `emit_event(name, payload)`：挂载插件唯一的入口，只传事件名和 `severity`（0–10），加减全在 `heartflow.py`。
- **生理期改由医疗发事件**：医疗检测到第 1 天时发 `period_start`（带痛经等级），干净后发 `period_end`；终端在医疗连着时不重复发（只留兜底），避免一条事件扣两次。
- **Prompt 带「为什么」**：`heartflow` 记录最近 8 条事件（带中文说明），`get_prompt_summary()` 末尾输出「最近发生：生理期来了，痛经 5 级；他夸我了。情绪就是这么来的」，让模型知道情绪从哪来，而不是只看到数字。
- 严重程度按 0–10 → 0.3–1.5 倍等比放大该次事件的影响。

## 9.0.3（生理期接入心流：医疗面板双击设置）

- `state.set_period_settings(cycle_days, start)`：医疗面板改周期/上次开始，写配置 + kv 并重算。
- `_period_feel_tick()`：生理期第 1 天发 `PERIOD_START`（Energy−20 / Anger+15 / Desire_BODY+20），干净后第 1 天发 `PERIOD_END`；每天各一次，写在 kv `period_feel`。
- 心流数值仍然只由事件驱动，面板不开放改数。

## 9.0.2（面板改动修正：别误删函数）

- 9.0.1 的面板改动里，删除旧雷达图时误删了紧随其后的几个顶层函数（`action` 等）。这次按「函数头到下一个顶层函数」精确切割，并加了三道自检：关键函数清单、`node --check` 语法检查、`moodModal` 必须为 0。
- 结果：七情只读 + 六欲折叠照旧，`listFrom / renderProviderUsage / diaryDayString / action` 全部在位。

## 9.0.1（面板：七情只读 + 六欲折叠）

- 主页「当前心情」改成**七情**（喜/怒/哀/惧/爱/恶/惊）只读条；六欲（眼/耳/鼻/舌/身/意）折在「六欲（点开看，只读）」里；下面一行显示饿/精力。
- **删掉调整心情的弹窗和 `/mood/update` 接口**：数值只能由事件（聊天/转账/医疗/生理期…）驱动，面板改不了。
- 去掉不再使用的雷达图绘制（10 维）与相关样式。

## 9.0.0（心流数值核心：基础生理 + 七情 + 六欲，双核驱动）

- 新建 `heartflow.py`（终端核心，非挂载）：`Physiology`（饿/精力）、`Emotion`（喜/怒/哀/惧/爱/恶/惊）、`Desire`（眼/耳/鼻/舌/身/意）三个枚举 + `HeartflowEvent` 事件枚举，**0–100 边界锁定，只做加减**，业务判断留在调用方。
- **双核驱动**：内驱动 `decay(minutes)` 按时间流逝加饥饿、掉精力，七情六欲按小时 8% 回基线；外驱动 `apply(event)` 只认事件名，加减表是纯数据（`EVENT_DELTAS`）。已接：发照片、收到转账/红包、生理期开始/结束、生病/治好、旅游、改行程、夸/凶/被晾。
- **Prompt**：`get_prompt_summary()` 输出七情数值；某项 >70 或 <10 自动变成第一人称内心戏（例如「我现在火气压不住」「我现在特别想被他抱着」）。
- 存储 `kv heartflow`，重启不丢；`_tick` 里按上次 tick 的间隔衰减，不会重启一次掉一大截。
- 旧十维心情暂留作兼容（面板下一阶段切换），prompt 已改用新数值。

## 8.9.4（用量页：现在峰价/谷价 + 24 小时计价格）

- 用量页新增**计价时段条**：横条从左到右是 00–24 点，橙色=高峰价、青色=空闲价，红线是此刻；右侧胶囊直接写「现在：高峰价 / 空闲价（5 折）」。
- 分段由后端 `usage_clock()` 按 `usage_is_peak()` 实时算（工作日 9–12、14–18 高峰，周末全空闲），改计价规则不用动前端。

## 8.9.3（记忆守门人：去重、时间绝对化、冲突留痕）

- 新增 `memory_guard.py`：所有走 `_write_memory_checked` 的记忆先过一遍——
  - **去重**：同一人 10 分钟内同样的内容只写一条（写成功后才登记，失败重试不会被挡）；
  - **绝对时间**：「今天/昨天/昨天夜里/明天/后天」替换成 `11-12` 这样的日期，放久了也不会串台；
  - **冲突留痕**：同一天出现「酒店」和「景区」这类互相矛盾的地点时打 warning，方便发现她在编，但**不拦截**（拦住会丢真事）。
- 纯本地规则，不额外调用模型、不增加 token。

## 8.9.2（枚举落地第一层：心情 / 日程分类 / 场景区域）

- 新增 `amo_enums.py`：`MoodKey`、`ActivityCategory`、`SceneZone` 三个 `str` 枚举，**值就是原来的字符串**（`MoodKey.ANGRY == "生气"`、`ActivityCategory.SLEEP == "sleep"`），`str()` 也输出中文值，拼提示词/写库不会出现 `MoodKey.ANGRY`。
- `MOOD_KEYS` 改成从 `MoodKey` 派生，顺序不变；老数据库、老配置不需要迁移。
- 新增 `coerce()` / `value_of()`：读历史脏数据时把裸字符串转成枚举，认不出的退回默认值，不抛异常（带空格的能认，大小写不对的退回默认）。
- 目的：把「字段拼错 → 静默走错分支 → 看起来像失忆/幻视」这类问题变成当场报错。日程分类和场景区域的字面量会在后续提交里逐处替换。

## 8.9.1（睡觉这件事有状态机了：枚举化）

- 新增 `sleep_cycle.py`：`SleepPhase`（醒着/睡着/半夜醒）、`SleepAnswer`（答应/太早/不想）、`WakeReason`（口渴/做梦/噩梦/吵醒/起夜/热醒/冻醒/想他/手机亮/睡不着…）全部用 `Enum`，中文说法集中在一张表里。
- **他让她睡**：晚上 23 点后（或凌晨）答应 → 从这一刻起日程变「睡觉」、群里私聊都**不再回消息**，第二天 7 点自动醒；23 点前会说「还早呢」。他说「起床/醒醒/别睡了/我回来了」会把她叫醒，然后正常聊。
- **半夜醒来**：睡着时按概率醒一次，带枚举原因；醒来那一刻的日程写成「半夜醒来：<原因>」，日记同一小时追加一句，记忆写一条 `event`（7 天降权/14 天删除），过一会儿自己睡回去。
- 新配置：`sleep_accept_after`（默认 23）、`sleep_wake_hour`（默认 7）、`sleep_night_wake_chance`（默认 0.25）。

## 8.9.0（他能影响日程了：打赏？不要，按她意愿）

- **他喊她回来 / 去别处**：私聊里说「回来吧 / 快回来 / 别逛了 / 过来 / 去超市」，她自己掂量愿不愿意——心情差（生气+暴躁+郁闷+委屈偏高）直接不去；心情还行就答应。
- **不瞬移**：日程拆成「原来的活动 → 在路上（`move_transition_minutes`，默认 30 分钟）→ 到达」；到达后 `move_hold_hours`（默认 3 小时）内的格子跟着改到目的地，睡觉和吃饭两格不动。
- **她记得**：答应或拒绝都写一条 `event` 记忆（7 天降权 / 14 天删除）。
- 触发词补齐：「回来吧 / 快回来 / 回家吧 / 别逛了 / 回酒店 / 过来 / 来陪我 / 去超市 / 去商场…」；「来接我」不再多插一段路（目的地本来就是路上）。

## 8.8.1（人格里的房车交给金融）

- 新增 `_maybe_push_assets()`：每 10 分钟把 `schedule_profile` 里的房/车（例如「奔驰」）推给金融的 `set_persona_assets()`。人格写了什么车就用什么，不再被随机成比亚迪。

## 8.8.0（日程里不再有他 + 他的今天进记忆 + 生图留痕）

- **日程去「他」**：宅家模板地点改回她自己的家（不再叫「他桌面上」），出行模板去掉「跟他一起出门」「等他忙完」「在他电脑里睡着」；新增 `_strip_his_presence()` 在所有日程出口（生成/已有日程/出行覆盖/出发日/回程）清洗，只有聊天确认他今天在场（`his_present_day`）才允许出现他。他只能出现在聊天里：他说自己在哪、什么时候回来、来找她。
- **他的今天**：每天 `his_digest_hour`（默认 23 点）把他当天说过的话整理成「他去了哪/吃了什么/工作/身体/打算」，写成 `his_day` 事件记忆——7 天降权、14 天删除（数据插件同步登记）。
- **生图留痕**：每发一张图（画图/自拍/主动分享）写一条 `photo_record` 事件记忆（地点+在干嘛+画面摘要），不再「发了那么多图一条记录都没有」。

## 8.7.4（幂等号对不上金额就报冲突）

- `charge()` 的幂等缓存把金额一起存：同一个 `request_id` 换了金额，返回 `idempotency_conflict`，不再把旧流水当这笔的结果（内存和落库两条路都校验）。
- 老流水没有金额可比时照旧按「重复」返回，不误报。

## 8.7.3（说的地点和画的地点必须是同一处）

- 新增「每轮活动快照」：`_dynamic_context` 注入给模型的那份「她在哪/在干嘛」，出图时原样复用（`_activity_snapshot(umo)`，3 分钟有效）。日程刚好在聊天和出图之间翻页，也不会出现「她说酒店、照片在景区」。
- 出图调用带齐 `place / activity / zone`：地点不再由生图插件自己再读一遍状态。
- 主动分享同样用这份快照（概率判定、提示词、出图三者同一处地点）。

## 8.7.2（不再往群里爆代码 + 出去玩要花钱）

- 出站清理新增 `strip_pseudo_tags()`：模型把 `<astrbot_execute_python>` 这类框架标签当正文输出时，整块剥掉、代码围栏一起清；只发语音的那一轮如果正文只剩标签，就整条不发（以前会把标签当文字发进群）。
- 语音标记用的文本也过一遍同样的清理（`<text>…</text>` 包装不再被念出来），拿不到可念的话就不设「只发语音」。
- 地点永远是注入项且带「不许说成别处」：日程在景区她说在酒店的编造被堵住（状态与照片同源）。
- 「拍张照/拍照给我/发张照片」默认自拍：`selfie` 判定传入生图插件，不再因为地点里有「山/店/路」被翻成路人他拍。
- 出去玩要花钱：`_bill_trip()` 在出行覆盖层生效时走 `charge()` → 金融账本 → 记忆，一天一次、幂等号 `travel:<日期>:<城市>`，金额按城市+日期确定（门票+交通+吃饭）。

## 8.7.1（配置自愈不再复活已删除的键）

## 它是怎么工作的

群聊：

```
用户消息
  → 心流引擎（五维评分 + 动态阈值 + 沉浸模式 + 防抖 + 群聊独立配置）
  → 达到条件时设置 event.is_at_or_wake_command = True
  → AstrBot 原生 LLM 生成回复（人格、上下文都走 AstrBot）
  → on_decorating_result 交给完整本地分段引擎
  → 按符号分段、成对符号保护、打字延迟、群聊引用
```

私聊：

```
健康 / 生理期 / 日程门控
  → 通过则走 AstrBot 原生回复
  → 完整本地分段引擎发送（私聊不引用）
```

没有修改 AstrBot 核心代码，也没有替换它的回复链路；心流只负责“要不要说”，分段只负责“怎么说”。

## 功能

- **完整心流（内置）**：五维评分、动态阈值、沉浸模式、判断暂停、防抖、群聊独立阈值、白名单、自定义评分规则、详细日志、心流命令。
- **完整本地分段（内置）**：强制分隔符、字数范围、超长处理、短尾合并、断句符号、标点保留、连续符号顺延、成对符号保护、排除关键词、超长跳过、固定/随机/按字/智能延迟、主动消息处理。
- **生理期**：28 天周期可配置，月经期、卵泡期、排卵期、黄体期；影响心情、体力、疼痛、回复概率与主动求安慰。
- **九维心情**：开心、平静、郁闷、生气、委屈、疲惫、焦虑、兴奋、依恋；直接影响语气。
- **世界观与日程**：基于 AstrBot 人格生成世界观，再由世界观生成每日日程；天气、健康、生理期共同参与。
- **天气**：和风天气；未配置 Key 时本地模拟。
- **长期记忆**：本插件不再自带记忆库，只读写外挂记忆插件（天使之魂 / 我会牢牢记住你 / livingmemory）；记忆会注入回复与主动消息。
- **用户档案**：自动建立，记录名字、称呼、生日、关系、好感；相恋仅管理员可设。
- **用户画像界面**：状态 / 用户画像 / 设置三个页签；可搜索、编辑画像、查看记忆、同步陪伴插件档案，直接调整关系（仇恨/抵触/普通/熟识/相恋）。
- **全部开关进 WebUI**：设置页加载完整 `_conf_schema.json`，布尔开关、数字、文本、列表/模板列表都可直接改，保存后写入插件配置并重建心流/分段引擎。
- **主动私聊**：概率、频率、每日上限；难受时找相恋的人撒娇，遇到有趣的事分享。
- **九维面板**：查看心情雷达、生理期、健康、天气、日程、阈值。

## 配置

配置项分为三组：

- 基础陪伴：`period_*`、`proactive_*`、`mem_*`、`weather_*` 等；
- 心流完整版：`hf_*`（原始心流配置名前面加 `hf_`）；
- 本地分段完整版：`seg_*`（原始分段配置名前面加 `seg_`）。

| 配置 | 说明 |
|---|---|

| `hf_reply_threshold` | 心流基础阈值 0.0-1.0 |
| `hf_enable_dynamic_threshold` | 动态阈值，默认开 |
| `hf_dynamic_threshold_min/max` | 动态阈值上下限 |
| `hf_dynamic_activity_window` | 活跃度统计窗口（秒） |
| `hf_enable_debounce` | 防抖，默认开 |
| `hf_debounce_delay` / `hf_max_debounce_wait` | 防抖等待/最大等待 |
| `hf_immersive_mode_duration` | 沉浸模式持续秒数 |
| `hf_judge_rules` | 自定义五维评分规则 |
| `hf_group_threshold_configs` | 群聊独立阈值 |
| `hf_chat_whitelist` | 群聊白名单 |

| 配置 | 说明 |
|---|---|
| `seg_enable` | 启用完整分段引擎，默认开 |

| `seg_random_delay_range` | 随机延迟范围 |
| `seg_fixed_delay_seconds` | 固定延迟 |
| `seg_per_char_delay_seconds` | 按字延迟 |

> 分段是**符号列表**方案，不是正则。需要调断句符就改 `seg_split_symbols`；成对符号保护默认开启。

## 挂载记忆插件

本插件不带记忆库，记忆来自你装的其他插件。市面上记忆类插件很多，**面板会直接列出你已安装的所有插件**，
选哪个就用哪个的记忆和画像，不用改代码：

| 配置 | 说明 |
|---|---|
| `companion_memory_plugin_name` | 挂载的记忆插件；留 `auto` 自动检测，面板下拉列出已安装插件 |
| `companion_memory_include_profile` | 读取挂载插件的画像（强记忆、边界、表达习惯、偏好、兴趣） |
| `companion_memory_include_important` | 读取挂载插件的长期记忆（不限条数） |
| `companion_profile_sync` | 从挂载插件自动补全用户画像（只补名字/生日/关系） |

**检索是按 `uid` 查的**（QQ 号 / 平台用户 ID）：召回时带着当前说话人的 uid 去插件里查，
查不到再按名字/称呼兜底；画像也以 uid 为主键（同名不同号不会串）。

能自动读取的结构（有哪个读哪个，都不限制条数）：

- `users[uid]["companion_memory"]["items"]` 的 `text` / `weight`；
- `companion_memory["profile"]` 里的 `strong_memories`、`boundaries`、`speaking_style`、`weak_preferences`、`interests`；
- `users[uid]["important_memories"]`；
- `worldbook_member_profiles[uid]["important_memories"]`；
- 实现了 `search_for_event` / `recall_for_event` / `search_memory` 等检索接口的插件（直接调用它的检索）。

只读，不修改挂载插件的数据；没有可用的记忆插件时就不注入记忆（本插件不再自带记忆库）。

> 注意：陪伴插件本身也会回复消息。如果两个插件同时接管聊天，可能出现双回复；建议只保留一个负责回复，另一个作为记忆源。

## 版本号规则

- 三段：`x.y.z`，**第二位和第三位只能是 0-9，逢十进一**：3.8.9 → 3.9.0，3.9.9 → 4.0.0；
- **首位不做限制**，可以是多位数：9.9.9 再进一位是 10.0.0（不是 1.0.0.0）；
- **测试版**：动第三位（7.4.0 → 7.4.1）；
- **发布版**：动第二位、第三位归零（7.4.1 → 7.5.0）；
- **大版本**：首位 +1（7.5.0 → 8.0.0）；
- `python3 tools/check_version.py` 校验四处一致与规则，
  `python3 tools/check_version.py --next test|release|major` 直接算下一个号。
