## 为什么？

**2026，AI Agent 爆发的元年。**

OpenClaw、Claude Code……Agent 正在从"工具"变成"同事"。但一个根本问题浮出水面：

> **你的 AI 同事每次上班都失忆。**

ChatGPT 记不住你的审美偏好。Cursor 不知道你上次的架构决策。OpenClaw 的 MEMORY.md 越写越长，token 越烧越多。我们给 AI 装上了记忆体，却没有给它记忆系统。


**黑方体给出一套全新的解决方案。**

当 OpenClaw 社区从早期玩家走向主流用户，"AI 记忆"正在从 Nice-to-Have 变成 Must-Have。不是简单的"记住上次聊了什么"——而是**结构化地理解一个完整的人**。

## 它解决了什么

### AI 记忆的"不可能三角"

| 方案 | 能记？ | 能理解？ | 能无限增长？ | 成本可控？ |
|------|:------:|:--------:|:------------:|:----------:|
| **传统 RAG** | ⚠️ 碎片 | ❌ | ❌ 检索衰减 | ⚠️ |
| **长上下文 (128K+)** | ✅ | ❌ 过载遗忘 | ❌ 成本爆炸 | 💀 |
| **MEMORY.md** | ✅ | ⚠️ | ❌ 文件不可控 | ⚠️ token 膨胀 |
| **黑方体** | ✅ | ✅ 结构化 | ✅ 越用越准 | ✅ ~2K/次 |

### 黑方体的解决思路

不把所有记忆塞进上下文，而是建一个**结构化的个人数据仓库**——

> AI 像查数据库一样查你的档案：精准、按需、毫秒级。

## 一句话体验

你和 AI 聊第 100 次话时，它不需要回顾 99 次对话全文，而是：

- 知道你上次讨论职业选择时的决策风格是 `calculated + growth`
- 记得你偏好极简、低饱和、留白多的视觉风格
- 理解你面对压力时的应对模式是 `problem_focused + talk_it_out`
- 直接调用你三个月前设定但忘了的目标，提醒你进度

**这或许就是 Agent 时代该有的记忆系统。**

## 核心特性

### 🧠 结构化记忆 — 不是聊天记录，是人格档案

```
8 大域分类
├── 身份认知    — 你怎么定义自己
├── 心理结构    — 你的思维模式和决策倾向
├── 审美偏好    — 你的视觉、听觉、品味
├── 职业画像    — 你的技能树和职业轨迹
├── 计划目标    — 你想成为什么样的人
├── 日程节奏    — 你的时间习惯和能量曲线
├── 杂项偏好    — 饮食、运动、生活习惯
└── 关系网络    — 你在意的人和社交模式
```

**海量维度，持续扩展。** 每个维度只有 `id` + `name` + `focus_prompt`，AI 自主判断该不该记录、怎么记录。

### ⚡ 按需加载 — 一次只花 ~2000 tokens

```
传统方式:  把全部记忆塞进 context  → 💸💸💸
黑方体:    对话前 → 语义分析 → 只加载相关维度 → ✨
```

OpenClaw 的 Pre/Post Hook 机制让它零侵入运行：
- **对话前**：分析当前话题 → 从 500+ 维度中选出最相关的 → 查询 SQLite → 注入上下文
- **对话后**：分析对话内容 → 提取结构化数据 → 写入 SQLite
- **全程自动**，你不需要做任何事

### 🎯 智能召回 — 不是检索，是推理

```
用户说："帮我设计一个方案"

阶段1: 多路召回
├── 语义召回    — "设计方案" → 职业画像 + 审美偏好 + 决策风格
├── 历史召回    — 上次聊方案时用了哪些维度？
├── 热度召回    — 全局哪些维度最常被调用？
├── 共现召回    — 跟"决策风格"一起出现过的维度
└── 无数据召回  — 哪些维度该填但还没填？

阶段2: 打分排序
score(d) = α·rel_llm + β·hist + γ·pop + δ·cooc - λ·fatigue - μ·over_coverage

阶段3: LLM 重排
└── 生成最终的 focus_prompt → 引导 AI 精准提取
```

### 🔒 隐私分离 — 你的数据，留在你的机器

| 数据 | 存哪 | 离开本地？ |
|------|------|:----------:|
| 对话原文 | 本地 memory/ | ❌ 从不 |
| 结构化档案 | 本地 SQLite | ❌ 从不 |
| 维度 ID + 字段数 | 服务端元数据 | ✅ 仅元数据 |
| 分析策略 | 服务端 → 客户端 | ✅ 引导数据 |

**核心原则：服务端是"大脑"，不是"保险箱"。** 它只决定该记什么、怎么记，你的实际数据永远在本地。

## 差异化对比

| | 传统 RAG | 长上下文 | MEMORY.md | **黑方体** |
|--|----------|----------|-----------|:----------:|
| 数据结构 | 碎片文本 | 全量文本 | 自由文本 | **结构化** |
| 检索方式 | 关键词 | 全量扫描 | 通读 | **SQL 精准查询** |
| 上下文消耗 | 不确定 | 全部 | 全量 | **~2K/次** |
| 跨维度关联 | ❌ | ❌ | ❌ | **✅** |
| 记忆进化 | ❌ | ❌ | ❌ | **✅ 越用越准** |
| 隐私 | 依赖外部 | 依赖外部 | 本地 | **本地 + 脱敏** |

### 比本地 RAG + OpenClaw 多了什么？

| 需求 | 本地 RAG | 黑方体 |
|------|----------|--------|
| 维度概念池 | 需要自己维护 | **维度即服务**，海量维度持续更新 |
| 结构化写入 | 难定位"该记到哪" | **维度级事件**，自动归档 |
| 智能取数 | 检索什么用什么 | **语义层决策**，知道该用哪些维度的组合 |

## 技术栈

| 组件 | 选择 | 为什么 |
|------|------|--------|
| 本地存储 | **SQLite** | 零依赖、单文件、毫秒级查询 |
| 服务端 | PostgreSQL + JSONB | 灵活 schema、JSON 原生支持 |
| 向量检索 | Embedding-2 + 余弦相似度 | 语义理解准确 |
| 客户端 | OpenClaw Skill Hook | 零侵入、自动运行 |
| 服务端 API | FastAPI + Agent 框架 | 高性能、异步友好 |
| 用户导出 | CSV / Markdown | 用 Excel 直接打开 |

## 与 OpenClaw 生态

黑方体是 OpenClaw 的记忆层插件。它和 OpenClaw 原生的 `MEMORY.md` 互补而非替代：

```
MEMORY.md        →  手写的核心备忘（"主人叫 LL"）
黑方体 SQLite    →  AI 自动积累的结构化档案（"LL 偏好极简设计"）
OpenClaw Session →  当前对话上下文
```

三者协同，构成完整的 AI 记忆体系。
