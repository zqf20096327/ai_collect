# 情绪混剪 Vlog 剪辑编译器

把「我喜欢这种感觉」翻译成可执行的剪辑方案。

给它参考片、口播和你自己的素材，它输出风格档案、语义锚点表、逐镜剪辑执行单，以及可以直接交给剪辑产品的初剪指令。你改完之后，它把你的修改记成候选偏好——**只有你明确说「以后也这样」，才会写进长期风格。**

它生成的是**可编辑初剪**，不是一键终稿。

---

## 它的逻辑

一句话：**口播是时间主轴，画面服从口播的语义。**

展开是四层联动——

```
口播语义决定画面      每一次切换都要承担新的语义、动作或情绪
情绪变化决定速度      信息密集处快切，转折与沉淀处放慢
关键动作决定卡点      动作的落点对准对应的关键词
空间变化决定声音和转场  换了空间，声场和转场才跟着换
```

在此之上有两条纪律：

**结论必须能读回。** 每个判断都标明证据来自哪里——文件属性、静帧、连续播放、试听，还是执行器。没验证的一律标为待验证，不写成已完成。

**修改不自动等于审美。** 你的每次调整先存成候选，写清原因和适用范围，由你确认归类。没确认的，下一个项目不会自动执行。

---

## 它做三件事

**看懂审美** —— 分析你指定的参考片，提炼叙事、情绪曲线、镜头语言、镜长档位、声音与字幕特征。只把跨样本重复出现的写进风格档案，单片特征和未验证的假设分开存放。

**执行审美** —— 把文案、素材库和风格档案连起来，生成逐句的语义锚点和逐镜的剪辑执行单。抽象表达必须转译成看得见的动作、人物反应或环境变化。

**积累审美** —— 你的每次修改都被记录成候选偏好，写清修改前后、原因、适用范围和反例，由你确认归类。一次修改不会自动变成长期规则。

## 适用范围

**情绪混剪 Vlog**：以第一人称旁白为时间主轴、由多条零散生活素材拼成、靠情绪推进而非信息罗列的片子。母婴、亲子、旅行、成长、关系、宠物、品牌情绪都属于这一类。

**目前只在母婴题材上验证过。** 其他题材原理相通，但没有实测证据，第一次跑请自己盯紧。

### 不适用

| 类型 | 原因 |
|---|---|
| 知识口播、产品测评、教程、访谈 | 画面不由口播语义决定，套用会变成逐字配图 |
| **纯音乐卡点** | 缺人声就缺时间主轴。不是参数问题，是缺一整条输入链 |
| 赛事集锦、剧情短片 | 同上 |

---

## 输入与输出

**你要准备**：一组参考片（你自己的旧作品也行）、一份文案或已录好的口播、一个明确授权的素材目录、目标平台与画幅。

**它会产出**：风格档案、语义锚点表（含未匹配缺口表）、逐镜剪辑执行单、执行器指令、候选偏好记录。

---

## 它不会给你什么

先把期望对齐，省得跑完失望。

- **不产出成片。** 它产出的是一份逐镜方案和一条**可编辑初剪**，剪辑、调色、配乐、导出仍然是你的事。
- **不替你看片。** 它没有听觉，动态画面也只在你让它抽帧时才看得到一部分。抖动、失焦、声音听感这些，最后必须你自己过一遍。
- **不保证一次到位。** 它明确区分"已验证"和"待验证"，产出里会有一批标着待确认的项。这是设计如此，不是没做完。
- **不会自动学你的口味。** 你的修改先存成候选，你不确认它就不复用。

### 你还需要一个执行器

它输出的是一份**工具无关的剪辑指令**：每镜的素材路径、原片入出点、时间线位置、字幕与声音。要变成真的时间线，需要下面二者之一：

- **能读指令的剪辑 Agent 或 AI 剪辑工具** —— 把 `assets/executor-prompt-template.md` 连同产出文件一起交给它。
- **你自己在普通剪辑软件里手动执行** —— 逐镜执行单本身就是一份完整的镜头清单，照着拉时间线即可。慢，但可行。

**没有执行器的话，你拿到的是一份很详细的文档，不是视频。**

### 大概要多久

以 300 条素材、一条 60 秒成片为参考：

| 步骤 | 耗时 |
|---|---|
| 建媒体清单（含哈希与探测） | 约 10 分钟 |
| 素材匹配与逐镜执行单 | 约 30 分钟 |
| 参考片学习 | 取决于参考片的数量与长度 |

它被明确要求不用抽样代替全量分析，所以慢是预期内的。

## 推荐操作顺序

顺序不是建议。每一步都依赖上一步的结果，乱序要返工。

1. **先把文案定稿。** 文案决定语义锚点，锚点决定每一镜配什么画面。

2. **录好口播，并确认不再改。** 口播是时间主轴，总时长、停顿、重音都由它决定。没有口播，时间只能靠字数估算，实测偏差可达 15%，之后全表要重排。粗录能先用来校准，但换正式配音后还要再排一次。

3. **一次性给全参考片。** 它要区分「跨样本重复的稳定特征」和「只出现在一条里的单片特征」。样本不全，这个区分做不出来。

4. **确认素材范围，再建媒体清单。** 清单是后面所有素材引用的基础。

5. **先出风格档案，再做素材匹配。** 镜长、声场、转场语言都从档案推导。

6. **匹配完先处理缺口表。** 它会列出「这句话在你的素材库里没有对应画面」，每一处你要么补拍，要么明确接受一个代偿画面。同时注意：素材的自动标签只用于候选召回，真实画面必须自己看过再定。

7. **执行单定稿后，再交给执行器。** 执行器负责建立可编辑时间线，不负责决定风格。

8. **从头到尾连续看完、听完，再给反馈。** 静帧和结构检查替代不了播放——抖动、失焦、动作起落、声音听感只有播一遍才看得出来。它标「待验证」的地方是字面意思。

9. **给反馈时说明原因。** 它靠原因区分：这是执行缺陷、只针对这条片子的修正、还是你的长期审美。只说「感觉不对」，它无法归类。

10. **要它记住一条规则，明说「以后也这样」。** 它不会把你对某次修改的认可当成长期规则。

## 工具脚本

```bash
# 建立只读媒体清单（时长、实际显示方向、音轨、哈希）
python3 scripts/media_inventory.py <素材目录> --output inventory.json

# 复核素材是否缺失、被替换或混入清单外文件
python3 scripts/verify_inventory.py inventory.json
```

**依赖 `ffprobe`**，随 ffmpeg 一起安装：

```bash
brew install ffmpeg          # macOS
sudo apt install ffmpeg      # Debian / Ubuntu
```

**已知限制**：`media_inventory.py` 只支持**扫描一个目录**。如果你的授权范围是散落在多处的一批文件，目前的办法是先建一个目录、把这些文件做成只读软链接再扫描——清单里记录的仍是解析后的真实路径。按文件清单直接扫描的入口在计划中。
