# Cross-Runtime Inference Tester

**One model. Multiple runtimes. Verified predictions.**

Cross-Runtime Inference Tester measures whether a numerical ONNX model produces equivalent outputs in Python ONNX Runtime and browser ONNX Runtime Web. It reports numerical drift, class agreement, artifact identity, and measured runtime latency. Its bundled renewal-risk model uses synthetic data for engineering demonstration only; it is not a validated business risk estimate.

![Cross-Runtime Inference Tester runtime parity dashboard](docs/images/dashboard.png)

## What it does

- Builds a deterministic, stratified scikit-learn training, validation, and test workflow.
- Exports the complete `StandardScaler + LogisticRegression` pipeline as one float32 ONNX artifact.
- Verifies artifact SHA-256 and graph metadata before inference.
- Generates 256 held-out vectors plus typical, boundary, numerical, and batch fixtures using actual Python ONNX Runtime execution; all 268 are executed in the browser suite.
- Compares arrays with `abs(a-b) <= atol + rtol * abs(reference)`, reports class agreement, and fails on shape/non-finite/drift errors.
- Runs the same model locally in a browser Web Worker using the WASM execution provider.
- Measures Python and browser initialization, first inference, warm latency, batch behavior, and asset sizes; timing results are device-specific.
- Produces JSON, HTML, and Markdown reports and a static dashboard.

## Quick start

Requirements: Python 3.11+, Node.js 20+, pnpm 12.3.4, and uv.

```sh
uv sync --extra dev
pnpm install
uv run --project . cross-runtime-inference-tester demo
uv run --project . cross-runtime-inference-tester verify
pnpm dev
```

Open the local Vite URL printed by pnpm. The first request to the dashboard loads static model and runtime assets; inference then runs in the browser. No server-side prediction endpoint, account, paid service, cloud credentials, GPU, or model download is required.

### CLI

```sh
uv run --project . cross-runtime-inference-tester --help
uv run --project . cross-runtime-inference-tester train --seed 2026 --samples 7000
uv run --project . cross-runtime-inference-tester validate
uv run --project . cross-runtime-inference-tester predict '[18,15,1,0,24,49,45,4]'
uv run --project . cross-runtime-inference-tester benchmark --warmup 10 --iterations 100 --independent-runs 3
uv run --project . cross-runtime-inference-tester verify --atol 0.0001 --rtol 0.001
uv run --project . cross-runtime-inference-tester doctor
```

`demo` trains, exports and validates the model, then writes the manifest, metrics, fixtures, and Python reference predictions under `artifacts/models/subscription-risk-v1/`. `verify` compares the stored Python ONNX references with fresh Python ONNX Runtime outputs. Cross-runtime browser verification is performed by Playwright and the dashboard; it requires generated artifacts and browser dependencies.

Example local verification output:

```text
PASS 268/268 cases; reports: artifacts/reports
```

This is generated by the synthetic fixture suite on Python ONNX Runtime CPU. It does not imply browser WASM results; those are written separately by Playwright.

## Architecture

```text
deterministic synthetic data → sklearn Pipeline → ONNX + manifest + SHA-256
                                                    ├─ Python ONNX Runtime CPU
                                                    └─ Browser ONNX Runtime WASM
                                  golden float32 vectors → parity comparison → reports
```

The manifest records graph input/output names, types, shapes, feature order, class interpretation, opsets, library versions, and artifact identity. It is validated by the Python contract and the browser checks required fields and graph metadata before execution. Browser predictions do not call the CLI or a remote inference service. See [architecture](docs/architecture.md), [model contract](docs/model-contract.md), and [numerical parity](docs/inference-parity.md).

## Reports and measurements

`cross-runtime-inference-tester verify` writes `report.json`, `report.html`, and `report.md` in `artifacts/reports/`. `cross-runtime-inference-tester benchmark` writes measured Python initialization, first inference, and warm latency at batch sizes 1, 8, 32, and 128 to `artifacts/benchmarks/python.json`. The browser benchmark measures blocks of repeated real WASM executions to reduce browser timer quantization, after 10 warmups, at those same sizes. It reports per-execution averages and the repetition count. Cross-machine timings do not establish that one runtime is universally faster; transfer, initialization, and warm inference are distinct costs. See [benchmarking methodology](docs/benchmarking.md).

## Dashboard

The static dashboard includes live browser inference with editable features, the complete fixture comparison suite, category and status filtering, input/output inspection, local tolerance recalculation, error distribution, parity matrix, percentile and startup charts, measured batch latency plots, worst-case ranking, benchmark controls, and isolated injected faults. Browser and Python benchmarks measure multiple independent ONNX sessions. Python reference values are explicitly identified as previously generated by the CLI.

## Adding a model

The current registration command validates a trusted local ONNX graph and a versioned manifest, enforces a 100 MiB file limit, verifies SHA-256, and checks the Python CPU runtime contract:

```sh
uv run --project . cross-runtime-inference-tester register model.onnx manifest.json --output artifacts/models/my-model
```

The supported inference contract is float32 numeric input and a float32 `[batch, 2]` probability output for the browser dashboard. The Python comparison core also handles task-independent numeric arrays. See [adding models](docs/adding-models.md). ONNX graphs and conversion toolchains are untrusted input; only register files you trust.

## Browser deployment

```sh
uv run --project . cross-runtime-inference-tester demo
uv run --project . cross-runtime-inference-tester verify
uv run --project . cross-runtime-inference-tester benchmark
pnpm build
```

The Vite build copies the generated model bundle and bundles the matching ONNX Runtime Web WASM asset to `apps/web/dist/`. Deploy that directory as static hosting, including `apps/web/public/_headers` (Cloudflare Pages applies it when present). Single-threaded WASM is the baseline and does not require cross-origin isolation. Threaded WASM is detected as unavailable/unused in this version; no false threaded capability is reported. See [deployment](docs/deployment.md) and [runtime support](docs/runtime-support.md).

## Limitations and roadmap

- Only the synthetic binary classifier is exercised by the browser UI today; arbitrary ONNX input contracts are not automatically supported by the dashboard.
- The browser suite uses WASM CPU; WebGPU, native mobile, and threaded execution are outside the current verified matrix.
- The browser report captures page timing, asset sizes, model fetch/hash, session setup, first inference, and warm execution. It does not run a controlled cold-versus-warm HTTP cache experiment; browser-version matrix and hosted Pages headers also require separate deployment checks.
- Benchmark comparisons are descriptive, not cross-device runtime rankings.
- Future work: generic manifest-driven regression and multiclass browser outputs, Firefox/WebKit verification, controlled cached-versus-uncached browser runs, separate process-startup measurements, and optional threaded WASM.
