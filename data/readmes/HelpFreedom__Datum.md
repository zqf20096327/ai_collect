# Datum

**Русский** · [English](README.en.md) · [Video](https://www.youtube.com/watch?v=C5_5jtvc_hw)

**Инженерный ИИ-редактор: конструирует и считает ИИ-агент, человек ставит
задачу и направляет.** Вы говорите, что нужно, — «корпус под эту плату с
защёлкой», «рука на двух сервах, поднимает 100 г», «ложемент под этот скан»,
— а агент строит детали, объявляет, откуда взято каждое число, гоняет
проверки и расчёты, показывает вам результат в окне и сам исправляет то, что
не прошло. Вы смотрите, мерите, поправляете замысел и решаете, когда готово.

Datum создан для агента. Его операции — это инструменты агента; проверки
сообщают не «красное», а причину словами; окно — общее рабочее место, где
агент видит то же, что вы, и может показать вам деталь, срез или место
задевания. Рассчитан на [Claude Code](https://claude.com/claude-code): он
встроен в окно, а правила конструирования приходят к нему навыком. Без
агента Datum — это библиотека и набор команд, а не редактор.

![Datum: симуляция робо-руки с картой нагрузки и проверками](docs/media/demo.gif)

> Проект молодой и развивается. Проверен на Linux (x86-64). Интерфейс,
> сообщения и документация — в первую очередь на русском.

## Как выглядит работа

1. Вы открываете окно и ставите задачу агенту словами — в доке внизу.
2. Агент заводит параметры с происхождением (замерено, угадано с диапазоном,
   выведено формулой, взято из паспорта), пишет детали скриптами на Python и
   собирает их.
3. Он прогоняет проверки и расчёты: собирается ли изделие, держит ли
   защёлка, хватит ли привода, выдержит ли звено, напечатается ли деталь.
   Не прошло — исправляет и прогоняет снова.
4. Неизвестное он не угадывает молча: развёртка показывает, какое из
   незамеренных чисел решает дело, и агент просит померить именно его.
5. По ходу он показывает вам результат в окне; вы мерите штангенциркулем,
   выделяете деталь, говорите «вот здесь тонко» — агент видит, о чём речь.
6. Когда проект готов, ИИ-критик со свежим контекстом ищет упущенное; на
   выходе — файлы для производства, ведомость и сборочная инструкция.

## Что умеет

- **Детали и сборки.** Тело строит ядро [manifold3d](https://github.com/elalish/manifold):
  примитивы, булевы операции, фаски и скругления, резьба, надписи по шрифту,
  скульптура полем, карман по пути вставки, ложемент по скану, Gridfinity.
  Сборка — порядок, способ постановки (вдвигается или защёлкой), шарниры.
- **Детали машин.** Ось в проушине (срез, смятие, изгиб), винтовая пара (КПД,
  самоторможение), балки, подшипники качения, устойчивость стержня, кулачок и
  клин с трением, лишние связи механизма — каждая проверка на все виды
  отказа, а не на один.
- **Прочность.** Метод конечных элементов (P2-тетраэдры, сетка fTetWild) с
  тестом заплаты на той же сетке; ответ — вилка, а не одно число, острые
  углы опознаются как особенность, а не как прочность.
- **Механизмы.** Симуляция в MuJoCo: момент приводов против паспорта,
  отставание, устойчивость или нагрузка на крепление, задевания по точной
  геометрии, напряжения звеньев в худший момент, люфт и трение, если они
  объявлены; выгрузка GLB с движением, MJCF и URDF.
- **Материалы и покупное.** Каталог пластиков (PLA, PETG, ABS, ASA, TPU) —
  параметрами проекта; любой другой материал — своими модулем, плотностью и
  прочностью с источником, и свой замер всегда перебивает каталог. Покупные
  детали (сервы, подшипники, крепёж) участвуют в сборке и расчётах, а
  библиотека компонентов переносит их между проектами.
- **Числа с происхождением.** У каждого параметра — `measured`, `assumed` (с
  диапазоном), `derived`, `standard` или `chosen`; развёртка по угаданному
  отделяет то, что надо мерить, от того, что мерить незачем.
- **3D-печать.** Печатность в позе печати (стенка, нависания, мосты,
  полости, первый слой, прочность между слоями), 3MF и STL со сверкой
  записанного файла, нарезка консольным ElegooSlicer и разбор G-code по
  слоям, масса по настройкам печати, пробные образцы посадок.
- **Окно.** Electron + three.js: штангенциркуль как в слайсере, толщина
  стенки, срез, разнесённый вид, перенос и поворот мышью, версии со
  сравнением формы, проигрыватель симуляции с картой нагрузки, лента всех
  действий — ваших и агента.

## Агент

Встроенный Claude Code получает:

- все операции Datum как инструменты MCP — те же, что кнопки окна и CLI;
- навык с правилами конструирования (плагин `plugin/`), в любом проекте;
- окно: что выделено и скрыто, откуда смотрит камера, что выбрано
  штангенциркулем, весь стол картинкой — и возможность показать вам деталь,
  срез или подпись;
- ИИ-критика и команду `/datum:audit` — независимую проверку проекта по
  темам несколькими агентами;
- журнал решений проекта, который новая сессия получает сводкой.

Какого агента использовать — выбор пользователя: любой агент с поддержкой MCP
подключается к тем же операциям командой `datum mcp --stdio`. Но окно, навык,
критик и хуки сделаны под Claude Code, и с ним Datum работает в полную силу.

## Установка

Нужны: Linux, Python 3.11, Node.js 22.12+ с npm, компилятор C++ и `make` (для
нативного модуля терминала), [Claude Code](https://claude.com/claude-code)
(`claude` в `PATH`, вход выполнен) — или другой агент с поддержкой MCP.
Необязательно: ElegooSlicer — для нарезки из Datum.

```sh
git clone https://github.com/HelpFreedom/Datum.git
cd Datum
python3.11 -m venv .venv
.venv/bin/pip install --require-hashes -r py/requirements.lock
.venv/bin/pip install --no-deps -e py
scripts/bootstrap.sh          # зависимости окна; скрипты установки — поимённо
npm run build
make install                  # команда `datum` в ~/.local/bin (терминал, dmenu, меню)
```

Подробно, с объяснением каждого шага и решением частых проблем, —
[руководство](docs/guide.md).

## Быстрый старт

```sh
datum                     # окно с пустым проектом «Без названия»
datum examples/arm        # или открыть пример
```

В окне нажмите «Запустить Claude Code» в нижней панели и опишите задачу,
например:

> Сделай настенный держатель для двух отвёрток диаметром 8 мм, печатать
> из PETG без поддержек. Диаметры я не мерил — уточни, что важно померить.

Агент заведёт параметры, построит деталь, прогонит проверки, покажет вам
результат и спросит то, чего не знает. Без окна — `claude` в каталоге
проекта (`.mcp.json` пишет `datum init`) или в репозитории после `make mcp`.

## Под капотом

Всё, что делает агент, — открытые файлы и команды, которыми можно
пользоваться и самому. Деталь — Python-скрипт в `parts/` проекта:

```python
from datum.build import P, centre_on_bed, part
from datum.geom import box, cyl_z, diff


@part("пластина", print_up="+Z")
def build():
    w = P.PLATE_W
    plate = box(-w / 2, w / 2, -w / 2, w / 2, 0, P.PLATE_T)
    hole = cyl_z(P.HOLE_D, -1, P.PLATE_T + 1)
    return centre_on_bed(diff(plate, [hole]))
```

```sh
datum init   ~/parts/plate   # новый пустой проект
datum build  ~/parts/plate   # собрать
datum check  ~/parts/plate   # проверки; код 1 при провале
datum sweep  ~/parts/plate   # что измерить в первую очередь
datum export ~/parts/plate   # 3MF и STL в output/, в позе печати
```

Полный пример с параметрами — в [руководстве](docs/guide.md#первый-проект).
Все команды — `datum --help`; они же инструменты агента (`mcp__datum__*`).

## Окно

Сверху — меню, состояние проекта и кнопка «Проверить». Слева — сцена (детали,
видимость, порядок сборки), импортированные модели, версии и корзина. Справа —
свойства выделенной детали, проверки (худшие сверху) и параметры с
происхождением. Снизу — Claude Code и лента вызовов: в ней видно, что сделали
вы и что агент.

| Клавиша | Действие |
|---|---|
| `D` | штангенциркуль: вершина, ребро, окружность (Ø), центр отверстия, грань; два элемента — расстояние или угол |
| `T` | толщина стенки (считает сервер) |
| `M` / `R` | перенос / поворот детали; это правка проекта (`placement.yaml`) |
| `E` | разнести детали / вернуть в сборку |
| `B` / `C` | собрать / проверить |
| `H` | вернуть камеру |
| `Delete`, `Ctrl+Z` | удалить деталь целиком (в корзину проекта) и вернуть |
| `Ctrl+S`, `Ctrl+Shift+S`, `Ctrl+O` | сохранить, сохранить как, проекты |
| `?` | все клавиши; буквы работают в любой раскладке |

## Примеры

| | |
|---|---|
| `examples/hello` | то, что создаёт `datum init`: пустой проект |

## Проект на диске

```
datum.toml            оборудование, стол, материал
params/base.yaml      параметры с происхождением
parts/*.py            скрипты деталей (и механизмы для симуляции)
lib/                  общие помощники проекта
assembly.yaml         порядок сборки, способ постановки, шарниры
checks/checks.yaml    проверки из каталога (`datum checks`)
NOTES.md, JOURNAL.md  рассуждения и журнал решений
.datum/, output/      кеш и выгрузка (в архив не идут)
```

Проект — обычная папка с текстом: его правят агент, редактор и git, а
«Сохранить» упаковывает его в один архив `.datum`.
