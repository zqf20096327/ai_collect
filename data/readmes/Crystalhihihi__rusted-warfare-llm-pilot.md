# Rusted Warfare LLM Pilot

让大模型真正参与即时战略游戏的判断与指挥，而不是由固定脚本锁定资源、敌人和打法，再让模型点头确认。

这个项目希望看到的是：多个 AI 在各自权限内自主行动，面对同一战场形成不同的选择，并产生可以被观察、解释和复盘的实际行为。目标不是预设一套必胜打法，也不是让随机选择器冒充智能。

## 基本原则

- **模型负责决定。**决定做什么、为什么做、投入多少、在哪里行动、承担什么风险。
- **系统负责支撑。**整理真实战况、计算地图和资源信息、检查权限、执行模型命令并报告真实结果。
- **没有授权就不行动。**系统不能自行造兵、建设、升级、侦察、进攻或撤退。
- **不接受表面成功。**命令被接受不等于建筑建成、单位出厂或战斗完成，必须有游戏现场的真实证据。

## 角色分工

**总指挥**负责战争方向、经济重点、主要进攻方向和阶段安排。

**中层**负责战队编制、生产补员、具体任务和多队配合。包抄、风筝、集火等有组织的战术由中层规划，不推给快速层。

**快速层**只指挥已经分配给自己的战队，在明确战斗任务和预案内处理简单的现场动作。它不能抢单位、改编制、改生产或自行改变战略目标。生产、集结、巡逻和探索都需要中层明确授权；没有任务时保持现状。

快速层是否真能产生有价值的行为，仍需要真实战斗检验。它不是随机选择器，也不能用预设战术替它表演。

## 一轮怎样工作

1. 模型收到当前目标、相关事实和未读通知。
2. 模型完整思考并写下本轮任务或工单。
3. 模型正常交付后，系统才统一检查并执行；思考期间的草稿不会提前生效。
4. 系统持续落实已授权任务，并把真实结果写入角色信箱。
5. 有实质变化时再唤醒对应角色；没有事情就待命，不持续调用模型。

普通战况刷新不会打断正在思考的模型，也不会仅因出现新快照就丢弃它已经完成的回复。紧急消息默认在轮次之间交付，不假装能随时插入思考。

## 当前状态

已经在真实对局中完成海军厂、空军厂、采集器升级、防御建筑、资源制造仪，以及多类海空单位的生产与归队。

项目仍在发展。模型响应速度、复杂阵地、施工队分配、生产数量语义、真实战斗快速层和高级操作仍需继续完善。当前成果不代表已经具备完整即时战略指挥能力。

## 构建与运行

构建游戏附件：

```bash
bash agent/build.sh
```

运行检查：

```bash
python -m unittest discover -s tests -v
```

启动自用研究版本：

```bat
tools\run-with-agent.bat
```

启动公开模式：

```bat
tools\run-with-agent-public.bat
```

只开启当前需要的角色，例如只开启建设席：

```bash
python -u bridge/pilot.py --roles build --objective "由用户填写当前目标"
```

公开模式禁止多人。自用人机研究需要显式开启；真人多人测试需要另行明确授权。
