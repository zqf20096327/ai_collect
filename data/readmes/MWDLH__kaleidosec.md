# Kaleidosec

[English](README.en.md) | 简体中文

> **随视角变化，呈现无限安全图景。**
> *Every angle, a different path.*

Kaleidosec 是给 AI Agent 的**渗透测试决策模式**。它不提供扫描器、不编排工具、不生成 payload；
它注入的是一套决策协议——如何评估目标、如何取舍路径、如何用证据支撑每一步、何时收手。

名字取自万花筒：同一个目标，换一个身份、一个入口、一个视角，攻击面就是另一幅图景。
有经验的测试者不会只盯着一个角度，而是在多个视角之间切换，挑出最值得走的那条路。

Kaleidosec 以 Claude Code 插件的形式分发：一份常驻决策协议，加上两个生命周期 hook。
装好后，在渗透工作目录或明确信号下自动进入模式；不需要时完全不注入。它也可以作为普通 skill 单独使用。

---

## 它解决什么问题

AI Agent 不缺漏洞知识。SQL 注入的分类、Kerberos 的认证流程、云 IAM 的提权路径，它答得比多数人完整。
它缺的是在真实、动态、信息不完整的现场里**持续做对取舍**：先打哪、打多深、什么时候停。

自动化工具擅长**覆盖**，把已知的攻击面快速扫一遍；现场真正消耗时间的是**取舍**。
Kaleidosec 做的是后者——它可以和现有的扫描器、利用框架、代理工具一起用：工具负责执行，
它负责决定执行什么、以什么顺序执行、什么时候停止。

| 常见问题 | Kaleidosec 的机制 |
|---|---|
| 失败就换工具，不诊断原因 | 8 维失败分类，每次只改一个变量 |
| 把扫描器输出当成结论 | 证据分级：事实 / 推断 / 假设 / 未知 / 已否定 |
| 换个攻击面就从头扫描 | 模块调用栈 + 父路径回传，跨域携带身份与证据 |
| 在一条路径上无限深入 | 路径四态（活跃 / 深入 / 搁置 / 关闭），搁置带重激活条件 |
| 说不清为什么走这一步 | 每一步输出：判断 / 证据 / 未知项 / 为什么优先 / 失败改什么 |

## 怎么工作

一次授权测试被建模为持续更新的决策循环：

```text
定位当前位置 → 整理已有证据 → 排序候选路径
→ 执行一个有边界的动作 → 判读结果 → 更新状态 → 重新排序
```

循环里有三个原则：

- **分档判断**：按暴露面、身份与权限边界、仍会改变路线的未知项、目标价值、可用预算评估。
  默认从最轻的一档开始，证据变化时升档，连续没有收益时收口。
- **证据纪律**：事实、推断、假设、未知、已否定分开记录；每一步动作都绑定已确认的事实，
  不因为"手上有这个工具"就动手。
- **主动止损**：收益不再支撑成本时搁置路径并写明重激活条件，而不是机械地把工具跑完。

决策分层：硬边界由规则固定（高危操作人工确认、是否注入、基础盘必须执行），
判断交给模型（走哪条路、多深、何时停），每一步强制留痕。

### 最高安全红线

高危操作必须由真人确认。这一层优先于所有工作流和分档判断——预授权不能覆盖，"之前批准过"也不等于现在批准：

- **持久化**：计划任务、服务、启动项、后门、账号创建
- **信任或权限变更**：域管、ACL、证书模板、IAM、令牌签发
- **生产或控制面变更**：业务配置、WAF/EDR、安全组、路由、DNS
- **不可逆或可能中断业务**：删数据、批量外带、DoS 验证、生产库写入
- **会改变目标状态的主动攻击**：写数据、落盘、自我复制、批量凭据猜测

无法确认时，搁置该分支并标注"待确认"，不静默降级、不自行放行。

插件还会对少数明显的高危命令（递归删除、持久化写入、凭据导出、批量口令尝试）弹出确认提示，作为一层兜底。它只覆盖最明显的形态，不能替代人的判断。

## 安装

需要 Python 3.8+，并以 `python` 命令可用（macOS / Linux 只有 `python3` 时，见
[`examples/claude-hook/`](examples/claude-hook/) 的说明）。

```
/plugin marketplace add MWDLH/kaleidosec
/plugin install kaleidosec --marketplace MWDLH/kaleidosec
```

装完**新开会话**生效。之后直接说你要做的事（"帮我渗透这个站" / "看看域控" / "跑个 nmap"），
模式会自动进入；打开带渗透特征的目录（名称含 pentest / engagement / red-team，或含 `.har` / `.burp` /
nmap 输出）也会自动进入。想固定某个目录、跨会话续跑，再在目录里放 `.kaleidosec`。

不想装插件，可用 [`examples/claude-hook/`](examples/claude-hook/) 手动接入；也可以把它当普通 skill 用：

```bash
git clone https://github.com/MWDLH/kaleidosec.git ~/.claude/skills/kaleidosec
```

## 宿主支持

Claude Code 支持插件与手动 hook 两种自动进入方式；作为普通 skill 时，Claude Code 与 Codex 均可用，
按描述触发。dsh 适配在后续版本。

## 项目结构

```text
kaleidosec/
|-- SKILL.md                    ← 唯一常驻协议（注入源）
|-- .claude-plugin/             ← 插件清单 + marketplace
|-- hooks/                      ← hooks.json + kaleido_gate.py（确定性注入）
|-- skills/kaleidosec/          ← 插件 skill 薄入口
|-- modes/                      ← STANDARD / DEEP 按需卡片
|-- references/                 ← 14 个领域与能力目录，每个都有路由入口
|-- scripts/                    ← 状态管理 + 预算/同步校验
|-- examples/claude-hook/       ← 手动 hook 兜底
|-- CHANGELOG.md / CONTRIBUTING.md / SECURITY.md / LICENSE
```
