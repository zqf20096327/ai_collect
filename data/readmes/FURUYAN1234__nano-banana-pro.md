An AI-assisted manga production and direction system that turns character references and a topic into a scenario, acting, camera directions and image instructions. Its focus is an interacting cast: consistent identities, actions and reactions grounded in the story, and wide shots with readable spatial depth. AI plans part of the direction between the author’s input and the final image; the author can review and edit each stage. / キャラクター資料と題材から、台本・演技・カメラ・画像用の指示を組み立てるAI漫画制作・演出支援システムです。多人数の人物整合性、物語を踏まえた働きかけと反応、ヒキを含む奥行きのある構図を重視します。作者の入力から画像化までの間にある演出判断の一部をAIが担い、作者は各工程を確認・編集できます。

OpenAI uses free page composition with four to eight panels; Gemini supports four panels in color or monochrome. Full-auto can continue through the stages, while post-generation quality review runs only when automatic image repair is ON. / OpenAIは自由配置の4～8コマ、Geminiはカラー・白黒とも4コマです。全自動で各工程を続ける使い方も選べ、生成後の品質検査は画像自動修正がONの場合だけ行います。

### Character text without reference images / 人物参照画像なしの人物設定

Background, prop and panorama images require at least one registered character; valid Story Maker character text counts, and character plus background images may be added together. Ordinary images are checked after recognition; panorama-only input is rejected before an API call. Removing all characters while backgrounds remain blocks the next stage until a character is restored. Style JSON alone is unaffected. / 背景・小物・360°背景の追加には登録人物が1人以上必要です。Story Makerの有効な人物テキストも人物として数え、人物画像と背景は同時追加できます。通常画像は認識後に検査し、360°背景だけの追加はAPI前に拒否します。人物をすべて削除して背景だけが残ると次工程を止め、人物追加で再開します。作風JSON単独は対象外です。

Drop reference images anywhere inside the blue dashed STEP1 frame, including over the shared six-line white character-information field. Per-image names and descriptions appear above the white character field; recognized images open these details automatically, while text-only or empty input keeps them collapsed. White fields marked editable let you adjust STEP1 information, STEP2 scenario and the final prompt in STEP4; rebuild STEP3 after scenario edits. The API dialog groups the application, OpenAI and Gemini PDF guides for use before connection. / STEP1の青い破線枠全体へ画像をドロップでき、基本6行の白い共通「人物情報」欄の上でも受け付けます。画像別の名前・説明は白い人物欄の上の「素材ごとの認識詳細」に表示し、認識済み画像があれば自動で開き、テキストのみ・空のときは閉じます。白い欄は人物情報だけに使います。「編集できます」と示す白い欄でSTEP1情報・STEP2台本・STEP4の最終プロンプトを編集でき、台本を変えたらSTEP3で作り直します。API入力画面では使い方・OpenAI・Geminiの3冊を同じグループから接続前にも読めます。

The main path is to drop character sheets anywhere inside STEP1’s blue dashed border, including the white character field. The whole border is highlighted while dragging files. Recognized characters and pasted Story Maker profiles share that same multiline field; per-image names and material details are available in a collapsible section above it. / 基本操作はキャラクターシート画像のドロップです。STEP1の青い破線枠内は、白い人物情報欄も含めて全体がドロップ範囲で、ドラッグ中は枠全体を強調します。画像の認識結果とStory Makerの人物情報は同じ複数行欄を使い、画像ごとの名前や素材の詳細は上の折りたたみから確認・編集できます。


Paste Story Maker’s STEP1 character information into the multiline character field, or drop a character-sheet image directly onto the same field. Text must use named character headings with Appearance and Clothing fields; scenarios belong in STEP2. Character Maker’s text copy is a sheet-design prompt, not character information for this field. / 複数行の人物設定欄にはStory MakerのSTEP1用人物情報を貼り付けるか、同じ欄へキャラクターシート画像を直接ドロップします。テキストは人物名の見出しと「外見:」「服装:」を含む形式が必要です。台本はSTEP2へ貼り付けます。キャラクターメーカーの「テキストCopy」はシート作成用の指示文なので、この欄には使いません。

You can paste usable character descriptions into STEP1 “人物情報” (`#reference-recognition-editor`) without uploading character images. The names, appearance and clothing are retained in API prompts and Web copy. Backgrounds and style examples do not count as character references; when character images are supplied, their identity remains the priority. Blank or insufficient settings still fail validation. / 人物画像をアップロードせず、STEP1「人物情報」（`#reference-recognition-editor`）へ十分な人物説明を貼り付けて制作できます。名前・外見・服装をAPI指示文とWebコピーへ残します。背景・描法見本は人物参照画像に数えず、人物画像がある場合はその同一性を優先します。空欄や不十分な設定は引き続き検査で拒否します。

For Story Maker integration, paste its STEP1 character information here and its scenario into STEP2 “生成されたシナリオ”, build the prompt in STEP3, then generate in STEP4. Story Maker outputs a scenario alone after a character sheet has actually been imported and its character registered; provide the same sheets for all cast members in this app. Without imported sheets, Story Maker generates separate character information and offers full, scenario-only and character-only copies. Image identity is not automatically compared between apps. / Story Makerとの連携では、STEP1用の人物情報をここへ、台本をSTEP2「生成されたシナリオ」へ貼り、STEP3で指示文を作ってSTEP4で画像化します。Story Makerでシート画像を読み込み人物登録した場合は台本だけを出し、漫画側にも全人物分の同じシートを読み込みます。未取り込み時だけ人物情報を追加生成し、全文・台本だけ・人物情報だけのコピーを使えます。両アプリの画像の同一性は自動照合しません。

Open Character Maker from STEP1 to prepare character sheets, or Story Maker from STEP2 to create a scenario. The outlined buttons explain the destination and return path and open a separate tab, preserving this page. The same links are available on the initial API connection screen. / STEP1のキャラクターメーカーボタンで人物シートを、STEP2のStory Makerボタンで台本を準備できます。枠線付きボタンには用途と戻し先を説明し、作業中の画面を残して別タブで開きます。初期のAPI接続画面からも同じリンクを使えます。

## Multipage production through MCP / MCPで複数ページを制作

The production skill also supports a single manga page. When a manga request leaves the method unspecified, Codex offers this MCP workflow first and asks once. An explicitly selected or already accepted method is reused. A one-page request stays one page, without adding a separate cover. / 制作スキルは1P漫画にも対応します。漫画の制作方法が未指定なら、このMCP方式を第一候補として一度確認します。指定済み・了承済みの方法は聞き直しません。1Pの依頼では、別の表紙を勝手に追加せず1ページで制作します。

The skill includes storytelling and revision guidance derived from Story Maker: reader expectations, motivation, setup and payoff, visible acting, and preserving successful drafts. It presents panel-by-panel proposals and uses the manga application's planning pipeline; Story Maker installation or extra provider calls are not required. / Story Makerの実装から抽出した、読者の期待、人物の動機、仕込みと回収、絵で伝わる演技、成立した案を保つ推敲の手順を同梱しています。コマごとのシナリオを提示し、漫画アプリの構成処理へつなぎます。Story Makerの導入や追加API呼び出しは不要です。

When image production is also requested, the scenario skill carries conditional composition checks into the handoff: place the principal body action before surrounding beats when suitable, distinguish its crossing silhouette from later actors, check leg→shoe→contact continuity, and correct material defects while retaining a strong layout. It imposes no fixed coordinates, cast, drawing style or per-page crossing quota. / 画像制作も依頼された場合の引継ぎでは、場面に適すれば主動作の身体を先に置いて周辺場面を組み、越境身体と別時点の人物を区別し、脚→靴→接触面を確認します。強い構図を保って実害のある箇所だけを直し、固定座標・人物・画風や毎ページの枠越えを課しません。

Silent actors and nonhuman opponents remain in the panel cast when their visible action or body is specified. ## Single-page design approach / 1ページ制作の設計方針

### AI handles intermediate direction decisions / 演出の中間工程をAIが担う

The author supplies references, a topic and any explicit directions. The workflow connects three kinds of decisions rather than requiring every panel to be specified separately. / 作者は資料、題材、必要な明示指定を渡します。次の三つの判断を制作工程でつなぎ、コマごとの細部を毎回すべて指定する負担を減らす設計です。

| Direction decision / 演出判断 | How the workflow handles it / 制作工程での扱い |
|---|---|
| A consistent multi-person cast / 多人数の描き分け | Carry appearance, clothes and identity from references into the scenario and drawing instructions; optional image QA checks material cast defects. / 資料の外見・衣装・人物対応を台本と描画指示へ引き継ぎ、任意の画像QAで重大な人物不具合を検査します。 |
| Acting through sequence and relationships / 出来事の順序と関係性を踏まえた演技 | Plan whose action prompts whose response, including gaze, posture and action phase. Documentary fact/timeline checks preserve source events, dates and causality. / 誰の働きかけが誰の反応につながるかを、視線・姿勢・動作段階とともに計画します。ドキュメンタリーでは資料の出来事・日時・因果も照合します。 |
| Wide shots and spatial direction / ヒキと空間演出 | Combine camera position, height, framing and lens cues with character action; organize foreground, middle ground, background and the focal subject. / 撮影位置・高さ・寄り引き・レンズ感を人物の動作と組み合わせ、前景・中景・背景と注視点を整理します。 |

These are implemented instructions and checks, not a guarantee that the model understands every relationship or renders it consistently. Timeline fidelity is distinct from natural acting, and the app does not provide persistent emotional or relationship state across an entire long-form series. Other manga tools also offer character references, story generation and automation; no exclusive-feature or comparative-quality claim is made here. / ここで説明するのは実装した指示と検査であり、モデルがすべての人間関係を理解し、一貫して描けるという保証ではありません。時系列の保持と自然な演技は別で、長編全体の感情・関係性を永続的に追跡する機能も提供していません。他の漫画ツールにも人物参照・ストーリー生成・自動化があり、機能の独占性や比較品質を主張するものではありません。

### One page as the production unit / 1ページを制作の単位にする

The app uses one manga page as its unit of story planning, direction and image generation. When automatic image repair is ON, quality review also runs per page. The aim is to concentrate these steps on a coherent story and readable visual detail within that page. / 本アプリでは、物語の構成、演出、画像生成を1ページ単位で組み立てます。画像自動修正がONの場合は品質確認もページ単位で行い、各工程をその1ページの物語のまとまりと、読み取れる絵の密度に集中させる方針です。

- **Story density / 物語の密度:** Give page space to events, choices and reactions that advance the story. Monologues, action scenes and quiet beats serve the story's pacing; adding pages or repeating similar beats is not a quality target. Panel-count and layout rules are described in [Panel layout](#panel-layout--コマ数とページ構成). / 出来事、人物の判断、相手の反応に必要な紙面を配分します。モノローグ、バトルシーン、静かな間も物語上の役割に応じて扱い、ページ数や類似場面の反復そのものを品質の指標にしません。コマ数と配置の具体的なルールは、[コマ数とページ構成](#panel-layout--コマ数とページ構成)で説明します。
- **An interacting cast / 複数人物の相互作用:** Use registered appearance, personality and relationships to guide the topic's scenario and each character's acting. When several people share a panel, plan whose action prompts whose response in the same scene. Cast size follows the story and available space. See [Story construction algorithm](#story-construction-algorithm--物語アルゴリズム) and [Visual direction and reading](#visual-direction-and-reading--演出と読みやすさ) for the acting and continuity rules. / 登録した外見、性格、人物間の関係を、題材のシナリオと各人物の演技へ反映するよう指示します。複数人が同じコマに登場する場合は、同じ場面で誰の働きかけが誰の反応につながるかを設計します。人数は物語と使える紙面に応じて扱います。演技と連続性の詳細は、[物語アルゴリズム](#story-construction-algorithm--物語アルゴリズム)と[演出と読みやすさ](#visual-direction-and-reading--演出と読みやすさ)を参照してください。
- **Page boundaries / ページの外枠:** Plan on an A4 portrait page and instruct the model to keep all four outer frame sides and corners inside the canvas with visible margins, unless full bleed is explicitly requested. Intentional panel-breaking effects remain available. Exact API canvas sizes and Web-copy differences are described in [API routes and settings](#api-routes-and-settings--api経路と設定). / A4縦の紙面を基準とし、明示した断ち切りを除き、外枠の四辺・四隅と余白を画像内に残すよう指示します。意図した人物の枠越え演出は利用できます。API出力の正確な画像サイズとWeb貼り付け時の違いは、[API経路と設定](#api-routes-and-settings--api経路と設定)で説明します。
- **Automatically constructed instructions / 指示文の自動構築:** AI builds the scenario and image instructions from character references and a topic. The normal workflow does not require hand-written YAML or other structured data; review and optional editing remain available in the [four-step workflow](#what-this-project-does--このプロジェクトでできること). / キャラクター資料と題材から、AIが台本と画像生成用の指示文を組み立てます。通常の制作手順でYAMLなどの構造化データを手書きする必要はなく、[4ステップの制作工程](#what-this-project-does--このプロジェクトでできること)で内容を確認し、必要に応じて編集できます。

The achievable cast size and detail depend on panel space, dialogue volume and the image model. These are design goals; inspect the generated image for the actual framing, character depiction and readability. / 実現できる人数と描写の細かさは、コマの広さ、台詞量、画像モデルの能力に依存します。これらは設計上の目標であり、実際の枠の収まり、人物描写、読みやすさは生成画像で確認してください。

### Story-led composition / 物語に合わせて配置する

Use the most effective visual moment to organize the page. Large and small panels, foreground/background contrast and intentional overlap should serve the action and reading order. Natural boundary adjustments and small proportional differences do not alone require regeneration. A foreground figure must be grounded in the source scene; a person shown inside a picture is distinct from a person physically present. / 最も効果的な見せ場を中心に、大コマと小コマ、前後の距離、意図した重なりを組みます。動作と読順が成立する自然な境界調整や小さな比率差だけで再生成しません。前景人物は元の場面に登場する人物とし、写真や画面の中の人物と、その場にいる人物を区別します。

## Art styles / コマごとの絵柄

Automatic style selection first considers composition, distance and depth, light and shadow, and detail density. Quiet scenes are not automatically assigned watercolor or sketch; suitable repeated styles and explicit style requests take priority. / 自動画風選択では、構図・距離と奥行き・明暗・描写密度から場面の強弱を考えます。静かな場面を自動的に水彩やスケッチへ割り当てず、内容に合う同じ画風の継続と明示指定を優先します。

The overall `Outfit` and clothing stated in scene/action directions take priority. Carry each person's clothing through the same scene even when later panels omit its description, while retaining explicit costume changes and panel-specific overrides. API and Web-copy routes share these instructions. Wardrobe continuity does not require freezing the camera, action, expression or per-panel style. It is an instruction rather than a guarantee of matching generated clothes; inspect the final image. / 衣装は、全体の `Outfit` と状況・動作に書かれた指定を優先します。同じ場面で後のコマに衣装の説明がなくても、その人物の衣装を引き継ぐよう指示します。明示された着替えやコマ限定の指定は保ちます。API用とWeb貼り付け用で共通の指示を使い、衣装の継続のためにカメラ、動作、表情、コマごとの絵柄を固定することは求めません。生成画像での衣装の一貫性を保証するものではないため、最終画像を確認してください。

In free input, write directions such as 'Panel 1 NORMAL, panel 2 POP, panel 3 watercolor, panel 4 GEKIGA.' Apply the same notation to the panels in four- to eight-panel mode. Numbers identify story panels, not style-menu choices. English style names also work. Each panel's `[EMOTION: ...]` records its style, so you can check or edit it before STEP3. / 自由入力に「1コマ目は通常、2コマ目はPOP、3コマ目は水彩、4コマ目は劇画」のように書けます。4〜8コマモードでも、作成するコマに合わせて同じ書き方を使います。数字は選択肢の番号ではなく、物語のコマ番号です。英語名でも指定できます。台本では各コマの `[EMOTION: ...]` に画風が記載されるので、STEP3へ進む前に確認・編集できます。

Monochrome NORMAL panels request fewer redundant hair strands, incidental fabric wrinkles and background micro-textures. Existing deep shadows are grouped into coherent black shapes, with white gaps around faces, hands and focal silhouettes. GEKIGA keeps its directional crosshatching; character identity, skin/material tone assignments, dialogue, camera and acting remain part of the same instruction. The finalized document is shared by API generation, Web copy and TXT export. Targeted repairs keep their local scope. / 白黒の通常コマでは、不要な髪の細線、服のしわ、背景の微細模様を整理する指示を加えています。深い影はまとまった黒ベタへ寄せ、顔や手、主役の輪郭の周囲に白い隙間を残します。劇画の方向性のあるカケアミ、人物の特徴、肌・素材のトーン、台詞、カメラ、演技は同じ指示文で保持します。確定した全文をAPI生成・Webコピー・TXT保存へ共通で渡し、部分修正は指定箇所の範囲を保ちます。

|---|---|---|
| Normal / 通常 | NORMAL | Everyday manga drawing based on the registered character references / 登録した人物資料の絵柄を基準にした、普段の漫画表現 |

GEKIGA does not require changing a calm face to a severe expression. Monochrome translates color characteristics into ink lines, black/white shapes and halftone dots. AI chooses unspecified panels to suit the topic and direction. Results vary, and small panels or distant faces may show weaker distinctions; inspect the image and specify necessary corrections. / 画風は顔・髪・服・小物・背景へ適用する指示です。人物の同一性や衣装、台詞、場面のカメラと演技は保ちます。劇画だから険しい表情にする、といった変更は求めません。白黒では色の特徴を墨線、白黒の面や網点へ置き換えます。指定しないコマは題材と演出に合わせてAIが選びます。生成にはばらつきがあり、小さなコマや遠い顔では描き分けが弱くなることもあるため、最終画像を見て必要な修正を指定してください。

POP requests printed color shapes and dots on faces too; watercolor requests transparent pigment layers on faces and hair; GEKIGA requests facial structure and intersecting pen lines. The Gemini four-panel and OpenAI free-composition routes share these character-rendering instructions. OpenAI free composition separates reference appearance data from each panel's drawing recipe: hair, skin, glasses and identifying facial features remain, while stylized eye size and painting follow the panel's medium. An explicit reference-style lock takes priority. / POPでは人物の顔にも印刷の色面と網点、水彩では顔・髪にも透明な顔料の重なり、劇画では顔の骨格と交差するペン線を指定します。Geminiの4コマとOpenAIの自由配置で共通の人物描画指示を使います。OpenAIの自由配置では参照シートの外見情報をコマの描画指示と分け、髪・肌・眼鏡・顔の識別点を残しながら、目の様式的な大きさや塗り方を各コマの画風に合わせます。参照絵柄を固定する設定では、その固定を優先します。

For OpenAI image generation, a built-in technique guide is attached automatically when a color or monochrome scenario includes POP, watercolor or GEKIGA. Custom-style and reference-style-preserving modes, including SeriousDocumentary, omit it, as do scenarios containing only NORMAL, SKETCH and CHIBI_GAG. For OpenAI Web generation, save `nano-panel-media.png` from STEP4 and attach it last, after all STEP1 source images. A guide does not guarantee style compliance; inspect the cast and rendering afterward. / OpenAI画像APIでは、カラー・白黒とも、POP・水彩・劇画を含む台本に組み込みの描法見本を自動添付します。見本は指定されたコマの描き方だけに使い、人物の同一性・衣装・ポーズ・構図・文字は写さない指示です。白黒では墨線・ハッチ・網点の描法を参照し、紙白と台本の肌・素材の割当トーンを優先します。見本の色や彩色のにじみは写しません。カスタム画風、参照絵柄を保持する設定（SeriousDocumentaryを含む）では添付しません。通常・スケッチ・ちびギャグだけの台本にも添付しません。OpenAI向けWeb貼り付けでは、STEP4に表示される見本を nano-panel-media.png として保存し、STEP1の元画像をすべて添付した後、最後に添付してください。描法見本があっても指定どおりの描写を保証するものではないため、生成後の人物と画風を確認してください。





Hand-ink cues use pressure variation, entry/lift, slight wobble and dry accents only in shadows/hatching. Selected media, readable faces/hands/text, camera and acting remain primary; watercolor/pencil are not forced into ink. / 墨の媒体では筆圧の太細・入り抜き・微小な揺らぎと、影やハッチ部分だけのかすれを加える指示です。各画風・顔や手と文字の判読性・カメラ・演技を保ち、水彩や鉛筆へ墨を強制しません。

## Visual direction and reading / 演出と読みやすさ

Sound effects are drawn as part of the manga artwork, outside speech balloons. The scenario can place motivated Japanese lettering beside movement, impacts and everyday sounds in any ending mode. The image generator renders it in the selected medium; the app does not overlay typed text afterward. Explicit silence or no-SFX instructions take priority, and dialogue, faces and action contacts remain readable. / 擬音は吹き出しの外に、絵の一部として描きます。どの結末でも、動き・衝撃・生活音に合う描き文字を台本で指定し、画像AIが各画風で描画します。生成後に文字を重ねる処理ではありません。無音・擬音なしの明示指定を優先し、台詞・顔・動作の接触点を隠さないよう指示します。

GEKIGA panels request exaggerated facial relief through dense multidirectional fine pen hatching: deep eye sockets, a projecting nose and carved cheek/jaw planes, including calm or smiling faces. Line density builds the shadows; solid black supports only local occlusions. Color sits under the pen drawing; monochrome remains black and white. Other panel styles retain their own rendering. This is a drawing instruction, not a guarantee; inspect the generated faces. / 劇画コマでは、目のくぼみ・鼻梁・頬骨・顎の彫りを強め、顔や首に細い斜線を何方向にも重ねる濃いカケアミを指定します。影は線の密度で作り、黒ベタは局所を締める補助に留めます。穏やかな顔や笑顔も描き込みを弱めず、年齢や表情は保ちます。カラーはペンの描線の下に着色し、白黒は無彩色を保ちます。他の画風には適用しません。指示どおりになる保証ではなく、生成後の顔を確認してください。

POP panels redraw faces, hair, clothes, props and backgrounds with extra-bold black contours, vivid opaque flat colors and clearly separated large Ben-Day dots. Monochrome uses bold black/white shapes and dots only in permitted shadow/material regions. Camera, acting, identity and dialogue stay intact; inspect the actual output. / POPでは顔・髪・服・小物・背景に極太の黒い輪郭、鮮烈で不透明な平面色、大粒で明瞭な網点を指定します。白黒では大胆な白黒面と、許可された影・素材面の網点へ置き換えます。カメラ・演技・同一性・台詞を保つ指示ですが、実際の出方は生成画像で確認してください。

**Story-led page composition / シナリオに合うページ構成**: STEP2 first chooses the most effective story moment, then compares distinct page structures in the same request. The last six accepted session scripts provide geometry-only comparison data. Story impact and legibility take priority; novelty only breaks ties between suitable alternatives. Explicit layouts and meaningful repetition remain valid. No extra layout API call or similarity-only regeneration is added. The comparison resets on reload or full reset. / STEP2はシナリオの動き・表情・間・オチから最も効果的な見せ場を選び、上下の横長大コマ、左右の縦長、中央の見せ場などを同じリクエスト内で比較します。この画面で採用した直近6作品の構図を参考にしますが、内容への効果と読順を優先します。同程度に適した案があるときに偏りを抑え、違う構図にするためだけに話を変えたり、人物を小さくしたりしません。明示された配置や物語に必要な反復は使えます。比較専用のAPI呼び出しや、構図の類似だけを理由とする再生成は追加しません。比較履歴は再読み込み・全設定リセットで消去されます。

**Page production flow / ページ制作の流れ**: OpenAI STEP2 creates a complete four- to eight-panel script; STEP3 preserves its panel count, order, dialogue, camera and art styles while preparing the image instructions. Large and small panels, tall frames and connected foreground actors are selected to support the story. Repeating a suitable layout is allowed and does not by itself trigger paid regeneration. The old four-strip slide switch is hidden; see [Panel layout](#panel-layout--コマ数とページ構成) for the current interface and MCP page counts. / OpenAIのSTEP2で4～8コマの台本を作り、STEP3でコマ数・順番・台詞・カメラ・画風を保った画像指示文へ変換します。大小のコマ、縦長の枠、一続きの前景人物などを物語に合わせて使います。適切な配置の反復は許容し、配置の重複だけで有料再生成しません。旧横長4段へのスライドスイッチは非表示です。現在の画面とMCPのコマ数は[コマ数とページ構成](#panel-layout--コマ数とページ構成)を参照してください。

STEP3 matches annotated character names to a unique registered alias before checking page foreground ownership. A full name and its canonical short form refer to one actor, so they do not create duplicate cast constraints. Missing, offscreen, quoted-only or ambiguous owners do not authorize a page foreground. / STEP3は括弧注記付きの人物名を、一意に対応する登録名と照合して前景の所有者を確認します。正式名とその基本名を同一人物として扱い、人数指定を二重に作りません。不在・画面外・引用内だけの名前や、対応が曖昧な人物ではページ前景を確定しません。

A connected page foreground retains its source scene’s medium across another panel. ## What this project does / このプロジェクトでできること

The application provides one continuous four-step workflow. / アプリは次の4ステップを一続きで実行します。

1. **Material recognition / 素材の認識:** Read character sheets, backgrounds and props, and extract their roles and traits. / 人物・背景・小物の参照画像から種類と特徴を抽出します。
2. **Scenario / シナリオ:** Generate the scenario in STEP2 and optionally strengthen its direction. OpenAI normally chooses four to eight panels from the story. / STEP2でシナリオを生成し、必要に応じて演出を強化します。通常のOpenAI制作では話に合う4～8コマを選びます。
3. **Prompt / プロンプト:** Build and directly edit the complete final prompt, including reference instructions, for both four-panel and 4–8-panel pages. / 4コマ・4～8コマとも、参照指示を含む最終プロンプトの全文を直接編集できます。
4. **Image / 画像:** Generate through Google Gemini or OpenAI; automatic image repair ON adds one review and at most one material correction. / Google GeminiまたはOpenAIで画像を生成します。画像自動修正ONの場合は総合検査1回と重大な破綻の修正を最大1回行います。

The distributed manga skill uses the work’s author credit, watermark preferences, and accurate AI-production disclosure. Social links are included when the user chooses them for the post. The optional, separately maintained personal preferences file is retained by the skill updater. / 配布スキルは作品ごとの作者表記・製品ウォーターマーク・実際のAI制作工程に従います。SNSには利用者が選んだリンクを添えます。導入先で別途作った個人設定ファイルはスキル更新時に引き継がれます。

The editable final prompt is the single document used by ordinary API generation, full/split copy, TXT and Web companion JSON. STEP3 adds reference and rendering instructions before editing; sending or exporting does not append, trim or rewrite them. API size limits still apply. Image-repair requests separately replace the reference manifest to identify the repair source. / 最終プロンプトは一つの編集欄です。STEP3で参照・描画指示まで組み立て、編集後の全文を通常のAPI生成・全体／分割コピー・TXT・Web版制作情報JSONへそのまま渡します。送信・保存時に自動追記・削除・書き換えをしません。API文字数上限は維持します。画像修正の依頼だけは、修正元画像を識別する参照説明を別途組み立てます。

For high-resolution OpenAI file uploads, the 32,000-character limit includes multipart line endings and reference descriptions. Automatic repair compacts only repeated application instructions and checks the outgoing length before sending. The approved camera, acting, dialogue and panel composition stay intact. / OpenAIへ高解像度画像をファイルで添付するときは、改行と参照説明を含めた送信時の文字数を32,000文字の上限と照合します。自動修正では、アプリが付ける重複指示を圧縮し、承認済みのカメラ・演技・台詞・構図を保持します。

Ordinary single-page API results also keep a metadata-bearing PNG and matching JSON together in a work folder. Names include the scenario title, `001ページ` and local date/time even when the title is hidden in the artwork. In a supported browser, explicitly choose a parent folder before generation; the app writes and reads back both files in a new work subfolder. This permission is reused for the current session. Without folder access, one ZIP containing the same folder and pair is downloaded; extract it to keep the files together. Both files use the same sanitized generation-time record, so later edits do not change that image's history. / 通常の1ページAPI生成も、制作情報入りPNGと同名JSONを作品フォルダーにまとめます。絵のタイトル表示をOFFにしていても、保存名には台本の作品名・`001ページ`・年月日時分秒を含めます。対応ブラウザーでは生成前に親フォルダーを選ぶと、その下の作品フォルダーへ両方を書き込み、読み戻して確認します。保存先の許可は現在のセッション中に再利用します。フォルダーへ直接保存できない場合は、同じフォルダーと2ファイルを含むZIPを1件ダウンロードするので、展開して保管してください。両ファイルには同じ安全化済みの生成時記録を使い、後からの編集で生成済み画像の記録を変えません。

In STEP4, **Simplify and stylize backgrounds** starts OFF. When ON, establishing, movement and clue scenes retain location landmarks in a few large shapes; reaction and conversation scenes can use bold color fields and geometric abstraction. The direction protects each panel's usual character detail, assigned art style, story props and lettering. The app uses the same editable final prompt for ordinary API generation and Web paste, with no mandatory image-edit stage. Turning it OFF restores the original prompt; a new STEP3 prompt starts OFF. Check the actual result for both background reduction and character detail. / STEP4の「背景を簡略化・デザイン化」は初期OFFです。ONでは場所紹介・移動・手掛かりのコマに必要な目印を少数の形で残し、反応や会話のコマでは大胆な色面・図形まで背景を抽象化するよう指定します。人物はコマ固有の絵柄と通常の描き込みを維持し、物語の道具・文字を保つ指示です。同じ編集可能な最終プロンプトを通常API生成・Web貼り付けに使い、生成後の画像編集は必須にしません。OFFで元の指示へ戻り、STEP3で新しく作るとOFFになります。生成後は背景の省略度と人物の細部を両方確認してください。

During four-panel A4 placement, if fitting the panels edge to edge would create unusually wide gaps, the app fits the whole source page instead and retains its panel spacing. / 4コマをA4に配置するとき、コマを横幅いっぱいに並べると間隔が広がりすぎる場合は、元ページ全体を収めてコマの間隔を保ちます。
