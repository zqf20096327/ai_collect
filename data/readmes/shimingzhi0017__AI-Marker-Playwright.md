# AI阅卷工作台

面向教师的本地可视化 AI 阅卷工作台。源码更新：**2026-11-12**；已发布的 Windows 便携包版本：**v2026.10.30**。本轮为源码更新，下载链接仍指向现有发布包。

从“开始阅卷”主流程出发，完成评分方案、模型配置、页面检查、自动评分、人工确认、历史追踪与结果导出。

[下载 Windows 便携版 ZIP](https://github.com/shimingzhi0017/AI-Marker-Playwright/releases/latest/download/AI-Marker-Playwright-portable.zip) · [查看 v2026.10.30 发布说明](https://github.com/shimingzhi0017/AI-Marker-Playwright/releases/tag/v2026.10.30)

## 当前版本亮点

- **开始阅卷主流程**：打开阅卷浏览器、检查页面、选择运行模式并开始处理。
- **评分方案**：支持题目、参考答案、图片和公式预览，可生成并编辑评分标准。
- **单双评与仲裁**：支持主评、复评、客观题逐项比对、主观题分差判断及仲裁。
- **人工确认**：评分结果、识别内容和评分理由可在提交前检查与修改。
- **任务与历史**：支持独立并发任务、暂停、历史详情以及 JSON、CSV、带图 HTML 导出。
- **Windows 便携版**：ZIP 内置运行所需组件，解压后双击“启动工作台.cmd”即可使用，无需单独安装 Node.js。

## 2026-11-12 本地源码调整

- 数学、物理、化学、生物统一宽松口径：答案正确且写有相关有效过程应给分，不因过程不完整判零；足以支持结论时给满分，否则按有效内容给部分分。
- 过程题完全只写答案不给过程分，答案分按已保存标准执行；客观题仍按答案判定。
- 阅卷方案新增“实际阅卷口径”：显式选择宽松、正常或严格并保存后，优先于旧模板的模式标记；结果详情记录本次口径。修正固定“严格阅卷老师”提示与宽松选择的冲突。
- 宽松先判断已有有效过程是否满足满分，不因省略重复说明暗扣分。模型明确采用不适用的严格标准扣分或报告错误口径时，有限重评一次；冲突仍未解决则转人工确认。
- 正常口径同样先认可充分的已写证据，刹车案例在正常、宽松下均满分；严格仅核对事先规定的细节。对比示例见[三档评分口径](docs/三档评分口径与示例.md)。
- 九学科分别补充等价表达、实验设计、文本证据、材料论证及图表等真实阅卷边界，同时用于标准生成和实际评分。
- 生成器与阅卷共用方案设置解析，按已保存标准确定学科、宽严和给分方式；完整共享规则只传递一次。界面可查看各科核验重点，打包自检逐科验证模板加载。
- 物理结合定义、方向与实际代入判断，认可刹车公式中代入负加速度等自洽表达；不按参考公式表面的加减号判错。
- 模型报告影响分数的规则缺失、冲突或资料不足时转人工确认，双评分数一致也不自动放行。
- 逐科说明见[九学科优化说明](docs/九学科提示词优化说明-2026-11-12.md)；可直接分享[九科 Markdown 压缩包](docs/prompt-exports/九学科提示词-按学科拆分.zip)，每科包含三种口径的完整提示词。
- 使用方式及覆盖范围见[理科宽松评分口径](理科宽松评分口径.md)。本地修改尚未发布为新便携包。

## 2026-11-11 源码更新

- 宽松、正常、严格采用不同的过程与细节要求，并同步用于评分标准生成和实际阅卷。物理与数学分别处理方程赋分、关键运算和错误依赖；解答题按小问汇总，填空逐空评分。
- 点击“下一步”会先保存方案或评分设置；等待保存期间的新编辑继续写入，失败保留输入并支持重试。
- 已确认提交的答卷分配永久本机编号，历史支持按编号和学生／平台标识定位，查看详情、复制定位信息并导出。网站分数的复核修改仍通过阅卷平台进行。
- 分项数量按实际评分标准核验；完整合法的明细可以修正冗余总分，并保留异常记录及独立复核要求。
- 调整任务摘要栏宽度、状态对齐与长文字换行，清理重复保存逻辑及启动时的历史重复写入。

启用新评分口径时，请重新生成、检查并保存评分标准；已有方案不自动改写。详细说明见[数学评分口径](数学评分口径说明.md)及[代码整理记录](代码整理记录-2026-11-11.md)。

## 快速开始

1. 下载便携版 ZIP，并先“全部解压”到普通文件夹。
2. 启动工作台，配置 AI 接口和阅卷方案。
3. 打开专用阅卷浏览器，登录并进入阅卷页面。
4. 点击“检查页面”，确认识别结果后开始阅卷。
5. 首次使用建议选择“人工确认”或“只填分”，确认网站流程稳定后再启用自动提交。

## 安装源码版

需要 Node.js 24 或更新的 LTS 版本：

```powershell
npm.cmd ci
npx playwright install chromium
npm.cmd run ui
```

Windows 也可以双击 `启动可视化.cmd`。详细步骤见[首次运行说明](首次运行说明.md)。

## 测试与验证

2026-11-12 九学科应用集成后的完整回归 **209 项通过，0 项失败**，包括九科三档规则传递、生成器与阅卷设置一致、共享规则不重复、自定义优先级及规则疑点阻止无人值守提交。九学科浏览器自检通过。此前运行与修复过程见[测试报告](测试报告.md)。完整回归建议使用 `node --test --test-concurrency=4 test/*.test.mjs`，以控制同时启动的浏览器数量。常用检查命令：

```powershell
npm.cmd test
npm.cmd run test:ui
npm.cmd run check:browser
```

自动测试使用本地模拟网页和模型服务，不会向真实平台提交分数。真实网站的登录、评分准确率和自动提交仍需在实际环境中逐平台验收。
