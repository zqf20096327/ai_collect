# Dome

<p align="center"><img src="dome/ui/static/logo.svg" width="420" alt="Dome: Find the ring. Find the room."></p>

> **Find the ring. Find the room.**

**Live:** **[dome.surf](https://dome.surf)**, a replay of the recorded real case with an Ask box that answers from
the case files.

<p align="center"><a href="https://youtu.be/n3xntLqfbcA"><img src="https://img.youtube.com/vi/n3xntLqfbcA/hqdefault.jpg" width="480" alt="Watch the Dome demo video on YouTube"></a><br>
<b><a href="https://youtu.be/n3xntLqfbcA">▶ Watch the demo video</a></b></p>

Dome is an investigation tool for trust and safety teams, anti-trafficking NGOs and police
trafficking units. Six agents under one LangChain **deepagents** supervisor pick out suspicious
social accounts, find the ring behind them, and narrow its photos down to the building, and the
room, where they were most likely taken. **Every output is a lead for human verification.**

**All data is synthetic.** No real accounts, people or phone numbers. Nothing is scraped.

**Ring A**: 12 posting accounts with a shared phone, a reworded ad script, reposted room photos
and three recruiters. Dome links them, draws the area, lists the buildings inside, matches the
photos to one building's scan, and explains a **High** lead.

## Run it

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pip install -r requirements-topo.txt && pip install "numpy>=2"   # optional topological scorer
pytest -q
```

Keys go in `.env` (copy `.env.example`; never commit it).

```bash
# Real case: real CoStar, Matterport and Vexcel data tools (needs the keys and the CoStar kit)
DOME_STUBS=0 DOME_MONEY=1 DOME_SPOTTER=1 python -m dome.supervisor --case real-a --data synth --scripted
python -m dome.agents.briefer --case real-a --score data/answer_key/answer_key.json

# No keys: stub data tools, same agents and guards
DOME_STUBS=1 python -m dome.supervisor --case synth-a --data synth --scripted

# UI, then open http://localhost:5001/?replay=demo-real-a
DOME_GLOBE=1 DOME_STEPS=1 DOME_ASK=1 python -m dome.ui.app --port 5001
```

Drop `--scripted` to let the LLM supervisor plan the steps. Outputs land in `case/<case_id>/`
(`rings.json`, `zones.json`, `candidates.json`, `matches.json`, `brief.json`, `summary.html`, the
audit trail `log.jsonl` and more). Replays in `samples/demo_cases/` are written only by
`scripts/record_demo_case.py`, which blanks every street address and refuses to save if one remains.
The globe flight and inside views need a local asset pack that is not in the repo.

| Flag | Effect |
|---|---|
| `DOME_STUBS` | `1` = stub data tools, `0` = real CoStar/Matterport/Vexcel |
| `DOME_MONEY` | money discovery on the synthetic ledger |
| `DOME_SPOTTER` | Spotter: accounts where 3+ signal kinds agree |
| `DOME_GLOBE` / `DOME_STEPS` / `DOME_ASK` | UI globe, "Show the work" drawer, Ask box |
| `DOME_GRAPH` | UI runs live through the LangGraph server instead of the replay |
| `DOME_MODEL` | LLM for the supervisor and Q&A (default `google_genai:gemini-3.5-flash`) |

Gemini answers are cached under `cache/gemini/`, so reruns make no new calls.

## How it works

| # | Agent | Writes | Answers |
|---|---|---|---|
| 0 | Spotter | `spotter.json` | Which accounts look suspicious? |
| 1 | Linker | `rings.json` | Which accounts are one ring, and why? |
| 2 | Zoner | `zones.json` | Where is the ring active, as an area? |
| 3 | Lister | `candidates.json` | Which buildings are inside and fit the photos? |
| 4 | Locator | `matches.json` | Which building's room and window view match? |
| 5 | Briefer | `brief.json` + `summary.html` | How strong is the lead and why? |

`dome/supervisor.py` is a `create_deep_agent` supervisor (deepagents) with three sub-agents reached
through the `task` tool: `ring-analyst` (Linker, Spotter, money), `place-analyst` (Zoner, Lister,
Locator) and `brief-writer` (Briefer, then the plain-language report). They can read the case folder
but every write is denied; the supervisor only plans, checks what is required next and delegates.
[LangSmith trace](https://smith.langchain.com/public/ccdd3df0-49d8-4328-8a80-38f9b21f29d8/r/01a1df42-57b6-70a8-844c-21601db2bdde)
of a real run reaching Building A, High 59.

**Numbers come from code; the AI writes words.** Every `run_*` tool validates its output against
`dome/schemas.py`. `write_brief_text` refuses any number not already in the brief, a street
address or a phone number, and never touches a tier or score. In the traced run the brief-writer's
first draft cited two numbers not in the lead; the tool refused it and the second draft passed.

**Rules enforced in code** (each logged to `log.jsonl` with its evidence):

| Condition | Action |
|---|---|
| Ring confidence R < 0.4 | stop after the Zoner; the brief reports the area only |
| No scan matches with P ≥ 0.4 | no building lead |
| No window in any photo | no window check; lead capped at Medium |

**High** needs P, W and R all ≥ 0.6; a strong room match that falls short elsewhere is **Medium**;
everything else is **Low**. Dome finds a building that matches the evidence; it does **not** prove
anyone is inside. It gives an area, never an address, and has no tool that contacts or publishes
anything.

### The Linker

1. **Keys per account:** contact (phones, including disguised ones, handles, payment tags), photo
   hashes, ad text (MinHash for copies, `all-MiniLM-L6-v2` for rewordings), interactions, place,
   timing, shared keywords, wallets, direct messages and payment patterns.
2. **Rare keys count more:** a key shared by many accounts counts for almost nothing.
3. **Two kinds make a link:** two accounts link only if they share two different kinds of key.
4. **Layers must agree:** a ring needs both a content key and a network key.
5. **Recruiters:** bios offering modelling or jobs, with most interactions going into the ring.

Ring confidence R = 1 − Π(1 − w_k) over the kinds the ring shares, capped at 0.95. Scored against
the hidden answer key (`python -m dome.eval --data synth --three-way`), which no agent opens:

| Layers | Precision | Recall | Hard negatives linked |
|---|---|---|---|
| content only | 0.99 | 1.00 | 2 |
| network only | 0.93 | 1.00 | 7 |
| both (Dome) | 1.00 | 1.00 | 0 |

Each layer alone links some hard negatives (friend group, rental hosts, busy motel, delivery
driver); requiring both keeps them out.

**Topological second opinion** (`dome/agents/topo.py`): the Linker's evidence becomes a
combinatorial complex (accounts as points, each shared key or event as a cell) and a UniGCN network
(TopoModelX) scores P(in a ring) per account. The rules still make every link. On synth it scores
precision 1.00, recall 1.00, AUC 0.90; train with `python -m dome.agents.topo --train`.

## LangChain

- **LangSmith:** set `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY` and `LANGSMITH_PROJECT=dome` in `.env`.
- **LangGraph Studio:** `pip install -e ".[studio]" && langgraph dev`, then open
  https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024 and pick the `dome` graph.
- **In code:**

```python
from dome.case import Case
from dome.supervisor import build_agent

agent = build_agent(Case.open("demo-a", scenario="ring_a", reset=True))
for chunk in agent.stream({"messages": [{"role": "user", "content": "Run the pipeline."}]}):
    print(chunk)
```
