# 不是而是

`bushiershi` 是一个对抗模型输出不良表达习惯的 Agent Skill。

它仅在明确调用 `$bushiershi` 时生效。

## 它从哪里来

我用了三年多 GPT。过去几个月，我把真实任务里反复纠正的表达问题整理成了这个 Skill。

[阅读「不是而是」的由来](ORIGIN.md)

## 人话的底层思路

- **人话感来自内容本身**：具体对象、真实动作、清楚的关系和有依据的判断，比模仿口语、短句或某种“像人”的语气更重要。
- **AI 味常常是一种写作动作**：问题不只出在某几个词，还出在模型怎样组织结论、制造完整感、补意义和结束一段话。
- **改得顺不能以失真为代价**：更短、更直接的文字，如果改变了事实、程度、归因或不确定性，只是更自信的误写。
- **只控制最终成稿**：这个 Skill 处理读者实际看到的文字，不承担 Agent 全部思维、协作和任务推进方式。

## 快速使用

### 一键安装

在希望使用该 Skill 的 Git 项目目录中执行：

```bash
npx skills add jinhanbuilds/bushiershi --skill bushiershi -y
```

该命令会把 Skill 安装到当前项目的 `.agents/skills/bushiershi`。

### 手动安装

不使用 Skills CLI 时，下载本仓库并在仓库根目录执行：

```bash
mkdir -p ~/.agents/skills
cp -R skills/bushiershi ~/.agents/skills/
```

如果你的客户端使用其他 Skills 目录，请把目标路径替换为对应位置。

### 调用

在请求中明确调用 `$bushiershi`：

```text
使用 $bushiershi 改写下面这段中文，保留原有事实、立场和不确定性：

<原文>
```

也可以从零生成：

```text
使用 $bushiershi，根据以下事实写一段面向用户的中文说明：

<事实与要求>
```

## 希望成稿做到什么

- **直接进入事情**：先写对象、答案或判断，不让分析计划和框架占据开头。
- **让具体的人和事做主语**：写清谁做了什么、发生了什么、结果怎样，避免用抽象名词代替真实动作。
- **让判断带着依据出现**：把事实、动作、数字或关系放在判断附近，不先宣布价值再寻找支撑。
- **让每个句段增加新内容**：新的事实、理由、区别、后果或决定才算推进，换词复述不算。
- **让结构跟着材料生长**：按照事实、因果、时间和读者自然会追问的问题组织内容，不预套固定框架。
- **事情讲完就停**：不为了形式完整重复前文、强行总结、升华或展望。

## 需要避免什么

这些不是禁词。判断一句话正在做什么，再决定如何修改。

- **虚设反面**：凭空制造一个错误理解，再用“不是……而是……”“看似……实则……”翻案抬高结论。真实对照存在时应当保留，并写清具体差异。
- **价值报幕**：用“真正重要”“值得关注”“这意味着”预先宣布价值，却没有直接写出变化和后果。
- **洞察路标**：用“更深一层”“还有一点”等提示代替事实、因果和问题之间的真实连接。
- **过程旁白**：把“我先梳理”“下面展开”“为了确保完整性”等分析和组织过程留在成稿里。
- **抽象动作**：用“优化、提升、赋能、闭环”代替具体主体、动作和结果。
- **同义重复**：在开头、正文和结尾换几种说法重复同一个判断，制造完整感。
- **强行升华**：从材料中没有的启示、行业影响和未来趋势里制造收尾。
- **磨平原话**：把用户已经说准、具体、有生命力的表达改成通用品牌文案。

## 必须保留什么

- 用户已经说准、具体、有生命力的原话；
- 已知事实，以及其中的数字、时间和真实差异；
- 用户原本的立场和判断方向；
- 程度、比较范围和归因；
- “计划、希望、预计、声称”等原有知识状态；
- 材料中真实存在的不确定性和有意保留的含混。

删空话、合并重复或调整句段时，也不能损伤这些内容。

## 不把它做成什么

- 不固定一组所谓的“人话句式”，避免用一套新模板替换旧模板。
- 不建立不断增长的禁词表。词语是否合适，要看它在当前句子里做了什么。
- 不为每个失败案例追加一条规则，避免形成一面越来越长的 Prompt 墙。
- 不把所有 Agent 协作、确认、状态和任务推进问题塞进写作 Skill。
- 不把个人偏好包装成普遍正确的中文写作标准。
- 不用规则数量证明 Skill 完整，只看它在真实成稿中改对了什么、改错了什么。
