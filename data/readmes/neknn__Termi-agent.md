# Termi

Autonomous AI assistant for Windows with a safe mode

[![CI](https://github.com/neknn/Termi-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/neknn/Termi-agent/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

## Termi: модульная версия

Раньше всё лежало в одном файле на ~9900 строк. Теперь это обычный проект: небольшой запускающий файл и пакет `termi_core` из 36 модулей, каждый отвечает за одну вещь.

> ⚠️ **Используйте на свой риск.** Termi управляет мышью, клавиатурой, окнами и файлами и выполняет команды по ответам нейросети. Нейросеть может ошибаться. Программа предоставляется «как есть», без гарантий (лицензия MIT).

## Важные предупреждения

- **Это не песочница.** Safe-режим и список опасных команд работают эвристически и не гарантируют защиту. Не запускайте Termi на компьютере с критичными данными без резервных копий. Для проверки рискованного можно использовать Windows Sandbox.
- **Не оставляйте без присмотра** режимы с мышью и клавиатурой (`visual`, `direct`): в любой момент вы должны успеть остановить работу.
- **Ключ API и расходы.** Запросы к моделям платные и идут за ваш счёт. Ключ API - это секрет: не публикуйте его и файл `config.json`, не отправляйте в Issues и не показывайте на скриншотах. Установите `keyring`, чтобы ключ хранился в хранилище Windows.
- **Инъекции в тексте.** Сайты и файлы могут содержать скрытые инструкции для ИИ. Подтверждайте действия, которые Termi просит разрешить после чтения внешнего содержимого (`/taint`).
- **Данные уходят провайдеру модели.** Текст задач, найденное в интернете и скриншоты экрана (если включены) отправляются выбранному провайдеру. Не показывайте ему личное и чужое.
- **Только для Windows** (основной сценарий) и только с вашим разрешением на своём компьютере. Не используйте Termi для чужих аккаунтов, обхода защит и других действий, нарушающих закон или правила сервисов.

## Запуск

```
python termi.py
```

или двойной щелчок по `Termi.bat` (ставит `requests`, `pyautogui`, `pillow`, `keyring`, только если их ещё нет, и запускает `termi.py`). Нужен Python 3.9+. Остальные необязательные пакеты: `pip install -r requirements.txt` или команда `/deps` внутри программы. В `requirements.txt` указаны нижние границы версий.

Если у вас был свой `Termi.bat` с именем старого скрипта, замените это имя на `termi.py`. Папки `termi.py` и `termi_core` должны лежать рядом.

## Самопроверка

```
python check.py
```

Запускайте после любой правки (своей или нейросети). Проверка за пару секунд ловит: синтаксические ошибки, имена без определения, **одно имя, определённое дважды** (так сломался `_merge`), одинаковые методы в разных частях `Agent` и модули, которые не импортируются. Последним шагом она запускает тесты из папки `tests` (классификатор опасных команд, конфиг, отмена запросов, защита от подмены инструкций). Настройки и ключи на вашем компьютере она не трогает: тесты работают во временной папке.

Тесты отдельно: `python -m unittest discover -s tests -v` (или `pytest`, см. `requirements-dev.txt`). На GitHub то же самое запускает `.github/workflows/ci.yml` на Windows и Linux, Python 3.9 и 3.12.

| `styles` | стили движений и личные настройки ИИ |

| `history` | постоянный системный промпт и история задач |
| `keys` | хранение ключей API |
| `llm` | запросы к моделям |
| `safety` | безопасный режим: опасные команды, системные пути |
| `websearch` | веб-поиск и загрузка страниц |
| `gui` | мышь, клавиатура, окна, UI Automation |
| `drawing` | шаблоны рисунков |

| `browser` | невидимый браузер (Playwright) |

| `agent_screen`, `agent_native`, `agent_files`, `agent_web`, `agent_input`, `agent_draw` | остальные действия `Agent` (скриншоты, native-цикл, файлы и команды, поиск и браузер, мышь и клавиатура, рисование) |
| `riskdata` | общие данные для оценки рисков |
| `uihub`, `filescan`, `urlcheck`, `winwatch`, `observer` | режим наблюдения: красное окно, приём файлов, анализ ссылок, буфер и процессы, сам наблюдатель |

| `cli` | запуск задач, обработка команд, `main()` |

## Правило, которое держит порядок

Модуль импортирует только модули **ниже** себя; циклов нет. Уровни (от нижнего к верхнему):

0. `common`, `riskdata`
1. `gui`, `logbook`, `safety`
2. `drawing`, `terminal`, `winwatch`
3. `agent_screen`, `browser`, `sandbox`, `styles`, `uihub`
4. `agent_files`, `agent_gate`, `agent_input`, `config`, `filescan`
5. `deps`, `history`, `keys`, `prompting`, `websearch`
6. `agent_web`, `llm`, `native`, `urlcheck`
7. `agent_draw`, `agent_native`, `cli_info`, `observer`
8. `agent`, `observe_cmds`
9. `jobs`, `cli_env`
10. `cli`

Если новой функции нужно что-то из верхнего модуля, не импортируйте вверх: перенесите функцию выше или передайте нужное параметром. `python check.py` сразу покажет цикл.

## Куда лезть, если…

- меняется поиск в интернете: `websearch.py`;
- нужно подправить защиту или добавить опасные шаблоны: `safety.py`;
- новое действие агента: нужный `agent_*.py` (метод `act_<имя>`) и список действий в `prompting.py`;
- новая команда `/что-то`: `cli.py` (`handle_command`) и реализация в подходящем модуле;
- уровни опасности и решение «пускать/спрашивать/блокировать»: `safety.py` (что считать опасным) и `agent_gate.py` (что делать);
- после правки `safety.py` добавьте случай в `tests/test_safety.py`: так обход, однажды закрытый, не вернётся;
- текст справки: `cli_info.py`.

## Работа с нейросетью

Давайте ей **один модуль** и эту карту, а не весь проект. После правки просите запустить `python check.py`. Так она физически не может задеть чужой код и запутаться.

## Что изменилось по сравнению с одним файлом

Логика та же: код каждой функции, класса и константы совпадает с исходным побайтно (сверено по AST: 555 из 558 единиц идентичны). Отличия:

1. **Исправлен баг:** в файле было две функции `_merge` (проверка безопасности и склейка результатов поиска). Вторая затирала первую, поэтому любая команда агента падала с `'tuple' object has no attribute 'items'`. Поисковая теперь называется `_rrf_merge`.
2. Защита «самого Termi» (`safety`) теперь охраняет `termi.py` и все файлы пакета, а не один скрипт; песочница (`sandbox`) монтирует папку проекта и запускает `termi.py`.
3. В `gui.py` для не-Windows добавлена заглушка `_send_unit = None` (вызывается только при `IS_WIN`), чтобы модули импортировались на любой системе.
4. Класс `Agent` разложен по mixin-классам (`ScreenMixin`, `NativeMixin`, `FilesMixin`, `WebMixin`, `InputMixin`, `DrawMixin`); методы и их поведение прежние.

## Как проверено

Сравнение вывода старого и нового вариантов на одинаковых сценариях (сессия из 40 команд, выполнение действий агента, классификатор команд, проверка ссылок, защита путей): результаты совпадают, кроме случайных фраз маскота. Проверял на Linux. На реальной Windows, с окнами Tk, `pyautogui`, песочницей и настоящими запросами к API, не запускал: при первом запуске гляньте, что работает ваш обычный сценарий, и если что-то не так, напишите, что именно выводится.

## Доработки версии 2.1 (ревизия безопасности и надёжности)

**Безопасность**

1. `safety.py`: команда проверяется в нескольких видах (как есть, без `^` и обратных кавычек, без кавычек внутри слов), поэтому `r^d`, `Remove-I""tem` и подобное больше не обходят шаблоны. `python -c`, `node -e` и другие встроенные интерпретаторы проверяются как скрипты (`shutil.rmtree`, `os.remove`, `open(...)` по системному пути) и всегда не ниже «caution». Добавлены шаблоны `-e/-ec/-enc`, `FromBase64String`, подстрок переменных `%x:~1,2%`. `_merge` стал публичным `merge_levels`.
2. **Защита от prompt injection** (`agent_gate.py`, команда `/taint on|off`, по умолчанию ВКЛ): после чтения веба, поиска, отчётов под-агентов и прикреплённых файлов задача считается «заражённой». Тогда запуск команд, запись исполняемых файлов (`.bat .ps1 .py .exe` и т. п.) и ввод текста с Enter требуют вашего подтверждения, даже если вы выключили `/confirm`. Под-агенты по-прежнему только читают сеть.
3. Ключи: `/key show full` спрашивает подтверждение; `Termi.bat` ставит `keyring`, чтобы ключ не лежал в `config.json` открытым текстом; на не-Windows файл настроек получает права 600.
4. Песочница: установщик Python внутри неё проверяется по цифровой подписи (должна быть Python Software Foundation), иначе установка останавливается.

**Надёжность**

5. `config.json` пишется атомарно (временный файл, `fsync`, `os.replace`), прошлая рабочая версия лежит в `config.json.bak`; повреждённый файл откладывается в `config.json.corrupt`, настройки берутся из копии.
6. Запросы к модели прерываются `/stop` и во время пауз между повторами (раньше можно было ждать больше минуты). Фоновые задачи получают независимую копию настроек. Канал `stdout` запущенных команд теперь закрывается.
7. 52 места с молчаливым `except Exception: pass` пишут ошибку в журнал (`log_exc`, не более 3 записей на место). Остальные `except` с `return`/`continue` оставлены как есть: там ошибка ожидаема.

**Структура**

8. Из `agent.py` вынесен `agent_gate.py`, из `cli.py` выбор среды вынесен в `cli_env.py`.
9. Версия Python везде 3.9+, в `requirements.txt` нижние границы версий, `Termi.bat` не переустанавливает пакеты при каждом запуске.

**Ограничения, которые остались**

- Защита по-прежнему эвристическая: чёрный список шаблонов нельзя считать полной изоляцией. Надёжнее всего: `/confirm on`, `/taint on`, `/safe on` и песочница.
- Тесты и самопроверка запускались на Linux. На Windows (в том числе Tk-окна, `pyautogui`, песочница, реальные запросы к API) их проверит CI или вы при первом запуске.
