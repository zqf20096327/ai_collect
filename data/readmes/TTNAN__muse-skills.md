不用从头读。直接 Ctrl+F 搜你正头疼的事，点开那条，把三句话术复制给 Muse 就行。

<summary><b>105. README 三秒留住人</b> —— README 写得像说明书，访客三秒划走，star 全是…</summary>

README 写得像说明书，访客三秒划走，star 全是误点的。

**三句话术，复制就用：**

1. 把 README 发给 Muse：「以第一次点进来的开发者视角重写，第一屏讲清这项目解决什么问题」。

2. 让它补上 30 秒快速上手，「复制粘贴就能跑起来的那种」。

3. 最后让它挑刺，「删掉三句正确的废话，告诉我访客看到第几行会关掉页面」。

**实话**：三步它都能自己干，你只管复制粘贴；但项目本身值不值得留人还得看你的代码，它写不出好项目。

<summary><b>106. issue 自动分类加回复草稿</b> —— issue 一攒几十条，bug 提问许愿混在一起，回都回…</summary>

**三句话术，复制就用：**

1. 把 issue 列表导出来发给 Muse：「分成 bug、提问、功能请求三类，每类按紧急程度排序」。

2. 让它给每条写回复草稿，「语气客气别啰嗦，bug 类的先要复现步骤」。

3. 你过一遍直接粘贴回复，省下分类的时间专心修 bug。

**实话**：它发不了评论，草稿得你亲手粘贴；列表也是你导出，它只管分类和写草稿。

**三句话术，复制就用：**

3. 存成 CHANGELOG.md，以后每次发版走同一套流程。

**实话**：commit 列表得你亲手丢；存文件和 push 也得你自己来。
