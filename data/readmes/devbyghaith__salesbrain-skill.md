# salesbrain-skill

**An Agent Skill that gives any AI agent evidence-graded sales judgment: every rule tagged study, data, practitioner or opinion, every number sourced, and the popular advice that research contradicts called out.**

![Demo: the skill turning a "can you do better on the price?" email into a reply that asks before it discounts](assets/demo.gif)

Works with Claude Code and any agent that reads the [agentskills.io](https://agentskills.io) format. Covers
discovery, objections, closing and negotiation, outreach, offer design and pricing, pitching and demos,
persuasion research, sales process and team, mindset. The skill is the judgment layer; it does not fetch
CRM data, enrich leads or send email.

## Install

One command, for Claude Code:

```bash
git clone https://github.com/devbyghaith/salesbrain-skill ~/.claude/skills/salesbrain-skill
```

Or as a plugin, from inside Claude Code 2.1.275 or later:

```
/plugin install salesbrain-skill --marketplace devbyghaith/salesbrain-skill
```


Then ask anything about a deal: *"The COO just replied that $48k is way more than they expected. Draft my
reply."* The skill fires on its own when the task is about winning, pricing or advancing a deal, and stays
silent on support replies, internal emails and landing-page copy.

Other agents: clone into `~/.agents/skills/salesbrain-skill`, or into `<repo>/.claude/skills/` for one
project. As a Claude Code plugin: `claude --plugin-dir ./salesbrain-skill`.

If the "AI Sales Team" plugin is also enabled, set its `sales-objections` skill to off so the two do not
compete on the same prompts.

## What it is built from

- 55 talks and interviews and 26 studies, ingested into a notes layer (transcripts, per-source notes,
  evidence grades) kept outside this repo.
- An evidence review that checked the corpus's claims against DOIs, replications and vendor datasets, and
  found 14 of 41 checked claims verified, 12 overstated, 4 misattributed, 2 failed replication, 9
  unverifiable. The failures are in `references/claims-audit.md` so the agent does not repeat them.
- Design rules from research on how skills change agent behaviour (progressive disclosure, delta-only
  content, Default/Exception conflict resolution, scripts with length caps). See `AUTHORING.md`.

## Layout

```
SKILL.md                 router, the rules the model gets wrong, guardrails (loaded on trigger)
references/              one file per situation family, opened on demand
  discovery.md  objections.md  closing.md  outreach.md  offer-positioning.md  pitching.md
  rapport.md  persuasion-psychology.md  personal-branding.md  sales-process-team.md  mindset.md
  benchmarks.md          every number: value, source, date, sample, evidence tag, caveat
  claims-audit.md        do-not-cite list and safe statements
  sources.md             source register with grades (generated by scripts/build_sources.py)
assets/                  output templates with the constraints baked in
evals/                   plugin-evaluation cases: five positive, three near-miss negatives
.claude-plugin/          manifest so the Claude Code plugin evaluator can run on this folder
AUTHORING.md             the rules every line must pass
```

## Evaluate

Run the suite with the no-skill baseline and a cost cap:

```bash
claude plugin eval . --ablation with-without --max-cost-usd 10 --output-dir /tmp/salesbrain-evals
```

Pass `--output-dir` outside the repo: the manifest declares the repo root as the skill path, and the evaluation
runner warns when results land inside it. Pass `--case` once per invocation; a second `--case` flag replaces
the first.

Read the `Δ` column. A positive case with `Δ` near zero and the `skill-fired` grader failing means the
description is not triggering on that phrasing. A negative case with the skill firing means the description
over-triggers. Confirm any change at the default three runs before trusting it. Results go to
`evals/results/` (ignored by git).

Cheap loop while editing one file:

```bash
claude plugin eval . --case objection-too-expensive --runs 1 --ablation none --output-dir /tmp/salesbrain-evals
```

## Update

1. Add sources to the notes layer, write their `notes.md`, grade them in `meta.yaml`.
2. Regenerate the register: `python3 -I scripts/build_sources.py <path to sources/>`.
3. Edit the topic file. Every new bullet must pass the gate in `AUTHORING.md` section 6.
4. Re-run the evaluation suite. Keep the case prompts frozen; add new cases for new failures.
