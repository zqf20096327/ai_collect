# DriveAgent

**从找文件，到完成整理。** 一个有审批、有回执、可恢复的网盘智能助手。

Desktop AI agent for cloud-drive search, document understanding and controlled file operations.

## 项目解决什么问题

文件名记不清、资料分散在多个目录时，传统网盘操作需要反复搜索、打开、比对和整理。DriveAgent 把这些步骤串成一条可追踪的任务：理解用户需求，取得内容依据，提出具体方案，经授权执行，再用实际回执说明完成了什么。

项目采用 **Electron + Python / AgentScope + Go Provider**。模型负责理解、规划与工具选择；权限、审批、路径检查、持久化、调用预算和完成核验由程序承担。当前是 Windows 优先的源码开发版（0.3.0），适合作为 AI Agent 产品与工程实践案例。

| 能力       | 用户可以做什么                                      | 程序约束                                                 |
| ---------- | --------------------------------------------------- | -------------------------------------------------------- |
| 内容检索   | 按文件名、正文关键词、语义、图片画面或 OCR 查找资料 | 展示实际返回的片段与范围；云端索引状态未知时保持未知     |
| 原文理解   | 按需读取 PDF、Word、表格、图片、文本及视频指定帧    | 保留页码、段落、单元格和时间点；读取大小与视觉上下文有界 |
| 文件整理   | 新建、复制、移动、重命名；通过文件工作台批量操作    | 源与目标核验、计划哈希、授权审批、执行前复核             |
| 上传与下载 | 在授权的本地文件夹和网盘之间传输                    | 限定目录、禁止覆盖；未知写入不自动重试                   |
| 任务恢复   | 继续等待审批的任务，核对中断时的操作结果            | SQLite 保存事实与状态；沿用 operation_id 对账            |

## 快速体验

仅体验界面回放需要 Node.js **22.12+** 和 npm：

```powershell
git clone https://github.com/bargino/DriveAgent.git
cd DriveAgent
npm ci
npm run demo
```

使用右下角的演示步骤按钮切换主页、检索、审批和完成状态。该入口只加载随仓库提供的合成快照，不启动 Python / Go 服务，也不使用已有账号配置。依赖安装需要网络，回放窗口阻止 HTTP(S) 请求。

运行完整应用还需要 Python 3.12、Go 1.25+ 和 uv，并在应用中配置模型及连接百度网盘。安装、授权、模型设置、平台限制和构建方式见 [开发指南](docs/DEVELOPMENT.md)。

## 系统架构

![DriveAgent 系统架构：Electron、AgentScope Harness、Go Provider 与持久化状态](docs/media/architecture.png)

实际调用链为 `Electron / IPC → FastAPI / Service / Runner → AgentScope → DrivePolicy / DriveTool → Go Provider`。这是单智能体加确定性业务流程的实现。

几个值得展开的工程点：

- **受控行动**：用户本轮意图与权限策略先限制可执行动作，Provider prepare 阶段生成具体计划；批准绑定计划哈希，执行前再次核对状态，防止「批准的方案」与「执行的方案」偏离。
- **恢复与幂等**：持久化会话、AgentState、审批和操作事实。恢复时使用原操作 ID 查询回执；无法确认的外部写入保留 `unknown`，不重复提交或宣称成功。
- **证据与交付**：文件引用绑定实际查询结果；正文、原文和视觉输入分别记录证据。完成摘要以回执为依据，区分回复结束、业务完成和结果不确定。
- **上下文与预算**：按任务启用工具分组，限制本轮总工具调用与检索次数。预算跨审批与重启保留；用户禁止取回原文件时，由程序在读取前拒绝。
- **运行版本**：记录源码和依赖摘要、工具契约、模型配置摘要与权限模式；恢复遇到版本变化时追加记录。模型出口记录实际图片哈希与媒体类型，便于核对视觉证据。
- **发布检查**：Python 全套测试生成带源码指纹的报告；打包入口拒绝缺失、失败或已过期的检查报告。

源码与完整时序见 [Agent + Harness 架构](docs/AGENT-HARNESS-ARCHITECTURE.md)，工具参数与结果约定见 [工具契约](docs/TOOL-CONTRACTS.md)，对照阿里云手册的检查见 [手册核查记录](docs/HANDBOOK-REVIEW-2026-11-13.md)。

## 评测与验证

**当前自动化验证（2026-11-13，Windows）**：Python **330 passed / 21 skipped**，Node 桌面与渲染器测试 **206 passed**，Go 测试与 `vet` 通过。Python 跳过项是 Linux / POSIX 宿主专用检查。模型在 HTTP 层由脚本模拟，Provider 使用内存环境；这些检查验证工程契约与回归行为。

JavaScript 与 Python 锁定依赖审计均未报告已知漏洞。本次未发布或验收新的安装包，也未重新进行当前版本的全量真实模型评测。

![2026-11-07 历史评测的前后对照及局限](docs/media/evaluation.png)

历史评测使用前后各 1,200 次任务：1,100 条合成 Provider 任务调用真实模型，另有 100 条真实网盘历史回归。严格口径 **82.00% → 91.00%**；统一复核口径 **86.83% → 95.67%**。真实回归通过率仅 **85% → 86%**，平均分 **94.15 → 92.41**。

这组成绩用于展示迭代方法与失败分析。合成实例共享模板，真实题已用于历史回归，独立人工校准尚未完成；评分规则变化不计为产品提升。完整口径、耗时、token、退步与剩余问题见 [1,200 条历史评测报告](docs/ENTERPRISE-1200-BENCHMARK-2026-11-07.md)。

## 适用范围

当前连接百度网盘和用户授权的本地文件夹；其他网盘、自建 RAG 和本地全量内容索引尚未实现。云端语义 / OCR 检索依赖远端已有处理结果，提交解析不代表索引完成。视频只读取指定画面，不转写音频。真实网盘接口的可用性取决于账号、远端服务和运行环境。

登录凭据与模型密钥保存在本地，模型配置使用 Electron safeStorage。连接外部模型和远端网盘的功能仍会按需访问相应服务，「本地保存状态」不等于全流程离线。公开仓库排除账号 profile、数据库、日志、模型配置和原始网盘评测数据。
