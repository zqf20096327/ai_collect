## 三分钟上手

| 步骤 | 做什么 |
|---|---|
| 1. 安装 | 到 [Releases](https://github.com/1210350468/wanjuan/releases/latest) 下载 `wanjuan-setup-<版本>.exe`（Windows）或对应架构的 `.dmg`（macOS）。安装包未做代码签名，系统提示未知发布者时按[安装说明](#下载与安装)放行。 |
| 2. 配模型 | 打开「设置 → AI 模型」，选服务商预设（DeepSeek、智谱、硅基流动等），填 API Key 和模型名，点「测试连接」。想零成本可以先装 [Ollama](#用-ollama-跑本地模型)。 |
| 3. 建作品 | 回书房点「新建作品」，起名、选保存位置。类型、总章数、每章字数在设定页填。 |
| 4. 写到定稿 | 按「设定 → 架构 → 蓝图 → 正文」四步走。每步都能让 AI 起草、由你确认；正文写完可以审稿、修稿、定稿。 |

首次打开时会有四步引导讲解模型、参考来源与写作顺序，之后在空书房点「30 秒上手」可以重看。

## 用万卷怎么赚钱

网文变现的路子就那么几条，差别在于产能与选题。万卷在每一段都能省下具体的时间。

| 路子 | 收入来源 | 万卷帮在哪 |
|---|---|---|
| **免费阅读平台分成** | 番茄、七猫等按阅读时长与广告分成，签约后有稿费 | 番茄书库按男频女频榜单看真实在榜作品，选题不靠猜；批量蓝图保证日更不断更 |
| **付费订阅分成** | 起点、晋江等按订阅、月票、打赏分成 | 章节蓝图先把每章的冲突与钩子写清楚，审稿报告按条给意见，质量稳定才好上架 |
| **全勤与保底** | 平台按日更字数发全勤奖，签约作者有保底 | 「批量创作」一次连写最多 10 章，日更字数不再靠熬夜堆 |
| **短剧与有声改编** | 版权方买断或按分成结算 | 蓝图里的悬念钩子就是改编方要的抓手；剧情伏笔页能一眼看清哪条线索埋在哪一章 |
| **代写与工作室接单** | 按千字计费接单，工作室批量出稿 | 导入客户原稿续写，按客户文风拆解仿写，一个作者同时推进多本 |
| **自媒体与盐选连载** | 公众号、知乎盐选等按篇或按订阅结算 | 拆解爆款结构反推蓝图，快速摸清一类题材的写法 |

一条可执行的起步路线：

1. 用「番茄书库 → 分类榜单」看两三个题材的榜单，挑一个在榜作品多、自己也能写的题材。
2. 点「帮我配一单」让软件按题材配三本，看一眼诊断（题材、规模、节奏），再点「AI 定方向」出手，生成新书设定。参考作品只提供题材与结构依据，人物、地名、情节都是新的。
3. 先写前十章试水：蓝图按 10 章一批生成，正文用批量创作连写，再逐章审稿修稿。
4. 拿前十章去平台投稿或直接连载，看追读数据再决定是否加更。数据不行就换题材重来，沉没成本只有十天。

能不能赚到钱取决于作品本身和平台规则。万卷提高的是产能与选题命中率，不对收益作任何承诺。AI 生成内容在各平台的政策不同，发布前请按目标平台的作者协议自行确认。

## 它能做什么

万卷按写一本小说的顺序工作：你是作者，它是书童。每一步的结果都存进作品，下一步接着用。AI 负责起草，每一步由你确认。

### 番茄书库：搜书选题与多书融合

按书名、关键词或书籍链接找番茄上的作品；也可以按男频女频的题材翻榜单，男频 19 个、女频 18 个分类，每个分类列出该题材榜单上的作品，带封面、简介、字数与连载状态。读的是公开的书籍详情页：封面、书名、作者、标签、简介、字数、状态与全部章节标题，章节正文不读取。

不想一本本挑，就点「帮我配一单」：软件按题材骨架、章节节奏和在读数，从当前结果里配三本，并说明它们的共同题材和各自带来的新卖点。勾选两到五本后，下面会给出这套组合的诊断——算哪个题材、要写多大（章数 × 每章字数）、标签重合多少、节奏比平台主流快还是慢，并给出一套 0 到 100 的评分：综合与题材集中、热度、追读、结构、节奏五项。每张候选卡片的右上角也直接标着这本书的综合分，挑之前就能横向比。也可以点「AI 帮我选」：把候选的标签、在读、规模、状态与评分交给模型，由它判断挑哪两三本、为什么这么挑、往哪个方向写；挑不出来就明确报错，不替你凑数。融合取向可以自己写，也可以点「AI 定方向」让模型出两条方向，点一条就填进去；书名同理，点「AI 起名」。选好保存位置、确认名称后点「融合并新建作品」：软件新建作品、按参考作品的中位规模写好总章数与每章字数，再让 AI 生成设定、架构与核心大纲。参考作品只提供题材与结构依据，融合结果不复刻其中的人物、地名与具体情节。

分数不是拍脑袋凑的权重，每一项都有对应做法：

| 分项 | 单本权重 | 整单权重 | 怎么算 | 依据 |
| --- | --- | --- | --- | --- |
| 热度 | 30% | 22% | `log10(在读人数)` 从 10³ 到 10⁷ 映入 0–100 | 网文在读是长尾分布，对数刻度才接近读者的体感 |
| 追读 | 20% | 16% | 每章在读先按 `(v·R + m·C)/(v+m)` 收缩，再取对数映入 0–100 | IMDb 加权评分：10 章 100 万在读不该吊打 1000 章 100 万 |
| 结构 | 25% | 20% | 完结 100；连载按章数给 20–90；数据缺失记 40 | 连载长度与完结状态决定这本书能参考多少 |
| 节奏 | 25% | 20% | `exp(−δ²/2σ²)`，δ 是每章字数相对 3000 字的对数距离，σ=0.5 | 高斯核相似度：偏离主流是平滑衰减，不是一刀切 |
| 题材集中 | — | 22% | 标签两两 Jaccard 的均值；低于 0.15 压到 45 分，高于 0.6 压到 55 分 | 集合内聚度：太散配不成一本，太像没有新意 |

整单的热度、追读、结构、节奏取各书的**中位数**，一两本拖后腿不会毁掉整单。收缩先验取 300 章、每章 300 人在读——这是「样本少就往平台均值拉」的常见做法，不是拟合出来的最优参数，胜在每一项都能解释给你听。

关键词检索用 Bing 的站内检索定位书号；检索服务不可用时自动退回榜单里书名匹配的作品，也可以直接粘贴书籍链接。

### 拆解、仿写、续写与改写

书房里的「小说拆解与仿写」可以导入一部 .txt、.md 或 .epub 小说，按章拆开，导入时选择用途。

- **拆解与仿写**：选「参考小说」，AI 拆解它的结构、提取文风、反推章节蓝图，生成仿写约束，供你后面写作时参考。参考小说只进知识库和拆解结果，不会混进你的正文。
- **导入原稿续写**：选「我的原稿」，你已经写好的章节按章节号导入为定稿，AI 续写后面的章节时会接着前文的人物和情节走。
- **段落续写**：正文里选中一段文字，点工具条上的「续写」，AI 接着这段往下写。
- **改写**：整章改写用「修稿」，写下你要改的方向，也可以勾选审稿意见，修稿结果按段落和原稿对比，由你逐段决定用哪一版。改一小段时，选中文字后用工具条上的润色、扩写或改成对话。

### 设定与架构：先把故事立起来

设定页写下类型、受众、写作语言、总章数和每章字数。架构页分四节：故事前提、角色名单、世界观、情节大纲。每一节都可以让 AI 生成，也可以自己写。四节都确认后，再进入章节蓝图。

角色名单和架构放在一起编辑。每个角色有基础设定、当前状态和关系图谱。角色卡可以粘贴或从文件导入。

### 章节蓝图：动笔前先想清楚每一章

蓝图页逐章列出规划。每章写清主角小目标、冲突与转折、悬念钩子和出场人物。蓝图可以由 AI 按章节范围分批生成，中断后可以接着生成。

主按钮是「写第 N 章」。旁边的小弹层只放这一次写作的选项：用哪个模型，要不要补一句作者指导。想连写几章，用「批量创作」，一次最多 10 章。

### 正文：写稿、审稿、修稿、定稿

正文单章视图把一章从待写带到定稿。AI 写出草稿后，你可以直接改，也可以让 AI 审稿。审稿报告列出每条意见，你逐条勾选或忽略，也可以加上自己的意见。修稿结果以差异给你逐段确认，不会直接覆盖原稿。确认无误后定稿。

写作时，AI 拿到的是这一章的蓝图、相关角色、世界观、前文摘要和上一章全文，而不是整本书的聊天记录。

正文编辑器支持 Tab 插入两个全角空格作为段首缩进。写一章的全过程可以只用键盘完成。

### 运行侧页：看清 AI 正在做什么

所有生成任务都在运行侧页里，分进行中、历史、诊断三页。写作时可以实时看到输出，随时取消。批量创作可以暂停。生成失败时，已经写出的文字会留成恢复候选，可以复制或放弃。

### 作品资料与版本：写长篇不丢线索

- **剧情与伏笔**：按章节看主线、支线和伏笔的进度，记下每条线索在哪一章埋设、推进或解决。
- **知识库**：导入参考资料（.txt、.md）。没有配置检索模型时，也能用本地全文检索。
- **版本历史**：每章的历次稿件都留着，可以和当前稿对比，也可以回退成一份新草稿。
- **导出与备份**：导出为合并 Markdown、分章 Markdown 或 TXT。可以把作品打包存到本机，或备份到你绑定的 WebDAV 云端。恢复时总是另存为一份新副本。

### 写作 Skill：导入你自己的写作规则

在设置的「写作 Skills」页，可以从本机选一个 Skill 文件夹或单个 SKILL.md，也可以填 GitHub 上的 Skill 地址，导入提示词型的写作 Skill，比如「去 AI 味」、某种文风或某类题材的写法。SKILL.md 引用的 references 文本会一并装入。安装前软件会先读取并展示内容，由你检查后再安装。装好后把它绑定到规划、写稿、审稿或修稿阶段，之后这一阶段的生成都会带上它。

点「Skill 超市」会自动扫描内置推荐来源，直接列出可安装的 Skill，并提供「一键装可安装的」；也可以贴一个 GitHub 仓库地址单独扫描，或者按关键字搜 GitHub 仓库再挑。仓库结果带简介、星标与最后更新时间，都是当场从 GitHub 读的。列表会标出每个 Skill 的阶段、语言、附带文本数量，以及不能安装的原因（依赖脚本、hook、子代理或合并后超过 64 KiB）。同一仓库里已安装的条目会直接标成已安装。

只支持自包含的 SKILL.md 提示词。脚本、hook、子代理和工具调用这类内容不会被安装，Skill 不能在你的电脑上执行代码。

### 深色主题与中英文界面

外观有浅色「米黄旧纸」和深色「灯下夜读」两套。界面支持中文和英文。作品的写作语言可以选中文或英文。

## 支持的模型与服务

万卷不提供模型，也不代管额度。你在设置里填上自己的服务地址、模型名和 API Key。软件支持三种调用方式：

- **OpenAI 兼容协议**：Chat Completions 接口兼容的服务都可以用。
- **Gemini 原生协议**：Google Gemini。
- **本机执行器（CLI）**：直接调用你已经登录的 `codex`、`gemini`、`claude` 这类命令行 agent。

设置里内置了这些服务商的预设：

| 服务商 | 协议 | 说明 |
| --- | --- | --- |
| DeepSeek | OpenAI 兼容 | 预设地址 `https://api.deepseek.com` |
| SiliconFlow（硅基流动） | OpenAI 兼容 | 预设地址 `https://api.siliconflow.cn/v1` |
| BigModel（智谱） | OpenAI 兼容 | 预设地址 `https://open.bigmodel.cn/api/paas/v4` |
| OpenAI | OpenAI 兼容 | 预设地址 `https://api.openai.com` |
| xAI（Grok） | OpenAI 兼容 | 预设地址 `https://api.x.ai/v1` |
| Google Gemini | Gemini 原生 | 预设地址 `https://generativelanguage.googleapis.com` |
| Ollama（本地） | OpenAI 兼容 | 模型跑在你自己的电脑上 |
| NovelAI | OpenAI 兼容 | 最小兼容支持，未用真实账号完整验证 |
| 本机执行器（CLI） | CLI | 调用你已经登录的 `codex`、`gemini`、`claude`，不需要 API Key |
| 自定义 | OpenAI 兼容 | 填任意兼容服务的地址 |

「自定义」只是在 OpenAI 兼容或 Gemini 原生协议里换地址、模型名和凭据，不是任意 HTTP 接口。Anthropic、Azure、KoboldAI 原生接口等需要单独的适配器，换个 URL 不能保证能用。

知识库的语义检索另需一个向量模型，在设置的「检索模型」里配置。

### 用订阅自带的 CLI 当执行器

除了填 API Key，也可以让万卷直接调用你已经登录的命令行 agent：订阅了 ChatGPT 就填 `codex`，有 Google 账号就填 `gemini`，用 Claude 就填 `claude`，这些工具走的是你自己的订阅额度，不用另外配 Key。

进到这一页不用自己查命令：软件会扫一遍 PATH（含 `~/.local/bin`、Homebrew、npm 全局目录这些图形启动时拿不到的目录），跑一次 `--version`，再看凭据文件在不在，把 `codex`、`gemini`、`claude`、`agy` 的「装没装、什么版本、登录没登录」直接列出来。已经登录的点「用这个」就把命令与参数填好；没登录的点「登录」，会在系统终端里打开 `codex login` 或 `claude`（在 Claude Code 里输入 `/login`），授权完切回应用会自动重新检测。

```text
设置 → AI 模型 → 新建 → 服务商：本机执行器（CLI）
执行器：  Codex / Gemini CLI / Claude Code / agy / 自定义
命令：    codex
参数：    exec {{prompt}}
```

<p align="center">
  <img src="docs/assets/readme/retro/settings-harness.png" alt="设置页的本机执行器：上面列出检测到的 Codex、Claude Code、agy 与它们的版本和登录状态，点「用这个」后自动填好命令 codex 与参数 exec {{prompt}}" width="100%" />
</p>

检测只读：凭据文件只判断存在与大小，不读取内容，也不会上传。登录交给系统终端，应用本身不接触 token。
参数里写 `{{prompt}}` 表示把提示词放在那个位置；不写就让提示词从标准输入送进去。执行器没有 system 角色，提示词按消息顺序拼成一段。它不返回 token 用量，所以正文生成的用量统计会缺这一段，适合选题、起名、定方向这类小任务。

### 用 Ollama 跑本地模型

```text
服务商：   Ollama（本地）或自定义
协议：     OpenAI 兼容
Base URL： http://127.0.0.1:11434/v1
API Key：  可以留空；界面要求时填任意占位值
模型：     你的 Ollama 模型名，例如 qwen3:14b
```

向量模型也用 `/v1` 地址。不要填 `http://127.0.0.1:11434/api`，那是 Ollama 的原生接口。

## 下载与安装

安装包发布在本仓库的 [Releases](https://github.com/1210350468/wanjuan/releases/latest)。

### Windows x64

```text
wanjuan-setup-<版本号>.exe
```

1. 运行安装程序。升级时安装程序只更新应用本身，不会删除作品、角色卡或设置。重要作品仍建议先备份。
2. 安装后，应用可以在「设置 → 关于与更新」里检查更新。发现新版本时先提示你，你点「下载更新」后才开始下载，下载完再选择立即重启更新或稍后。
3. 旧版便携 ZIP 不能自动获得更新器，需要手动安装一次正式安装包。

当前安装程序未进行代码签名。Windows 可能提示未知发布者。请确认下载页面是本项目的官方 GitHub Release 后再继续。

### macOS（Apple Silicon 与 Intel）

```text
wanjuan-mac-arm64-<版本号>-installer.dmg
wanjuan-mac-x64-<版本号>-installer.dmg
```

1. `arm64` 适用于 Apple Silicon Mac（M1、M2、M3、M4 等）。`x64` 适用于 Intel Mac。
2. 把 DMG 里的应用拖进「应用程序」文件夹后启动。应用会提示新版本，但不会在 macOS 上自动下载或替换程序。更新时打开官方 Release 页面，手动下载对应架构的安装包。
3. 两个安装包均为 ad-hoc 签名，且均未使用 Developer ID 签名或公证。Gatekeeper 阻止打开时，先确认来源是本项目的官方 GitHub Release，再在 Finder 里按住 Control 点按应用并选择「打开」，或在「系统设置 → 隐私与安全性」里允许打开。

## 数据与隐私

| 数据或行为 | 存放位置或去向 |
| --- | --- |
| 作品、角色、蓝图、草稿和定稿 | 你的作品文件夹和本地 SQLite 数据库。 |
| 生成失败的恢复候选 | 只存在当前作品的本地数据库里，不会自动变成草稿或定稿。 |
| 导入的参考资料 | 留在本地作品里，除非你把它发给云端模型。 |
| 本地模型请求 | 发给你配置的本机或局域网推理服务。 |
| 云端模型请求 | 提示词和上下文发给你选择的服务商。 |
| 模型配置与 API Key | 保存在本机应用数据目录的 `ai-novel-writer` 文件夹里（Windows 为 `%APPDATA%\ai-novel-writer`，macOS 为 `~/Library/Application Support/ai-novel-writer`）。请保护好系统账户，不要分享这个文件夹。 |
| 应用偏好 | 与模型配置在同一个文件夹里。 |

早期版本把配置存在 `~/.vela`。新版本启动时会把它复制到上面的文件夹，原目录不改动。

软件本身不提供模型账号、云端生成服务或运营消息推送。联网检查更新只读取公开的 GitHub Release。

## 常见问题

**万卷免费吗？**

免费。软件以 GPL-3.0 协议开源。调用云端模型产生的费用由你和模型服务商结算，与本软件无关。用 Ollama 跑本地模型则不需要付费给任何服务商。

**用万卷写的小说，版权归谁？**

归你。软件不对作品主张任何权利，也不会把你的作品上传到任何地方。用 AI 起草再自己修改的部分同样归你，具体以你发布平台的作者协议为准。

**需要什么模型？**

任何兼容 OpenAI Chat Completions 接口的模型都可以接，Google Gemini 走原生协议。设置里有 DeepSeek、SiliconFlow、智谱、OpenAI、xAI、Gemini、Ollama 和 NovelAI 的预设。生成质量取决于你选的模型，软件不对模型输出质量作保证。

**作品数据存在哪里？**

存在你自己的电脑上：作品文件夹加一个本地 SQLite 数据库。只有你发起生成时，相关的提示词、作品设定和上下文才会发给你配置的模型服务。

**能写多长的小说？**

总章数由你在设定里填，没有固定上限。写每一章时，AI 拿到的是这一章的蓝图、相关角色、世界观、前文摘要和上一章全文，所以不需要把整本书塞进一次对话。批量创作一次最多连写 10 章，可以多次接着写。

**支持英文写作吗？**

支持。界面有中文和英文两种，作品的写作语言也可以选中文或英文。

**旧版本的项目怎么升级到 1.4.1？**

已经在用旧版本的用户可以直接用应用内更新升级（macOS 需要手动下载新安装包）。升级不改动作品数据，旧的外观偏好会自动迁移成浅色或深色。旧版本的项目如果要转成新格式，在书房点「导入」，选择「导入旧项目副本」。导入会生成一份新副本，原项目保持不动。

**能导入 Skill 吗？比如去 AI 味。**

可以。在设置的「写作 Skills」页选择本机的 Skill 文件夹或 SKILL.md，或填 GitHub 上的 Skill 地址，检查内容后安装，再绑定到写稿或修稿等阶段。只支持提示词型的 SKILL.md，不会安装或执行脚本。

**助手聊天去哪了？**

当前界面暂时隐藏了助手聊天入口，以后会单独重新开放。写作、审稿、修稿等功能不受影响。

**Windows 或 macOS 提示安装包不安全怎么办？**

Windows 安装包未签名，Mac 安装包只有 ad-hoc 签名、没有经过 Apple 公证，所以系统会提示。确认安装包来自本项目的官方 GitHub Release 后，按上面「下载与安装」的步骤允许打开。
