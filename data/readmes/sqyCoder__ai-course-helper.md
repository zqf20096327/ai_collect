## ⚠️ 请先读这一节

**本项目仅用于浏览器扩展技术与 Web 自动化的学习、研究和自测**——具体来说，是研究「如何在一个结构复杂、带反自动化检测的多 iframe 页面里做可靠的 DOM 自动化」。

使用前请务必理解以下几点：

1. **它可能违反你所用平台的服务条款。** 自动播放、改变播放速度、自动答题，在这类平台通常都被明确列为异常行为，可能触发**成绩作废、课程清零、账号封禁**。
2. **不要在有真实学分、绩点、毕业影响的课程上使用。** 这不是「小心一点就没事」的问题，是「一旦被判定就没有申诉空间」的问题。
3. **不要用它代替学习。** 视频看过不等于学过，答案填对不等于会做。
4. **作者不提供任何「包过」「代刷」服务**，也不对使用后果承担任何责任。
5. **如果学校或平台明确禁止此类工具，请立即停止使用并卸载。**

> 如果你的目的只是「不想被无意义的进度条绑住」，那请先看清楚：**真正有价值的是习题本身**。本项目的解题助手会给出答案，但不会替你理解它。

## 它能做什么

| 功能 | 说明 |
| --- | --- |
| **视频助手** | 自动播放章节内的视频类任务点，可设倍速，自动处理播放中弹出的题目，播完自动进入下一节 |
| **解题助手** | 识别测验 / 作业页的每一道题，求解并自动填充；学习页内嵌测验可选自动暂存，独立测验页**只填不提交** |

**视频助手完全不需要任何模型** —— 它是纯本地 DOM 操作（点播放、设倍速、跳下一节），装完就能用。

解题引擎是**可插拔**的，五种来源任选：

| 来源 | 谁出算力 | 装上能用吗 | 花费 |
| --- | --- | --- | --- |
| **网页版大模型**（`web`，默认） | 你自己已登录的网页版对话站点 | ✅ 零配置，登录一下就能用 | **0** |
| **答题中转**（`relay`） | 你自建的本地中转服务（见 `server/`） | ✅ 零配置，填个地址就行 | 你的 Key，架一次全员共用 |
| **仅本地题库**（`bank`） | 本地 JSON，不联网 | ✅ 能装，但只有题库里已有的题能答 | 0 |
| **自填大模型**（`llm`） | 任意 OpenAI 兼容接口（可指向本机 Ollama） | ❌ 每人得自己配 | 本机离线免费；云端按量计费 |
| **原插件服务器**（`origin`） | 第三方商业服务 | ❌ 每人得自己买权益 | 没权益反而更贵 |

外加一层**本地题库**：同一道题只解一次，之后秒答、零花费；支持导出 / 导入与同学合并。

> **为什么默认是网页版？** 因为默认值必须是「装完不用填任何 Key 就能跑」的那个。
> 网页版模式用**你自己已登录的账号**作答，免费、不需要 API Key。代价是每题 8~20 秒，偶尔会撞上限流。

## 一、安装

本项目**没有依赖、不需要构建**，直接加载源码目录即可。

**Chrome**

1. 地址栏输入 `chrome://extensions` 回车
2. 右上角打开 **开发者模式**
3. 点左上角 **加载已解压的扩展程序**，选择本目录（含 `manifest.json` 的那一层）
4. 要求 **Chrome 111+**（MAIN world content script 需要）

**Edge**

1. 地址栏输入 `edge://extensions` 回车
2. **左侧栏最下方**打开 **开发人员模式**（Edge 把它放在左边，不在右上角）
3. 点上方 **加载解压缩的扩展**，选到含 `manifest.json` 的那一层，不要选它的上级目录
4. 要求 **Edge 111+**（同为 Chromium 内核，现版本都远超要求）
5. 加载后点地址栏右侧的 **扩展** 图标（拼图块），把「网课助手·复刻版」**固定**到工具栏

> 如果公司或学校通过组策略锁了扩展安装，会看到「已由组织管理」的提示，那就需要换个人设备。

## 二、快速开始

### 1. 免费方案：网页版大模型（默认）

**这是默认设置，装完不用配任何东西。**

原理：扩展在后台开一个对话站点标签页，**用你自己在浏览器里已经登录的账号**，把题目打进去、把答案抠回来。不碰 API、不填 Key、不花钱。

**第一次用：**

1. 装好扩展 → 打开任一课程的**章节学习页**
2. 页面右上角出现蓝色面板 → 把「**视频助手 / 开启**」打到**开** —— 它自己就开始跑了
3. 遇到题目时，扩展会在后台开一个对话标签页
   - **没登录过** → 那个标签页会被自动**切到前台**，面板上提示你先登录，登录完回课程页重开一次即可
   - **登录过后** → 全自动，你继续干别的（标签页在后台，不抢焦点）
4. 想验证通道是否正常：设置页 → **测试网页版通道**

**这个标签页有两个「不要」：**

- ❌ **不要关掉它** —— 关了这道题就失败（下一题会重开一个）
- ❌ **不要在它里面手动提问 / 切会话** —— 扩展靠固定位置读答案，你插一脚就会读错

> 面板里的「立即执行本页任务」只是手动重跑一次用的。

**视频助手不需要任何 Key、任何服务**，因为它做的全是对页面本身的操作：

- 找到任务 iframe 里的视频任务点，逐个播放
- 设倍速并**每秒重申一次**（页面自己会偷偷写回 1x）
- **反检测**：在 MAIN world 吞掉页面注册的 `ratechange` / `seeked` / `seeking` 监听器
- 播放弹题自动作答（需要配置解题引擎）
- 播完点「下一节」继续

> 只要视频助手，那到此为止就够了 —— 后面全是给解题助手准备的。

### 2. 网页版模式的物理限制

网页版模式**能用、免费**，但它是在「自动化一个供人使用的网页」，所以有几条绕不开的限制：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 每题要 **8~20 秒** | 每个问题都要开新对话、等它想完 | 想快就架中转，一道题 0.3~0.7 秒 |
| 提示**「消息发送频繁」** | 免费网页版有静默限流 | 等一会儿再点「立即执行」；或改用中转 |
| 弹出**人机验证** | 登录态过期 / 请求太密 | 切到那个标签页手动点一下，然后继续 |
| 某题**答案不对** | 网页版模型也会答错 | 扩展会优先查本地题库，用久了命中率上来自动规避 |
| 对话站点**前端改版** | 官方更新了页面结构 | 需要更新 `src/content/deepseek.js` 里的选择器 |

> ⚠ 自动化操作网页可能违反其服务条款，有**封号风险**，请自行判断。
> 想彻底避开这个风险，用本机 Ollama —— 完全离线、没有条款问题。

### 3. 想更稳？自建一次答题中转

**这是让「下载即用、同学零配置、又快又稳」同时成立的办法。**

原因：商业版插件装完就能答题，是因为题目截图发到了**他们自己的服务器**，答案由他们的算力算。扩展包里没有「答案从哪来」这段——那是别人花钱养的算力，物理上掏不出来。
所以本地复刻只有一条路：**你自己扮演那个角色**。

`server/answer-relay.mjs` 就是这个角色的实现：**单文件、零依赖、只用 Node 标准库**。
为了少让你敲命令，`server/` 里配了几个双击就能跑的脚本。

| 什么时候 | 双击 | 它干什么 |
| --- | --- | --- |
| 第一次架中转 | `server\启动中转.bat` | 第一次跑带你选上游并填 Key → 验 Key / 拉起模型 → 尝试放行防火墙 8787 → 探测局域网 IP → 生成口令并存回配置 → 打印「该填进扩展的两行」→ 启动服务 |
| 要发给同学（先做一次） | `server\放行防火墙.bat` | 弹一次 UAC 提权，放行入站 TCP 8787。**不放行同学会一直连不上** |
| 要发给同学 | `server\打包给同学.bat` | 复制干净源码到临时目录（不动你的源文件）→ 自动改写常量 → 语法自检 + 全部自测 → **删掉整个 `server` 目录并扫一遍有没有泄漏 Key** → 打出零配置 zip |
| 要存档 / 发布 | `server\pack-neutral.ps1` | 打**中性包**：干净源码、默认网页版通道、不含你的地址口令 |

流程就是：双击第一个 → 把它打印的**地址**和**口令**填进扩展设置页的「答题中转」→ 点「测试中转」。自己这份就通了。要发人时再双击后两个。

> ⚠ **两种上游都要求你自己的电脑开着**：模型在云端或本机是一回事，**中转进程跑在你电脑上**是另一回事。
> 想让同学在你关机时也能答题，只能把 `server/` 整个拷到一台常开的机器或云服务器上（见 [`server/README.md`](server/README.md)）。

#### 手工跑（不想用脚本时）

```bash
cd server

# 最少一行就能跑（纯题库模式，不调模型）
node answer-relay.mjs

# 有模型才真正能答题（以 DeepSeek 为例）
UPSTREAM_BASE=https://api.deepseek.com/v1 \
UPSTREAM_KEY=sk-你的key \
UPSTREAM_MODEL=deepseek-chat \
RELAY_TOKEN=和同学约好的口令 \
node answer-relay.mjs
```

### 4. 完全离线：本机 Ollama

设置页 → 答题引擎 → 预设按钮「本机 Ollama · 纯文字」，点一下即填好。

需要先在本机跑起来：

```bash
ollama pull qwen2.5:7b
ollama serve
```

零花费、零条款风险，代价是首次出题要把模型加载进显存（十几秒到一分钟，之后快很多）。

### 5. 本地题库（强烈建议打开）

默认已开启。命中题库的题**完全不请求引擎**——零花费、零等待。

用久了命中率会明显上升（同一门课的测验题复用率很高）。设置页可以：

- 看统计：条数 / 命中率 / 因缓存省下的引擎调用次数
- 导出 JSON，和同学合并（合并时以导入的答案为准）
- 清空

### 7. 独立测验页（考试 / 作业）

这类平台通常有两套答题页面，本扩展两套都支持：

| 页面 | 题目容器 |
| --- | --- |
| **学习页内嵌测验** | 任务 iframe → `#frame_content` → `#ZyBottom` 内的 `.singleQuesId` |
| **独立考试 / 作业页** | 顶层 `document` 的 `.questionLi`，序号表在 `#topicNumberScroll` |

打开独立测验页后，在面板点「解题助手」开启（或点「立即执行」）即可逐题求解并**直接填充**。

> 独立测验页**只填不提交** —— 填充完你确认无误，再点页面上的提交按钮。
> 试卷查看页不做自动作答。

| | 自动填充答案 | 开 | 关掉只求解、不填 |

| 答题引擎 | 答案来源 | **网页版** | `web` 网页版（默认）｜`relay` 答题中转｜`bank` 仅题库｜`llm` 自填大模型｜`origin` 原插件服务器 |
| | 等它答完的最长秒数 | 180000 | 默认 3 分钟，本机模型冷启动需要 |
| | 中转地址 + 口令 | 空 | 选 `relay` 时填，例如 `http://192.168.1.10:8787/solve` |

## 四、工作原理

1. **任务扫描**（MAIN world）遍历页面上的 `iframe` 与 `.blockquote-wrap`，凡是模块化任务点或「展开式测验块」都算一个任务点，算好 `data-dx-task-id` 后 `postMessage` 给内容脚本。
2. **内容脚本**把任务归一化为 `video / audio / pdf / work / text`，按顺序排队执行。
3. **本地题库先查**：每道题先按「题号 → 题干+选项哈希 → 图片哈希」派生 key 查题库；命中就直接用（**不请求任何引擎**），未命中才走引擎，拿到答案后自动入库——所以用得越久越省。
4. **未命中时按「答案来源」分派**：`web` → `relay` → `llm` → `origin` → `bank`。都没有可用配置时返回 `errNo -100`，面板只提示一次然后跳过该题，**不会刷屏报错**。
5. **网页版通道**：后台开 / 复用一个对话站点标签页 → 用 React 受控赋值把题目打进 `textarea` → 点发送 → 轮询**新出现的**回答元素（用元素身份而非元素个数判断，避免把上一题的答案当成本题）→ 抠出文本返回。**每道题开一个新会话**，批量题目会合并成一条提示词一次问完，减少限流。
6. **视频类任务**：定位任务 iframe 里的 `<video>`，设 `playbackRate` 并每秒重申，监听 `ended`；遇到弹题就求解后勾选提交。**同一道弹题连续 3 次解不掉就放弃并继续播放**，避免卡死。
7. **学习页内嵌测验**：进入 `#frame_content` 的 `#ZyBottom`，逐题取题干 / 选项 / 题型，需要时滚动到题目并截图，交给求解器，再按题型把答案填进对应 DOM（兼容新旧两套选择器），最后按设置「暂存」或「提交」。
8. **独立考试 / 作业页**：顶层 `document` 的 `.questionLi` 逐题取题干 / 选项 / 题型，序号表 `#topicNumberScroll li[id^='answerSheet'].active` 判定已答，只填不提交。
9. **反检测**：`video-rate.js` 在视频模块页里让页面注册不上 `ratechange / seeked / seeking` 监听，并把 `onratechange / onseeked / onseeking` 置为只读空实现。**这一点必须在 `document_start` 就位**，否则页面会在 2.5 秒内把倍速写回 1x 并暂停。
10. **字体混淆**：部分页面用自造字体（`@font-face` 内嵌 base64 TTF，随机 `font-family` 名）把题干文字替换成乱码码位。扩展**把页面自带的那份 TTF 解出来**（手写 cmap format 4 / 12 解析拿到它真正用到的码位白名单），再用 canvas 取字形墨迹、与参考 CJK 字体做向量匹配还原真实文字 —— **只替换白名单内的码位**，避免污染本来正常的题干。还原失败时退回截图交给视觉模型。
11. **章节排空后的跳转**：队列走完后先看目录的「下一节」按钮（可见才点），再确认页面的完成提示层是否真的显示出来，是则点下一章 —— 只在页面真的给出下一步时才跳，绝不猜目录。

## 五、已知限制

- **只适配一个平台的页面结构**。其它在线课程平台未实现（各平台 DOM 差异极大，套用会直接失效）。
- **强依赖页面 DOM**（`#ZyBottom`、`.singleQuesId`、`.answerBg`、`.questionLi`、`#topicNumberScroll` 等）以及**对话站点的前端结构**（`textarea`、发送按钮特征、`.ds-markdown`）。任一方改版后都需要同步更新选择器。这是这类工具的**固有寿命**，不是 bug。
- **倍速开太高（> 4x）** 部分课程仍可能被判定为异常，建议 2x ~ 3x。
- **`bank`（纯本地题库）不产生任何答案**：题库空时解题助手只会提示一次然后跳过。视频助手不受影响。
- **答题质量取决于你接的引擎**：云端小模型对选择 / 判断 / 填空很稳；本机 7B 模型对主观题（简答 / 论述 / 计算）会明显弱。
- **纯文本模型答不了纯图片题**：题干本身是图片的题会**跳过**（`origin` / `relay` 通道除外，支持传图）。要答图片题得换视觉模型。
- **本机 Ollama 首次出题较慢**（要把模型加载进显存），因此默认超时给了 3 分钟，冷启动超时不是 bug。
- **云端上游要花钱**。中转的题库会去重，同一题第二次不再花钱。
- **API Key 只在你的 `server\relay-config.json` 里**（已 `.gitignore`，且打包脚本会先删掉整个 `server` 目录、再扫一遍 `sk-` 开头的串）。所以发给同学的 zip 和这个仓库里都没有你的 Key —— 反过来说，**拿到扩展文件的人也不能花你的钱**。
- **中转是你自己的机器**：它停了、改了地址、口令不一致，`relay` 模式就会连不上（面板会提示 `-3 连不上答题中转`）。中转的题库文件 `answer-bank.json` 要自己备份。
- **题库是本地明文 JSON**，存在 `chrome.storage.local` 里；若你在意，请勿导出分享给不信任的人。
- **`origin` 通道需要你自己持有第三方商业服务的权益**，且会把题目内容与截图发往第三方服务器。
- PDF / 音频任务点在页面上没有可播放媒体时，只等「已完成」标记（最多 60s）后按完成处理。

## 七、自测

纯逻辑部分带了一组自测，**不需要任何依赖、不需要网络**：

```bash
node test/logic.test.mjs      # 预期：通过 208 项，失败 0 项
```

覆盖范围：MD5 与 `node:crypto` 对拍、任务归一化 / 指纹、答案规范化、base64 解码、
**本地题库**（key 派生优先级、题干空白归一、LRU 淘汰、导入合并语义）、
**五种答案来源的分派**（含 `errNo -100`「没有可用引擎」必须回退成安静跳过）、
以及**接线检查**——把 `consts.js` / `util.js` 在 node 沙箱里真实加载一遍，
再断言 `side-bar.js` 与 4 个 MAIN world 适配器里出现的每一个
`DX.*` / `DXU.*` / `MSG.*` / `SK.*` / `BRIDGE.*` 引用都有定义、
适配器的桥协议字面量与 `BRIDGE` 常量一致、`manifest.json` 引用的文件全部存在、
**并且中转服务与扩展的题库 key 算法逐项一致**（否则两边题库无法互相导入）。

**答题中转**另有一组端到端测试：

```bash
node test/relay.e2e.mjs       # 预期：通过 43 项，失败 0 项
```

覆盖：健康检查、口令校验、题库命中 / 未命中、**上游返回 400 时自动去掉 `response_format` 重试**、
中文与图片（`image_url`）在链路上不损坏、key 派生语义、题库 2 秒防抖落盘与 `.tmp` 原子 rename。

另有一个**选择器保真审计**工具：它把 `src/` 里每一个 DOM 选择器拉回原插件 bundle 里查证，凡是查不到的都会标为「未命中（疑似臆造）」：

```bash
node tools/selcheck.mjs src/content/side-bar.js <原插件>/SideBar.d70b0916.js
```

> 这是本复刻的开发纪律：**不凭「平台常识」臆造选择器**，每个选择器都必须能在原 bundle 里找到。当前 `side-bar.js` 为 **60 个选择器 / 59 命中**，唯一未命中是标签选择器 `querySelector("p")`（误报）。
>
> `tools/` 是**开发目录，不随扩展分发** —— 它需要你手上有原插件 bundle 才能跑。

## 八、这个复刻是怎么做的

原插件是打包过的 MV3 扩展。这里做的是：

1. **静态解包**：解出主 bundle（33 万行、UTF-16LE），格式化后逐块读。
2. **提取行为事实**：任务点是怎么被识别的、倍速是怎么被页面写回的、答案是怎么填进两套完全不同的答题页面的、题库 key 是怎么派生的。
3. **重写而非照抄**：原版把「答案从哪来」放在他们的服务器上，包内没有这段；本复刻把它抽象成**可插拔的引擎层**，并补了三种原版没有的自持方案（网页版通道 / 自建中转 / 本机 Ollama）。
4. **选择器保真**：`tools/selcheck.mjs` 把每个选择器拉回原 bundle 查证，避免靠「平台常识」臆造。60 个选择器里 59 个命中，唯一未命中已确认为误报。
5. **真机验证**：在真实课程页（77 个目录项、44 项已完成）上跑通了「跳过已完成 → 识别任务点 → 播放视频 → 识别并解码混淆题干 → 求解 → 填充」的完整链路。

逆向结论与实现位置的逐条对照见 [`docs/逆向对照.md`](docs/逆向对照.md)。

## 九、设计取舍

几个当时纠结过的点，写下来供参考（也供审阅）：

| 取舍 | 选了 | 为什么 |
| --- | --- | --- |
| 默认引擎 | 网页版通道 | 默认值必须是「零配置可用」。要求每个使用者先填 API Key，等于把 90% 的人挡在门外 |
| 提交按钮 | 独立测验页**只填不提交** | 提交是不可逆动作。把不可逆动作交给自动化，是这类工具最不该做的事 |
| 题库存储 | 明文 JSON + 本地 | 加密会让人误以为「安全」，实际上 key 也在同一台机器上。不如说清楚 |
| 反检测 | 做了，但写进 README | 藏着不说比做出来更糟。使用者有权知道自己在承担什么风险 |
| 多平台适配 | **不做** | 每多一个平台就要多维护一套选择器，而每个平台改版都会让它一夜失效。宁缺毋滥 |
| 打包分发 | 强制删除 `server/` + 扫 Key | 「自己的 Key 被同学打包带走」是这个项目最容易出的安全事故 |
