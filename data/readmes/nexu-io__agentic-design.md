## ✨ What is Open Design?

**Open Design is a chat-native, agent-native workspace for the full product lifecycle — from PRD to pixel to production.**

Traditional tool stacks fragment the same product across **Figma + Jira + GitHub + Slack + Notion + Linear + a docs wiki**. Every handoff loses context. Every new hire re-learns the maze.

**Open Design collapses the stack into one thing: a group chat where humans and agents co-create a living product.**

- 💬 **Chat is the interface** — every artifact (PRD, design, prototype, release note, user feedback) flows through one thread
- 🤖 **Agents are teammates, not tools** — designer agents, PM agents, QA agents, growth agents all get @mentioned and do work
- 🎨 **Design is the center** — the visual artifact is the source of truth, not a doc
- 🚀 **Ship to production** — prototypes turn into live web apps with one command
- 📊 **Data comes home** — user analytics feed back into the same thread for the next iteration

## 🌱 Why we're building this

> *"Figma was built for a world where humans designed alone. We're building for a world where humans and agents design together."*

We ran a product survey across 146 builders (94 qualified ICPs). The top 3 things they asked for:

1. **"Agents that hand off tasks to each other"** — 71% · the #1 capability want
2. **"All my coding agents in one place"** — 60%
3. **"7×24 background agents I don't have to babysit"** — 60%

And the top pain they named without prompting:

> *"I need a digital twin that grows with me — a swarm of agents I can coordinate in one space."*

That's what Open Design is.

## 🧭 Product Principles

1. **Default-on > configurable** — every onboarding step costs a user. We fight configuration hell.
2. **Chat-native, file-visual** — chat is how you coordinate; files are how you converge.
3. **Give users their own words back** — the product reflects what users already say about their work.
4. **Open core, managed edges** — source is free and forkable; orchestration, token routing, and collaboration are managed services.
5. **Design first, full-stack eventually** — we start at Design because it's where context becomes concrete. We expand into PRD, build, release, and data over time.

## 🗺️ Roadmap

Open Design will ship in 4 stages. We deliberately start **narrow and deep**, then expand.

### Stage 1 · Single-player Design (Now → Q2 2026)
- 🖼️ Web canvas — create and iterate on designs via chat
- 🤖 Built-in design agents (layout, component, copy, icon)
- 📄 PRD-to-Design — paste a spec, get a first draft
- 🧠 Persistent memory — the agent remembers your design system

### Stage 2 · Desktop & Local-first (Q3 2026)
- 💻 Desktop app (macOS / Windows / Linux)
- 📁 Local file library + Git-friendly design files
- 🔌 MCP + plugin ecosystem

### Stage 3 · Multiplayer Workspace (Q4 2026)
- 👥 Group chat as the design room
- 🧑‍🤝‍🧑 Human + agent co-editing, with same permissions
- 🔍 Searchable design history & decisions
- 🔀 Design review workflows

### Stage 4 · Full Product Lifecycle (2027)
- 📝 PRD ↔ Design ↔ Prototype ↔ Production ↔ Analytics — all in one thread
- 🚀 One-click deploy to live app
- 📈 Live user data feeds back into the design chat
- 🏭 Extensible to adjacent flows (marketing assets, brand systems, even manufacturing)
