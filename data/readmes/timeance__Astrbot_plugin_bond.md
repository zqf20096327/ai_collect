Bond 是面向 **长期多人群聊** 的关系记忆插件。它分别记录 Bot 对每位成员的熟悉度、亲近度与信任度，将三维状态转成自然语言描述，供当前人格在回复时参考。

关系可以随群聊互动更新，也可以在管理面板里查看、调整、撤销或设置限时覆盖。每份关系资料都属于对应的 Bot 账号与数据空间；群内公开查询只显示关系称谓，不展示具体分值。

> **初次安装默认在回复中体现关系，自动评估、动态称谓和诊断记录默认关闭。** 启用自动评估前，先在管理面板选择日常评估模型。已有配置中明确关闭的回复参考会继续保留。可先试用查询和管理功能，再按需开启自动评估。

## ✨ Bond 能带来什么

| 特色 | 你会用到的能力 |
| --- | --- |
| **三维关系，分别记录** | 熟悉度、亲近度、信任度各自计算，可以同时表达“亲近”和“戒备”。 |
| **76 个中文关系词条** | 在初识、渐熟和亲近阶段细分表达，也能描述熟悉却疏远、亲近却戒备等关系。 |
| **可选动态称谓** | 根据完整人格和三维关系生成个性化称谓，保存后复用；查榜不额外生成称谓。 |
| **表达沿用当前人格** | 词条提供理解线索，Bot 不必照读标签，也没有预设的冷淡或热情答法。 |
| **每个 Bot 有自己的关系** | 按真实 Bot 账号独立存储；群内关系与全局关系分开管理。 |
| **关系可查、可调、可撤销** | 管理面板保留变动流水，支持正式调整与限时体验，临时关系结束后恢复正式值。 |
| **可选诊断，方便验证** | 本机记录脱敏的变化、称谓与调用情况，帮助排查漂移和失败，不额外调用模型。 |

## 🌿 三层处理，让关系更容易理解

**三个维度负责计算，关系词典负责解释，当前人格负责表达。**

  <img src="docs/assets/relationship-overview.svg" width="1000" alt="三层关系处理：三维五档与125种主状态，结合局部细分提供76个关系称谓，再由当前人格表达。" />
</p>

### ① 计算：熟悉、亲近、信任各有含义

| 维度 | 描述什么 | 从低到高的五档 |
| --- | --- | --- |
| **F · 熟悉度** | 有多熟悉 | 陌生 → 眼熟 → 相识 → 熟悉 → 熟络 |
| **A · 亲近度** | 相处时的亲疏 | 疏远 → 疏淡 → 平和 → 亲近 → 亲密 |
| **T · 信任度** | 放心还是戒备 | 戒备 → 谨慎 → 保留 → 放心 → 信赖 |

熟悉度范围为 `0..100`，亲近度与信任度为 `-100..100`，三者不合成一个总好感分。初始三维均为 `0` 时，对应档位为「陌生 + 平和 + 保留」，关系称谓为 **陌生**。分档用于描述状态，不是经过心理学校准的概率。初期少量有效交流即可从“陌生”走向“眼熟、相识”；熟悉不等于亲近，更不等于信任。

### 眼熟模式

眼熟模式让 Bot 对同群活跃成员逐渐积累熟悉度。有人明确 @ 当前 Bot 时，默认按以下规则处理：

- 从同群最近 **10 分钟**的发言者中，选取最近发言的 **3 位其他成员**。
- 每人增加最多 **0.3 F**，每 **30 分钟**最多一次，通过此方式最多增长到 **60 F**。
- 与直接互动共用每日 F 加分额度；不套用阶段倍率或 Galgame 单次加分倍率，但保留 Galgame 的每日总额度。

这五项参数可在「详细设置 → 熟悉度变化」中调整，位于熟悉度每日扣分上限之后。人数设为 `0` 时不限制人数，仍只选时间范围内的成员。选中的人若处于冷却、额度不足或已达上限，会跳过本次奖励，不向更早的成员补位。

被动增长不刷新任何维度的保温时间，不增加亲近或信任。超过被动上限的 F 仍按原规则衰减，该上限不是衰减下限。当前 @ 成员不领取本次被动奖励，仍按既有规则处理直接互动。仅回复 Bot、文字唤醒及 @ 其他成员不触发被动奖励。

新安装或缺少配置时默认开启，已有开关选择会保留，可在「基础设置」中关闭。眼熟模式独立于自动评估，不增加模型调用，只记录成员身份和最近发言时间。重启后重新积累活跃成员，但仍保留已发奖励的冷却与去重记录。

流水来源显示为「群聊活跃」，同次触发合并显示。列表最多预览 3 人，详情可查看全部成员并分别撤销。详细规则与验证范围见 [眼熟模式说明](docs/PASSIVE_FAMILIARITY.md)。

### ② 理解：同样熟悉，也可以是不同的关系

| 词典中的状态 | 它保留的细节 |
| --- | --- |
| **陌生** | 初始默认状态（三维均为 `0`）：尚不熟悉，亲疏态度平和，信任有所保留。 |
| **亲近却戒备** | 有亲近感，也有明确戒心；亲近不会抵消边界。 |
| **疏远但信赖** | 不够热络，仍可以保有较强信任。 |
| **亲密而保留** | 已经熟悉且亲近，信任上仍有所保留。 |
| **亲密挚友** | 熟悉、亲近和信任均较强，仍不改变人格原则或权限。 |

这些词条表示并列的关系组合，不是一条逐级升级的路线。完整映射与局部细分见 [关系词典](docs/RELATION_LEXICON.md)，动态称谓规则见 [评估框架](docs/ASSESSMENT_FRAMEWORK.md#关系称谓)。

在亲近度与信任度保持平和、保留时，熟悉度增长可以依次呈现：**陌生 → 眼熟之人 → 浅交之人 → 泛泛之交 → 寻常相识 → 相熟之人 → 普通熟人 → 熟络之交**。前期在 F 达到 1、3、5、8 时就有不同表达；这只是这一组关系的示例，不代表聊天越多就必然成为朋友。

三维仍各分五档，共有 **125 格主状态**。部分组合另设 F 为 **3、8、20** 和 A 为 **25** 的局部展示边界，让同一主档位内也能呈现变化。

### 固定词典与动态称谓

默认使用 **固定词典**，不增加模型调用。想让称谓贴近 Bot 的气质，可在 AstrBot 插件设置中开启「动态称谓」，或进入 Bond「详细设置 → 个性化功能」开启同名开关。两个入口共用设置，与 Realistic / Galgame 的关系增长模式分别控制。称谓模型留空时跟随复核模型，也可单独指定；两者都未配置时继续使用固定词典。

动态称谓根据当前会话的完整人格和三维关系生成，经过校验后保存。按群记录时可参考本群印象，全局关系空间不使用跨群汇总的印象。亲近却戒备、熟悉但疏远等关系也可生成称谓。缺少完整人格、生成失败或校验未通过时，沿用仍适用的已保存称谓，否则显示固定词典。

成员实际互动时，若任一维度跨过 **5 分边界**，便会检查是否可以刷新。默认两次刷新尝试至少间隔 **12 小时**，每 Bot 每个 UTC 日最多 **30 次模型调用**；每次刷新最多尝试 **3 轮**，通过后即停止。生成、校验、失败和重试均计入次数，额度跨群和数据空间共用。可延长间隔、降低日上限，或将日上限设为 `0` 暂停；单次调用默认超时 **30 秒**。

查询和排行只读取已保存且仍适用的称谓，不触发生成。人格改变、关系含义不再匹配、来源撤销或临时关系切换后，旧称谓会停用。称谓刷新与印象更新分别进行；缺少明确会话的管理页面和跨插件查询使用固定称谓。

关闭动态称谓后，改用固定词典并保留已保存的结果。再次开启时，可继续使用仍适用的称谓；需要更新时先显示固定词典，等下次互动跨过分数边界、且满足间隔和额度要求后再刷新。

### ③ 表达：让角色用自己的方式回应

「在回复中体现关系」开启时，Bond 会给回复模型补充关系资料，保留原有的人格设定、用户输入和对话历史。系统不要求模型披露或照读称谓，具体如何回应由当前人格、系统规则和对话语境决定。

默认回复指导会区分不同的社交情境：普通求助、昵称、临时玩笑和持续亲密身份分别考虑；要求只是提议，不自动成为双方既有的承诺。熟悉后可以减少客套、接续有依据的话题，亲近后可以有符合角色的调侃，但高关系不代表必须接受，也不授予权限。已有自定义行为模板会保留，只有选择默认模板才使用新版默认文案。

普通群消息会先读取当前关系、印象和近期事件，再启动后台评估。同一条消息的重试或后续工具调用继续使用这份资料，下一条消息才重新读取。因此，本轮评分不会反过来影响本轮回复；角色仍可直接回应眼前的玩笑、求助或冒犯。第三方主动发起、绕过普通群消息入口的请求，只能在首次生成回复时读取资料；无法确认 Bot 和成员身份时不补充关系。

自然语言工具提供的是 **当前 Bot 对成员的关系**，不能据此推断成员对 Bot 的感受，也不能回答群友之间谁最喜欢谁。唤醒、接话与主动发言仍由 AstrBot 或 Angel Heart 等插件决定。

## 🚀 快速开始

### 1. 安装并确认 Bot

- 使用 AstrBot `>=4.28` 和 `aiocqhttp`；真实框架装配验证覆盖 `4.28.0`、`4.29.4`，Python 版本跟随宿主要求。后续版本可加载，兼容性以实际框架验证为准。
- 在 AstrBot 的插件管理中通过本仓库地址安装；也可下载 main 的 ZIP，解压到 `data/plugins/astrbot_plugin_bond/`。**插件目录必须全小写**。
- 重载后打开 Bond 管理页面，在「详细设置 → 基础设置」**先手动选择日常评估模型**（不自动跟随聊天模型），再按需开启自动评估，填入适用群与需要忽略的机器人账号。在「个性化功能」中调整回复参考与动态称谓。尚未发现 Bot 时也可完成这些设置。
- 在「详细设置 → 基础设置」选择关系模式，在「关系变化」调整基础参数；新安装默认为 Galgame。保存并重载后生效。连接 OneBot 后点击“刷新 Bot 列表”，选中需要管理的 Bot 与数据空间。

插件列表左侧与 README 使用同一版 Logo。更新插件后重载并刷新插件页面即可；手动安装时请保留根目录的 `logo.png`。

Bot 账号来自平台连接或可信消息事件；一个适配器可以包含多个账号。私聊可帮助登记 Bot，但不会建立关系记录。仅填写适配器配置、尚未连接或收到事件时，列表可能没有可识别的账号。

### 2. 先试公开查询与管理命令

在已启用 Bond 的群聊中发送：

| 命令 | 权限 | 用途 |
| --- | --- | --- |
| `/我的关系` | 所有群成员 | 查看当前 Bot 对发言者自己的关系称谓，始终保留原有行为。 |
| `/我的印象` | 所有群成员，需开启 | 按设置返回关系称谓，或结合当前人设生成一句话印象。 |
| `/好感排行` | 按配置（所有人 / 仅主人） | 查看本群前 10 名的昵称、头像与当前关系，按亲近度排序，不显示分值。 |

在 AstrBot 插件配置或 Bond「详细设置 → 查询与排行」中设置“我的印象”：默认**关闭**；“输出关系称谓”仅返回称谓；“大模型总结”使用**当前会话聊天模型和人设**，结合关系称谓、标签与已有印象生成一句话，超时、异常或无有效回复时回退关系称谓。

“你对我有什么印象”“你觉得我怎么样”“你对我的感觉如何”等问法由聊天模型识别后调用 `query_my_impression`，仍需宿主正常接话并支持工具调用；需要确定入口时使用 `/我的印象`，仅查关系称谓可继续使用 `/我的关系`。本功能只查发问者本人，不更新关系或存储生成结果。总结会将当前人设及上述关系资料发送给当前聊天模型，不发送分值或原始流水；同一 Bot 的全局空间只使用共享关系称谓，不带入其他群的标签或印象。

### 3. 按需开启自动变化与回复参考

| 想要的效果 | 设置方法 |
| --- | --- |
| 互动后自动评估关系 | 在「详细设置 → 基础设置」手动选择日常评估模型与评估模式，再开启自动评估；复核模型可留空。 |
| 回复时参考当前关系 | 在「个性化功能」调整「在回复中体现关系」，新安装默认开启。它与自动评估分别控制，也可配合手动设定的关系使用。 |
| 使用个性化称谓 | 在「个性化功能」开启「动态称谓」，模型默认跟随复核模型。 |
| 只在指定群使用 | 填写 `group_whitelist`；留空表示所有群。名单外不记录、不评估、不注入，也不响应 Bond 群聊查询。 |
| 观察规则与称谓的运行 | 在“详细设置 → 关系诊断”打开诊断记录。 |

自动评估在后台进行，**不阻塞正常回复**。**Bond 页面保存基础与详细设置后需要重载插件；提示词保存后立即生效。** AstrBot 原插件配置也可编辑同一份配置，宿主保存时会自动重载。切换编辑入口后先刷新，避免提交另一处已过期的表单。自动评估需要调用你选择的模型，会产生相应用量。用量统计缺失时显示未知，不估算货币成本。

### 印象与标签如何更新

印象更新频率由 `impression.interval` 配置（默认 `8`）：

- **哪些记录计入累计**：仅统计上次汇总之后**未汇总、未撤销的有效自动评估流水**（其中包含因每日额度等限制而写入的零变化评估流水）。已撤销的流水不参与，管理员手动调整不计入；这不是聊天消息条数或模型调用次数，**不是每聊 8 句就更新**。
- **何时尝试更新**：在一次自动评估实际更新关系后进行检查；当累计的有效自动评估流水达到 `impression.interval`（默认 8 条）时，启动后台任务生成印象。
- **群空间与全局空间**：按群记录（`per_group`）时，每个群分别积累；全局空间（`global`）中，同一 Bot 对同一成员的跨群评估记录共同积累，同样支持自动更新印象（但 Bond 不支持私聊关系记录，也不会因此在群聊回复中公开其他群的印象或历史）。不同 Bot 和不同数据空间相互独立。
- **两种记录模式**：默认的一句话模式同时更新印象和标签，标签最多 3 个；分点模式（`impression.points_mode`）更新印象要点并保留已有标签。模型不可用或生成失败时，保留原内容和待汇总记录。临时关系期间暂停自动更新。

AstrBot 插件配置与 Bond「详细设置 → 查询与排行」共用我的印象、排行权限、图片排行、显示人数、文字查榜与唤醒短语设置，保存后重载插件生效。AstrBot 插件配置保留启用、模型、适用范围和排行等常用选项。三维变化、印象与回复、评估高级参数放在 Bond 页面中，日常使用可以保留默认值。

### 4. 一套基础参数，两种关系节奏

<p align="center">
  <img src="docs/assets/rhythm-overview.svg" width="1000" alt="Bond 关系节奏、熟悉度六段增长倍率与默认 5 天关系保温期机制" />
</p>

新安装默认 **Galgame**，回复参考默认开启。自动评估默认关闭：先选择日常评估模型，再按需开启。

模型判断互动性质、指向、上下文与语义重复；Bond 校验身份、协议和当前原文证据，再执行本地数值规则。普通有内容问答可以增加熟悉度，不自动增加亲近度。**信任来自可观察的可靠行为**：有记录确认的纠错、履约和实质修正，可逐步建立或修复信任；感谢、示好、承诺和道歉本身不加信任。

纠错、履约和实质修正的可信事件基础增加 **0.5 T**，Galgame 下为 **1 T**。明确越界、重复实质施压、可证实的蓄意误导、严重操纵分别按 **−1 / −2 / −4 / −6 T** 处理，仍受每日额度限制。普通冒犯与普通操纵只影响原有亲近度判断，T 为 0。正常批评、无害玩笑不应被当作破坏信任。一次道歉不能抵消严重失信，后续独立的可靠行为可以慢慢修复。

**持续尊重边界也能积累信任。** 明确边界后，14 天内至少有 3 件独立、可核验的遵守行为，可获得基础 **+1 T**（Galgame 为 **+2 T**），每 5 天最多奖励一次。同一件事的重复表述不累计，奖励仍受每日额度限制。

自动信任变化需要选择**分级复核**并配置复核模型。两次判断须一致，并引用本群、当前成员上下文中实际记录的 Bot 回复；缺失记录、证据不完整或无法复核时不计 T。同一已确认事项的重复补述不重复计分。模型仍可能误判，引用存在也不等于现实事实已被验证；管理员可查看证据并撤销流水。

| 每日互动额度 | 基础模式 | Galgame（默认） | 两种模式扣分额度 |
| --- | --- | --- | --- |
| 熟悉度 F | +5 | +10 | 0 |
| 亲近度 A | +10 | +20 | −8 |
| 信任度 T | +2 | +4 | −8 |

Galgame 将所有正向请求和正向每日额度统一乘 2；负向单次变化、负向额度、模型、调用次数与衰减不变。正负用量独立累计，加减不能抵消已用额度；撤销恢复分值，不退还已消费的互动额度或调用次数。自动时间衰减不占扣分额度。切换模式不翻倍旧分数、不重算历史、不清空当天用量。

**越熟悉，积累速度越平缓。** 熟悉度按六个数值区间调整增长倍率，与关系词典的五档独立；具体倍率见上图。亲近度保留等级倍率与同日加分递减。微小的有效变化会保存，页面显示一位小数。

**关系保温期默认 5 天。** 超过保温期后，关系才开始随时间淡化；设为 `0` 可取消保温期。三个维度分别计时：普通问答只维护熟悉度，亲近和信任需要各自的合格事件。因此，即使熟悉度一直在增加，长期没有信任事件时，超出基线范围的信任仍会衰减。

合格互动会重置对应维度的计时，不恢复此前已淡化的分数。被规则拒绝或每日额度用尽的事件不延长保温期；如果事件本身合格，只是增量太小而被舍入为零，或分数已达到上限，仍可维护对应维度。三个维度都只计算超过 `decay.grace_days` 的时间。

`decay.maintenance_strategy` 默认 `independent`；`legacy` 保留熟悉度和亲近度的联动保温，**信任始终只由合格可信事件维护**。手动切换维护策略仍沿用既有结算机制，不补发保温期，也不重算历史奖励。成员详情的“最近互动”按三个维度最近的真实维护时间显示。

默认半衰期为熟悉度 **30 天**、亲近度 **30 天**、信任度 **60 天**，默认基线分别为 **10、0、20**。开启亲近度档位托底（`decay.floor_enabled`，默认开启）时，按当前亲近度所在等级（`厌恶 / 陌生 / 认识 / 友好 / 亲密 / 挚友 / 挚爱`）**向下两级的下沿**计算衰减下限（例如「挚爱 `95`」最多衰减到「亲密」下沿 `55`）；托底只影响亲近度，不保证三维关系称谓保持不变。每维的开关、半衰期与基线都可在详细设置的“熟悉度变化”“亲近度变化”“信任度变化”中调整；共用的关系保温期与额度换日时区位于“基础设置”。

基线是衰减的停止范围，不是自动赠送的分数。熟悉度高于基线（默认 `10`）时随时间向基线下降，低于或等于基线时保持不变；亲近度与信任度使用正负对称范围。例如信任基线设为 `20`，`+40` 在保温期结束 60 天后约为 `+30`，`−40` 约为 `−30`，之后继续向 `+20` / `−20` 收敛；低于 `−20` 的信任可向 `−20` 回升，`−20～+20` 内保持不变，但时间流逝不会把负信任变为正信任。临时关系期间暂停三维正式衰减；修改参数并重载后，对已有成员也使用当前设置。

<details>
<summary>评估次数与上下文范围</summary>

默认每位成员在同一 Bot 下每 5 分钟最多初评 5 次，每天初评 30 次、复核 8 次；每个 Bot 每天初评 300 次、复核 100 次，插件同时最多评估 2 人。调用额度跨群及数据空间共享，失败和超时也计入次数；调用日额度按 UTC 日期刷新。

评估默认参考最近 6 条相关发言或回复，以及 7 天内最多 8 条同群已计分摘要，总长不超过 4000 字符。只使用当前成员与 Bot 的相关互动，不监听完整群聊；历史内容不能重复计分，语义判断仍可能出错。

</details>

在「详细设置 → 基础设置」选择关系模式，在「关系变化」按熟悉度、亲近度、信任度分别调整参数；在「评估」调整窗口、预算、并发与上下文。点击 **「恢复此区默认设置」** 只将默认值填入当前设置分区，检查后保存并重载生效，不会清除模型选择、成员状态或流水。已有明确保存的模式与参数继续保留，重装保留配置也不会自动替换旧值。评估是否合适仍受接入模型影响，建议固定模型与人格观察 2–3 天。

升级、精度、额度与回滚说明见 [关系评估框架](docs/ASSESSMENT_FRAMEWORK.md)。

### 临时体验，不抹去正式关系

临时关系生效时，称谓、排行和回复参考使用临时值，成员详情中同时显示正式值与截止时间。期间暂停该关系的自动评估、自动印象更新和正式衰减，已发出的旧任务不能回写。

到期或点击“立即结束临时关系”后恢复正式值，随后继续衰减与评估；期间消息不补评。临时状态保存在本地，重启后继续生效。结束临时关系后，才能调整正式分数、撤销分数流水或重置；印象与标签仍可手动编辑。

诊断默认关闭。启用后默认使用 `assessment` 档，仅记录脱敏的变化、称谓、评估状态、调用耗时与用量；管理员可在当前 Bot、当前空间下查看状态、导出或清除，关闭后仍可管理旧记录。

<a id="boundaries"></a>
## 使用前，了解这些边界

**关系只影响态度和表达。** Bond 不改变系统规则、管理权限、人格核心或发言策略；配置中的“主人”只是沿用当前人格的称谓，不授予权限，也不豁免评分。关系状态用于角色表现，不代表 AI 拥有真实感情。

**先确认归因，再考虑变化。** 自动评估只接受没有冲突的当前 Bot 指向。其他 @ 对象、多目标、引用来源缺失或冲突时跳过更新。空文本、不满足入口条件的消息和相同稳定消息 ID 的重复处理由框架拒绝；是否只是寒暄、重复感谢或新的实质互动交由模型结合有界上下文判断。滚动调用窗口与分值额度分别约束调用和变化，纯文本转述仍可能被模型误解。

**模型提出事件建议，本地规则决定变化。** 模型不能直接修改三维数值。失败、超时、解析失败、复核预算不足或结果不确定时，本次不改关系，正常对话继续。同时评估人数已满时跳过新评估，不排队影响对话。

**感谢和道歉不自动换来信任。** 有记录支持的纠错、履约和实质修正，经初评与复核一致确认后可逐步增加信任。感谢、示好、承诺和道歉本身的 T 为 0，信任事件的证据要求见上方关系节奏说明。

**图片排行会获取 QQ 头像。** 获准查询后，仅向固定 QQ 头像服务发送榜内至多 10 名成员的账号来获取头像，不发送关系称谓、分值或聊天。头像只短时缓存在内存，失败使用昵称占位；图像在本机生成，内置中文字体，无需在线渲染或额外模型。关闭图片或使用模型工具查询时不请求头像。

**模型调用有数据外发。** 启用评估或刷新印象时，消息文本、允许的上下文或有限流水可能发送给所选 AstrBot Provider。动态称谓会将当前完整人格、三维关系与允许参考的本群印象发送给称谓模型（未单独指定时跟随复核模型），全局空间省略聚合印象。“我的印象”的大模型总结使用当前会话聊天模型。Bond 不自动上传本地诊断；请勿向 Issue、PR 或截图提交真实聊天、账号、数据库和密钥。

提示词保存在独立的 `data/plugin_data/astrbot_plugin_bond/prompts.json`。评估和行为模板分开管理，群级覆盖按真实 Bot ID 与群 ID 保存；评估模板始终保留程序的输出协议，未知占位符会被拒绝。

提示词文件损坏时保留原文件，暂停自动评估与关系注入；本地查询和管理继续运行。修复或恢复文件后重载插件，详见 [提示词说明](docs/PROMPTS.md)。

基础与详细配置适用于所有 Bot。Bond 页面保存后重载生效；已开始的任务按原配置执行完毕。群白名单外的历史资料保留，管理员仍可在面板管理。配置仍由 AstrBot 保存，隐藏字段保留；Bond 基础设置与评估页共用版本校验，过期保存会被拒绝，需刷新后重试。AstrBot 原配置入口不使用 Bond 的版本校验，因此在两处来回编辑时先刷新原配置表单。

LivingMemory 集成已移除，不再探测、读取或写入其记忆。本地关系、印象与流水不受其安装或卸载影响，见 [接口调查](docs/LIVINGMEMORY.md)。

</details>


## 升级、备份与回滚

升级前停用插件，并一起备份代码、AstrBot 插件配置和整个 `data/plugin_data/astrbot_plugin_bond/` 数据目录。复制 SQLite 文件前须停止写入；在线备份使用插件提供的备份功能。

**从 0.6.0 之前的版本升级时，会一次性重置信任专属的五项配置，原来自定义的值也会覆盖。** 已完成这次升级的安装不会再次重置。新值为基础每日加分上限 `2`、扣分上限 `8`、启用信任衰减、半衰期 `60` 天、基线 `20`。共用保温期、关系模式、F/A 设置和模型选择沿用已保存值。升级成功后再调整的信任设置会正常保留。

上述信任配置升级保留成员原始 T、各维度的维护时间与历史流水，重载后直接按新参数计算信任度，显示值可能立即变化。插件会将覆盖前的五项信任设置保存为数据目录下的 `trust-settings-before-0.6.json`，避免重复覆盖；保存失败时会撤回修改并报错。具体范围与处理方法见 [升级说明](docs/MAINTENANCE_UPGRADE.md)。

**0.7.0 保留关系分数与历史流水。** 旧称谓开关自动兼容；旧默认刷新间隔由 6 小时改为 12 小时，日上限由 10 次改为 30 次，并将生成和校验分别计次。其余自定义值只在超出新范围时调整。

当前数据结构为 **schema 20**，在原有称谓缓存和调用记录之外，新增持续尊重边界所需的证据记录。从早期单分结构升级时，原好感度保留为亲近度，新增的熟悉度与信任度初始化为 `0`。回滚须成套恢复匹配的旧代码、配置与完整数据备份。旧代码不能直接打开新库。Bond 不自动导入旧 `bond.db` 或 Xinxian 数据。

本版提供 [三组行为对照与多轮评测材料](docs/P0_BEHAVIOR_EVALUATION.md)。离线工程测试不证明真实模型已更自然或有趣，真实群聊效果需另行验收。
