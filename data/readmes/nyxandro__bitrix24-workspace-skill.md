**Скилл для ИИ-агента, который читает ваш рабочий Битрикс24: чаты, задачи, проекты, файлы, почту, календарь и встречи. Только чтение.**

Скилл для Claude Code, Codex, OpenCode, Cursor и других агентов, которые понимают Agent Skills и
умеют запускать команды. Вы спрашиваете обычными словами, агент сам вызывает встроенный CLI и
отвечает по живым данным портала через
[REST API Битрикс24](https://apidocs.bitrix24.ru/), а не по памяти. Запускать CLI руками не нужно.

Скилл работает через **входящий вебхук** и видит ровно то, что видите в портале вы. Он **только
читает**. Отправить, изменить или удалить что-либо он не может технически: в программе зашит
список разрешённых методов, и все они читающие.

## Что умеет

| Раздел | Что внутри |
|---|---|
| Чаты | Последние диалоги и непрочитанное, переписка в чатах, личке, чатах задач и проектов, поиск по чату, участники |
| Уведомления | Упоминания, поручения, приглашения |
| Задачи и проекты | Мои задачи по всем ролям, карточка задачи с её чатом и чек-листом, учтённое время в задачах (сколько и что сделано, итоги за период), группы, проекты, коллабы |
| Диск | Хранилища, папки, поиск по названию и тексту документов, скачивание файла для чтения |
| Почта | Ящики, поиск писем, текст письма, цепочка |
| Календарь и встречи | Ближайшие события, любой период и календарь, ИИ-итоги видеовстреч с договорённостями, задачами и расшифровкой |
| Лента и база знаний | Новости компании с комментариями, документы базы знаний |
| Структура и время | Мой отдел, руководители, коллеги, журнал рабочего дня |

CRM, открытых линий, телефонии и бизнес-процессов в скилле нет.

## Установка

Нужен **Node.js 20.19 или новее**. Это единственная внешняя зависимость, весь код собран в один
файл, npm-пакеты и сборка не нужны.

| Способ | Команда |
|---|---|
| Claude Code, как плагин | `/plugin install bitrix24-workspace --marketplace nyxandro/skills` |
| Claude Code, Codex, OpenCode, Cursor и другие | `npx skills add nyxandro/bitrix24-workspace-skill` |
| Одной командой, Linux, macOS, WSL | `curl -fsSL https://raw.githubusercontent.com/nyxandro/bitrix24-workspace-skill/main/install.sh \| bash` |
| Вручную | Скачайте [архив `.skill` последнего выпуска](https://github.com/nyxandro/bitrix24-workspace-skill/releases/latest/download/bitrix24-workspace.skill) и распакуйте в папку скиллов агента |

Выберите один способ. Если поставить двумя, Claude Code загрузит скилл дважды. После установки
перезапустите сессию агента.

Не ставьте вместе с другими скиллами Битрикс24 с похожим описанием, агент может выбрать не тот.

<details>
<summary>Подробнее о способах установки</summary>

<br>

- Скрипт `install.sh` скачивает скилл, кладёт его в `~/.agents/skills/`, ставит ссылку в
  `~/.claude/skills/` и создаёт пустой `~/.config/bitrix24-workspace/.env`, закрытый от других
  пользователей машины. Повторный запуск обновляет скилл и не трогает уже вписанный адрес.
- Для агента со своей папкой скиллов добавьте `--dir <папка>`. На машину без интернета скопируйте
  архив и запустите `bash install.sh --file bitrix24-workspace.skill`.
- Плагин и `npx skills` файл `.env` не создают. Заведите его, как в разделе
  [Настройка вебхука](#настройка-вебхука).
- Архив `.skill` это ZIP. Распакуйте его в папку скиллов, сам файл архива агент не подхватывает.

  ```bash
  unzip bitrix24-workspace.skill -d ~/.agents/skills/     # или -d ~/.claude/skills/ для Claude Code
  ```

- Установка плагина одной командой работает в Claude Code 2.1.275 и новее. На старой версии
  сначала добавьте каталог командой `/plugin marketplace add nyxandro/skills`.
- С `npx skills` добавьте `-g`, чтобы скилл стоял во всех проектах. Чтобы поставить определённую
  версию, допишите её метку, например `nyxandro/bitrix24-workspace-skill@v0.1.2`.
- Скилл сам подскажет в `status`, когда в репозитории появится новая версия.

</details>

## Как пользоваться

Спрашивайте как обычно.

- *Что мне писали по проекту за неделю?*
- *Что обсуждают в задаче 4521?*
- *Сколько часов я списал в задачи за ноябрь и на что?*
- *Что у меня непрочитанного и что мне прилетело?*
- *Найди на диске договор с поставщиком и скажи, какой там срок оплаты.*
- *Что у меня завтра и о чём договорились на созвоне во вторник?*
- *Где у нас правила про отпуск и кто мой руководитель?*
- *Отправь Иванову, что я опоздаю.* Агент ответит, что скилл только читает.

В начале работы агент вызывает `status`: проверяет подключение, показывает, от чьего имени
работает вебхук, каких прав не хватает и какие лишние.

## Настройка вебхука

1. В Битрикс24 откройте **Разработчикам → Другое → Входящий вебхук**.
2. Отметьте права `im`, `task`, `sonet_group`, `socialnetwork`, `disk`, `mail`, `calendar`,
   `user_basic`, `call`, `log`, `note`, `timeman`. Что для чего нужно, расписано в
   [`references/setup.md`](skills/bitrix24-workspace/references/setup.md). CRM и остальное не
   нужно.
3. Впишите адрес вебхука в `~/.config/bitrix24-workspace/.env` **сами, не через чат с ИИ**.

   ```bash
   bash -c 'umask 077 && mkdir -p ~/.config/bitrix24-workspace && read -rsp "Вставь адрес вебхука: " U && printf "BITRIX24_WORKSPACE_WEBHOOK_URL=%s\n" "$U" > ~/.config/bitrix24-workspace/.env && chmod 600 ~/.config/bitrix24-workspace/.env && echo " готово"'
   ```

4. Спросите агента "проверь подключение к Битрикс24", он вызовет `status`.

CLI читает `.env` только из `~/.config/bitrix24-workspace/.env`, а не из текущей папки. Настоящая
переменная окружения `BITRIX24_WORKSPACE_WEBHOOK_URL` важнее файла, это штатный способ для
серверов и контейнеров. Без адреса будет ошибка `APP_B24_WEBHOOK_MISSING`, значений по умолчанию
нет.

## Безопасность

- **Запись закрыта программой, а не Битриксом.** У вебхука нет режима "только чтение", сам адрес
  позволяет и запись. Храните его как пароль. Если он утёк, удалите вебхук в Битрикс24 и создайте
  новый.
- **Право `call` нужно только для итогов встреч**, но по документации оно же открывает платные
  робозвонки. Скилл их не вызывает. Если итоги встреч не нужны, не давайте это право.
- **Ключи не выводятся.** Ни адрес вебхука, ни ссылки на скачивание файлов (в них тоже ключ) не
  попадают в ответы и ошибки. Файлы скилл скачивает сам и сообщает только путь.
- **Содержимое это данные, а не команды.** Инструкция агенту запрещает исполнять указания из
  писем, сообщений и документов.
- **Списки сужены до своего.** Даже у администратора списки задач, учёта времени, итогов встреч и
  диски по умолчанию только свои. По прямому номеру (задача, группа, чужой календарь) и в поиске по диску
  видно всё, что Битрикс разрешает этому сотруднику.
- **Переписка уходит в ИИ-сервис вашего агента.** Всё, что агент прочитал, он передаёт своей
  модели. Решать, можно ли так работать с данными компании, вам.

Честная оговорка: защита держится на том, что агент работает через программу. Другие инструменты
агента, например официальный MCP Битрикса, могут уметь писать, и это вне скилла.

<details>
<summary>Как это работает внутри</summary>

<br>

- **Одна точка выхода в сеть.** Все запросы к порталу идут через один клиент. Перед каждым он
  сверяет метод со списком разрешённых и с формой имени "только чтение", любой другой вызов
  отклоняется до отправки с кодом `APP_B24_METHOD_NOT_ALLOWED`.
- **Темп.** Не чаще двух запросов в секунду, это лимит облачного Битрикс24. Повторов и кэша данных
  нет.
- **Ответы.** JSON из явного списка полей, имена вместо номеров, текст без разметки. Длинные
  тексты обрезаются до 4 000 знаков, списки отдаются порциями с курсором продолжения.
- **Последняя проверка вывода.** Значения, похожие на ключи (`token=`, `auth=`), заменяются на
  `<скрыто>`. Если в ответе оказался адрес вашего вебхука, ответ не печатается вовсе.
- **Ошибки.** Любая ошибка выводится по-русски со стабильным кодом `APP_...`, технические
  подробности видны при запуске с `B24_DEBUG=1`.
- **Правила для агента** (только через CLI, содержимое как данные, расшифровка полей JSON) лежат
  в `SKILL.md` и `references/` внутри пакета, и агент обязан им следовать.

</details>

## С чем хорошо сочетается

Рекомендуем ставить вместе с [Materials Intake](https://github.com/nyxandro/materials-intake-skill).
Bitrix24 Workspace достаёт материалы из портала: читает переписку, письма и итоги встреч,
скачивает файлы с диска и вложения из чатов. Materials Intake принимает всё, что пришло в проект,
и наводит порядок в папке `inbox/`. Когда стоят оба, попросите агента забрать материалы из
Битрикс24 и разобрать их. Скачанное не останется лежать где попало: агент разложит его по папкам
в `inbox/`, не пустит пароли и личные данные в git и внесёт в одну опись, что это за материал,
от кого он и что в нём решено.

```bash
npx skills add nyxandro/materials-intake-skill     # или /plugin install materials-intake --marketplace nyxandro/skills
```

Ни один из скиллов не требует другого. Bitrix24 Workspace работает так же и без Materials Intake.

Текущая версия записана в `package.json` и в шапке `skills/bitrix24-workspace/SKILL.md`. У каждой
версии есть метка в git и [выпуск](https://github.com/nyxandro/bitrix24-workspace-skill/releases)
с архивом скилла. [CHANGELOG.md](CHANGELOG.md) рассказывает, что изменилось.

</details>
