# 提示词本地生成器 · ComfyUI 插件

把勾选的视觉特征（风格 / 性别 / 人种 / 年龄 / 脸型 / 发型 / 表情 / 姿势 / 动作 / 服装 / 镜头光线 / NSFW）组合成「给本地 LLM 的优化指令文本」，再喂给你的本地 LLM 节点（如 **LLM TE 插件**）做描述优化，输出给 **Krea2 生图** 与 **MiniMax H3 视频**。

**面板关键能力**：可拖拽的二次元头像启动图标 · 分组树多选特征 · 中英对照输出 · 选择规则（内置 / 自定义，可多选）· 从本地导入 Skill（可重命名）· 图片·视频多帧反推（固定结构 + 分时段）· **生视频按时长自动分镜** · 功能配置（语言 / 视觉模型 + 自建「生成目标提示词」的增改删）· 关闭思考与思维链剥离。

## 安装

### 第 1 步：放进 custom_nodes

把整个 `comfyui_prompt_builder` 文件夹复制进 ComfyUI 的 `custom_nodes/` 目录。

> **别把备份目录留在 `custom_nodes/` 里**：ComfyUI 会把里面**每一个**含 `__init__.py` 的子目录
> 都当成插件加载。历史备份（`_backup_*/`、`_bak_*/`）如果在原地，会注册同名扩展、抢注同一个启动图标，
> 表现为**面板随机显示旧版界面**。详见文末「排错」。

### 第 2 步：安装依赖（重要，最容易踩的坑）

插件里的**视频反推**（后端解码抽帧）、**本地 GGUF 推理**、**自动获取规则**（网页抓取）
用到的包**不在 ComfyUI 核心依赖里**。只复制目录、不装依赖，会出现
「面板能打开、但反推/生成时报缺包」——这是 Issue 高发区。

**必须装进「ComfyUI 正在用的那个 Python 环境」**：

```bash
cd ComfyUI/custom_nodes/comfyui_prompt_builder
pip install -r requirements.txt
```

> **Windows 便携版（python_embeded）**没有全局 pip，用自带解释器：
> ```bat
> cd ComfyUI\custom_nodes\comfyui_prompt_builder
> ..\..\..\python_embeded\python.exe -m pip install -r requirements.txt
> ```
>
> **用 ComfyUI-Manager 的**：也可以点 Manager 的「Install missing dependencies」，
> 或照下表逐个 `pip install`。

| 依赖 | 用途 | 必需性 |
| --- | --- | --- |
| `aiohttp`、`numpy`、`Pillow` | 面板后端路由、图像/视频帧处理 | **必需**（ComfyUI 核心通常已自带） |
| `av`（PyAV） | 视频反推抽帧 ①首选 | 三者**至少一个**；新版 ComfyUI 核心已自带 `av` |
| `opencv-python` | 视频反推抽帧 ②次选 | ↑（若已有 `opencv-python-headless`，**不要再装**，二者会冲突） |
| `imageio-ffmpeg` 或系统 `ffmpeg` | 视频反推抽帧 ③末选 | ↑ |
| `llama-cpp-python >= 0.3.0` | 「本地 ComfyUI 模型」提供方（直读 models 目录的 GGUF） | 可选，但**本插件主打能力**，建议装；⚠ 必须 ≥0.3.0 |
| `torch`、`transformers >= 4.49` | `Qwen视觉模型加载器(接入点)` 在本进程跑 Qwen2.5-VL | 可选，体积数 GB |

> ⚠ **`llama-cpp-python` 不要直接 `pip install` 裸装**：它会尝试本地编译，Windows 上极易失败。
> 用预编译 wheel（`cu124` 换成你的 CUDA 版本，纯 CPU 用 `whl/cpu`）：
> ```bash
> pip install llama-cpp-python>=0.3.0 --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124
> ```
>
> ⚠ `opencv-python` 与 `opencv-python-headless` **不能共存**（会出现重复 `cv2` 报错）。
> 你的环境里已经有哪个，就用哪个，不要两个都装。

**装完自检**（下列命令在同一个 Python 环境下执行，装好的会打印 OK）：

```bash
python -c "import aiohttp, numpy, PIL; print('core OK')"
python -c "import av; print('PyAV OK')"        # 或 python -c "import cv2; print('OpenCV OK')"
python -c "import llama_cpp; print('llama.cpp', llama_cpp.__version__)"
```

### 第 3 步：重启 ComfyUI

重启后界面右上角会出现一个 **二次元女孩头像的小图标**（圆形按钮，见 `web/pg-avatar.png`）——它可以**拖到界面任意位置**，位置会自动记住；点一下就是整套面板（无需再单独运行 `web/app.py`）。若头像图片加载失败会自动退化成 🎛 兜底图标，功能不受影响。

> 改了 `web/*.js` 只需浏览器 `Ctrl+F5`；改了 `.py`（或新增了依赖）**必须重启 ComfyUI**。

## 面板（Lora Manager 风格，推荐入口）

面板是插件自带的 ComfyUI 原生前端（不是节点、不依赖外部网页服务），后端由 `server_ext.py` 注册到 ComfyUI 自身的 `PromptServer`，所以**只要 ComfyUI 在跑，面板就能用**。

**启动图标**：界面右上角是一个**二次元女孩头像的圆形小图标**（`web/pg-avatar.png`）。它支持**在界面上任意拖拽**——按住拖动即可换位置（拖动超过阈值才算拖拽，不影响点击），松手后位置会写进浏览器 `localStorage`，下次打开自动回到原位；位置会被约束在视口内，不会拖丢到屏幕外。点一下图标即展开 / 收起面板；头像加载失败时退化为 🎛 兜底图标。五个页签：

| 页签 | 功能 |
| --- | --- |
| **特征勾选** | 分组树导航（见下）+ 多选勾选框；底部可**补充自定义选项**（带删除）、**＋新页签**新增自定义大类（如「动物」）；顶栏可选**目标（生图 / 生视频，二选一，另含你在「功能配置」里自建的目标）**、**成人内容**开关、**扩写强度（标准 / 精细 / 极致）**；目标选「生视频」时会多出一个 **「时长(秒)」输入**（见「生视频时长与自动分镜」）；再往下是 **🎯 规则选择**（点「＋选择规则」弹出**可多选**的规则列表，见「生成规则 / Skill」）与 **📝「我的需求」** 入口；点「生成提示词」得到**中文 / English 左右对照**的提示词与 `features` JSON（均可复制） |
| **图片反推** | 选择图片 → 由**视觉模型**反推提示词，输出同样为中英对照 |
| **视频反推** | 选择视频 → **整段视频交给后端解码抽帧**（浏览器解不了的 mkv / h265 也行）→ 由**视觉模型**多帧反推；可选抽 **1 / 3 / 5 / 8 帧**，并把抽出的关键帧原样显示出来。输出为**固定结构 + 分时段**（见「视频反推」一节），中英各一份 |
| **📁 Skill 库** | 一个 skill = 一个 `.md` 文件：左侧文件列表（**逐条标注「内置」/「自定义」**），右侧直接编辑 front-matter 与规则正文；支持**保存到文件 / 删除文件 / 恢复内置 / 自动补全缺失的内置 skill / ⤓ 从本地文件添加**。从本地添加时会弹出**重命名窗**（可改 id、显示名称、用途），**与内置重名会自动改名绝不覆盖**，导入后立刻出现在「＋选择规则」里 |
| **功能配置** | 顶部是 **🧩 生成目标提示词**（自行添加，如 zimage：选 生图/生视频 → 起名 → 配规则 → ✨自动获取规则；每行可**修改 / 自动获取规则 / 删除**）；下面是 **语言模型 (LLM)** 与 **视觉模型 (Vision)** 两张卡片，分别配 `类型 / 地址 / 模型 / Key` 并保存（持久化到 `models.json`） |

### 特征勾选的分组树（大类 › 子标签 › 选项）

类别按语义收拢成两级/三级导航，面包屑可逐级回退，「已选汇总」列出所有勾选项并可点击跳转：

| 顶层 | 子标签 |
| --- | --- |
| 🧑 角色 | 性别 / 人种 / 年龄 / 脸型 / 发型 / 表情 / 妆容 / 姿势 / 动作 / **👗 服饰** |
| 👗 服饰（角色下） | 服装 / 服装细节 / 鞋履 / 袜类 / 配饰 |
| 🎨 风格与色调 | 主色调、风格 |
| 🎬 场景与镜头 | 场景背景、镜头与光线 |
| 动作物理反馈 | 力反馈 / 形变细节（建议生视频时开启） |
| NSFW 成人 | 成人向内容，**默认锁定**，需先勾选顶栏「成人内容」 |
| ＋新页签 / 自定义大类 | 用户自建类别自动出现在顶层 |

**NSFW 闸门**：顶栏「成人内容」未勾选时，`NSFW 成人` 页签呈灰色虚线且点击被拦（给出提示）；已勾选的 NSFW 选项也会被**自动剔出生成请求**（后端同样二次过滤），关闭开关时若正停在 NSFW 页签会自动退回。

> ⚠ **提示（重要）**：开启此功能时，请确认你**本地模型没有经过严苛的 NSFW 强对齐 / 安全过滤**，
> 否则模型会**拒绝生成**或输出「我无法协助」——那看起来像插件坏了，其实是模型侧的拒绝。
> 表现为：指令明明发出去了，返回的却是拒答文案或空白。遇到这种先换一个未强对齐的模型验证。
>
> 另外：NSFW 开关只是**让插件的选项与请求生效**，不改变模型能力，也不代表内容合规。
> 生成内容请遵守你所在地区的法律法规与模型许可条款。

> **关键**：图片 / 视频反推**必须**先配置**视觉模型**（如 Ollama 的 `llava`、`qwen2.5vl`，或 OpenAI 兼容视觉接口），否则反推不可用——面板会直接给出手动提示。语言模型用于「生成提示词」时优化描述。
>
> 面板生成的 `features` 可**复制**后粘贴进下面的 `特征选择器` 节点，接入你的工作流。

### 生视频时长与自动分镜（切镜）

选择目标为 **生视频（H3）** 时，顶栏会出现 **「时长(秒)」输入框**（1–120，默认 5）：

- **必填**：未填时长时，生视频的「生成提示词」会被拦下并提示先填时长——因为分镜要靠它来切。
- 后端用 `duration_block()` 按 **2 秒一段（最多 8 段，长视频自动加宽步长）** 算出时段表（如 `00:00-00:02`、`00:02-00:04`…），写进 LLM 指令，要求推理模型**按这个时长把整段视频分成若干分镜（切镜）**，每个分镜写成「起始-结束 + 分镜描述」。
- 指令明确要求分镜之间**衔接自然、符合逻辑**（避免硬切、避免时间码乱编），并把总时长写成 `总时长约 X 秒`。
- 生图目标不会出现这个输入框；切到生图时长自动忽略。面板生成后会回报 `时长：X s｜分镜时段：00:00-00:02…`。

### 生成规则 / Skill（一个 skill = 一个文件）

**每条生成规则就是一个 skill 文件**，放在插件目录的 `skills/` 下（`<id>.md`，带 YAML front-matter）：

```markdown
---
id: krea2_photo
label: Photography (写实摄影)   # 名称统一用「English (中文)」表述
target: krea2          # krea2=生图 / h3=生视频 / both=通用
order: 20              # 面板里的排序
tags: 写实,摄影
nsfw: false
---
写实摄影质感：全画幅相机配 35mm 或 50mm 定焦……
```

- **选择即调用**：特征勾选页点 **「＋选择规则」** 会弹出一个**可多选**的规则列表（标题即注明「可多选」），勾中的每个 skill 的规则正文会**按列表顺序叠加**注入到 LLM 指令的【生成规则约束】段。
- **内置 / 自定义一目了然**：列表每行右侧标注「**内置**」（插件自带）或「**自定义**」（你新建、追加过规则、或从本地文件导入的），弹窗顶部还会统计「内置 N 个 / 自定义 M 个」。
- **名称统一「English (中文)」**：内置 30 条的名称都是这种格式（如 `Photography (写实摄影)`、`One-Take (一镜到底)`），中英并排一眼看懂。
- **目标自动过滤**：目标选「生图」时只列出 `target: krea2` 与 `both` 的 skill；选「生视频」只列出 `h3` 与 `both`。切换目标会自动剔除不再适用的已选项。
- **目标自带规则会替换规则来源**：当目标选了你在「功能配置」里自建的**生成目标提示词**（如 `model:zimage`）时，规则会自动换成**该目标登记的那套规则**；若该目标**没填规则**，则回落到**默认所有适用规则生效**。生成结果下方会标注当前是「（自带规则）」还是「（未填规则 → 默认所有规则生效）」。
- **从本地文件添加**：「📁 Skill 库」页签上有 **⤓ 从本地文件添加**，可多选 `.md` / `.txt` 一次导入。选好文件后会弹出**重命名窗**，可逐个修改：
  - **id**（落成 `skills/<id>.md` 的文件名，重名会自动改名，绝不覆盖内置或已有文件）；
  - **显示名称**（写中文也能和内置区分，会显示在「＋选择规则」里）；
  - **用途** `target`（krea2 / h3 / both）。
  带 front-matter 的文件默认沿用其 `id / label / target`，纯文本按文件名派生 `import_<文件名>` 并补一份 front-matter。导入成功后界面会回报「实际存成了什么」；`README` / `_template` 会被拒绝。
- **自动补全**：首次启动（以及点「自动补全缺失的内置 skill」）会从 `_skill_defaults/` 把内置 30 条规则补回 `skills/`，**已存在的不覆盖**，因此你的改动不会被冲掉。想彻底关闭自动补全，在 `skills/.no_autofill` 放个文件即可。
- **内置母本**：`_skill_defaults/` 是干净母本，任何 skill 被改坏都能在「📁 Skill 库」里点「恢复内置」一键还原。
- **兼容旧数据**：读取优先级为 `skills/` 文件 → `custom_skills.json` 覆盖层 → 旧的 `skills.json`，老配置不会失效。
- 内置规则一览：**通用 8 条**（默认/极致画质/电影感/戏剧光/极简/商业/动漫/NSFW 艺术）、**生图 11 条**（写实摄影/人像/时装/产品/水墨/概念/风景/建筑/复古/微距/NSFW）、**生视频 11 条**（物理/一镜到底/慢动作/人像/产品/航拍/自然/循环/转场/粒子/NSFW）。

### 中英对照输出（所有模块）

生成 / 图片反推 / 视频反推的提示词都**同时产出中文与英文**：后端指令要求模型按

```
【中文】
…中文提示词…
【English】
…含义完全一致的英文提示词…
```

两段输出，再由 `prompt_templates.split_bilingual()` 拆成 `{zh, en}` 返回，面板用**左右两栏**并排显示、各自独立「复制」。
拆分是容错的：模型若只给了一段，会按中日韩字符占比判断它属于中文还是英文，不会把内容弄丢；面板还会提示「只返回了中文段」。

### 🧩 生成目标提示词（自行添加目标 + 增改删 + 自动获取规则）

「功能配置」页顶部的这张卡片用来登记**你自己的生成目标提示词**（例如 `zimage`）。用途只剩 **生图 / 生视频** 两项（原「提示词」用途已移除——它和「通用规则」重叠，徒增困惑；历史数据若为「提示词」会按 `both` 兼容读取）：

1. 点 **＋ 添加** → 选用途（**生图 / 生视频**）→ 起一个自定义名称（如 `zimage`）；
2. 写规则，或点 **✨ 自动获取规则（来源于网络）**：
   - 直接让**已配置的大模型**按名称给出 5-8 条可执行的提示词规则；
   - 也可以再填一个**来源网址**（该目标的官方 / prompt 指南页），后端会抓取网页正文（`urllib` + 去标签）交给大模型提炼，来源会标注为「网络资料 + 大模型提炼」。

   > ⚠️ **注**：网页抓取采用**轻量化实现**（`urllib` + 正则去标签），**暂不支持强动态渲染的网页**。
   > 现在很多模型官网（Krea、MiniMax 等）是 **SPA 单页应用**：正文由 JS 在浏览器里渲染出来，
   > 直接抓 HTML 往往只能拿到一堆 `<script>` 和占位 div，**提炼出来的规则会很空或跑偏**。
   > 另外需要登录 / 有反爬 / 走 JS 加解密的页面也抓不到。
   >
   > **抓取失败或内容不理想时**：请自己在浏览器里打开那个页面 → 全选复制正文 →
   > **直接粘贴进规则框**，再点「自动获取规则」交给大模型提炼（不带网址时它只用大模型自身知识，
   > 带上你粘的文本效果最好）。
3. 保存后规则会**同步成 `skills/model_<名称>.md`**（名称写成 `<名称> (用途)`），因此它会直接出现在「＋选择规则」多选里，可以被任何一次生成调用；用途映射为 `生图→krea2 / 生视频→h3`；
4. **列表里每行都有 `修改` / `自动获取规则` / `删除`**：改用途或名称会同步更新它的 skill；**删除**会连同它同步出的 skill 一起删掉（二次确认）；
5. 保存后目标会出现在**特征勾选页的目标下拉**（分组「我的生成目标提示词（自带规则）」）；选中它时，**生成规则会换成该目标登记的那套规则**，规则区显示「自带规则」提示；若该目标没填规则，则**默认所有适用规则生效**。

数据落在 `model_targets.json`（兼容旧字段，历史「提示词」用途按 `both` 读取）。

### 📝「我的需求」与 扩写强度

- **📝 我的需求**：点开是一个文本框，写你自己的诉求（场景、情绪、构图、必须出现的元素…），并提供 **6 个常用片段**（雨夜霓虹街头 / 逆光轮廓 / 电影感构图 / 动态抓拍 / 高级时装 / 动作张力）点击追加，带实时字数统计。保存后会在按钮上显示已填字数，并在下方给出一行摘要预览。
  生成时它作为 **【用户需求 · 最高优先级】** 注入，优先级高于已选标签与所选规则——**与标签冲突时以它为准**。
- **扩写强度**：三档，直接决定 LLM 指令里的目标字数与结构要求：

  | 档位 | 目标长度 | 说明 |
  | --- | --- | --- |
  | 标准 | 60-120 字 | 一句话式提示词 |
  | 精细 | 180-320 字 | 分要素展开 |
  | **极致 · 自动扩写** | 400-800 字 | 追加**十段式扩写大纲**（主体/外观/动作/镜头/光线/氛围/材质/色彩/构图/情绪），生图与生视频各有各的大纲；同时把输出预算抬到 4096 |

- 面板的这几项偏好（目标 / 扩写 / 已选 skill）会写进浏览器 `localStorage`，下次打开自动恢复。


## 视频反推（后端解码抽帧）

**为什么改到后端**：旧版在前端用 `<video>` + `<canvas>` 抽帧，**只能解浏览器放得动的编码**（h264/webm）。
遇到 **mkv / h265 / 变帧率** 的视频，`seeked` 不触发或直接报错 → 抽帧返回 `null` → 「视频反推失败」。
现改为**整段视频（base64）发给后端**，由 `video_utils.py` 解码抽帧，浏览器解不解得动都无所谓：

| 环节 | 说明 |
| --- | --- |
| 解码引擎 | **PyAV → OpenCV → ffmpeg** 三级回退（装了哪个用哪个），实测 mkv / h265 / h264 / avi 全部可解 |
| 抽帧 | 按视频时长**均匀取点**，用 `frame.time` 精确定位；PyAV 的 seek 会落到关键帧，因此会**向后解码到目标时间点**再取帧，保证 N 帧各不相同 |
| 帧规格 | 默认 3 帧、最长边 1024、JPEG q88；可在面板选 1 / 3 / 5 / 8 帧（上限 8） |
| 多帧推理 | 多帧作为**一次请求里的多个 image part** 送给视觉模型（`vision_multi`），让它能对比帧间差异推断运动与镜头 |
| 返回 | `{prompt, bilingual{zh,en}, frames[{t,w,h,dataUrl}], info{duration,size,fps,codec}, duration, segments[], engine}`；面板会把抽出的帧**原样展示**，让你确认送进模型的确实是这些画面 |
| 体积上限 | 面板侧 **48 MB**（`MAX_VIDEO_MB`）会提前拦截并提示先压缩；后端上传另有约 48 MB 上限（`aiohttp client_max_size`） |

> **视频太大怎么办（100 MB 的手机视频很常见）**：反推只看画面内容与运动，**不需要高码率**。
> 最快的做法——
> 1. **先在 ComfyUI 里裁短**：用视频剪辑 / 合成节点（如 `VHS_LoadVideo` + 裁剪、或任意视频裁剪节点）
>    把视频**剪到 10-15 秒**再导出，体积通常就降到几 MB；
> 2. 或者用 ffmpeg 压一遍（`-vf scale=-2:720 -crf 28` 基本能压到 1/10）；
> 3. 抽帧数也可以调小（面板可选 1 / 3 / 5 / 8 帧），但**决定因素还是时长与码率**。
>
> 10-15 秒已经足够覆盖「主体 / 人物 / 服饰 / 背景 + 分时段」的描述了；
> 太长的视频既传不上去，也不会让描述更准。

### 反推输出的固定结构（主体 / 人物 / 服饰 / 背景 + 分时段）

视频反推不再给一段散文，而是按**固定结构**输出，中英各一份：

```
【中文】
主体：画面里最主要、最吸引注意力的对象
人物：人物数量 / 身份 / 外貌 / 表情 / 动作状态（没有就写「无」）
服饰：服装、鞋帽、配饰及颜色与材质（没有就写「无」）
背景：场景、环境、天气、光线方向与景深
分时段：
00:00-00:02 该时段发生了什么
00:02-00:04 ……

【English】
Subject: … / Characters: … / Wardrobe: … / Background: … / Timeline: 00:00-00:02 …
```

- **时段表由后端算好**：按视频真实时长用 `timeline_segments()` 切成 `00:00-00:02` 这样的时轴（默认 2 秒一段，最多 8 段，长视频自动加宽步长），并**把时段表写进指令**，要求模型逐个覆盖，避免它自己乱编时间码。
- **多对象按时间序列**：指令里明确要求——画面中有多个互动对象（人物之间 / 人与物体 / 多主体）时，必须在「分时段」里按时间顺序写清「谁与谁 / 谁与什么，在哪个时段，发生了什么互动」。
- 面板会同时显示抽帧缩略图、`分时段时间轴（模型按此描述）` 提示，以及**中文 / English 两栏对照**结果。

> **多帧预算修复（重要）**：早期版本把每张图的 **base64 长度**当成提示词 token 来预留上下文，
> 结果是**帧数越多、输出预算越小**——3 帧起预算被压到 256 的下限，思维链一开头就被截断，
> 而且自动重试也突破不了这个下限，所以「多帧反推」几乎必失败。
> 现在按 **每张图固定 260 token**（实测 mmproj 投影后每图 220 token）计费，
> 帧数增加不再挤压输出预算，重试也真正有增长空间。

## 模型接入点（对接 Qwen Llama TE 的 Qwen 模型）

插件提供 **`qwen_model`** 输入 socket（自定义类型 `QWEN_LLAMATE_MODEL`），可接入 **`Qwen视觉模型加载器(接入点)`** 节点输出的 Qwen 模型，或外部 **Qwen Llama TE** 加载器（需其输出类型名等于 `QWEN_LLAMATE_MODEL`）。接入后：

- `本地LLM优化(直连/可选Qwen模型)` 与 `构建LLM指令(...)` 直接用该模型优化提示词（不再走 HTTP）；
- `视觉反推提示词(图->提示词)` 直接由该视觉模型反推，无需配置 HTTP 视觉服务。

> 模型对象需提供 `chat(prompt)` 与 `vision(prompt, image)` 方法；若外部对象接口不同，请在 `qwen_llamate.py` 的 `QwenLlamaTEWrapper` 中适配。`qwen_llamate.py` 延迟导入 `torch` / `transformers`，未安装时插件整体仍可正常导入启动。

## 本地 LLM 配置

- **本地 ComfyUI 模型（推荐）**：`type=local`，模型直接读 `<ComfyUI>/models/LLM`（或任何含 `llm` 的目录）里的 GGUF，
  用 llama.cpp 在本机推理，不需要 Ollama、也不需要任何外部服务；视觉反推需要该目录带 `mmproj*.gguf`。
- **Ollama**：`llm_base_url=http://localhost:11434`，`llm_model=qwen2.5:7b`（或你已 pull 的模型）
- **OpenAI 兼容**（LM Studio / vLLM 等）：`llm_type=openai`，`llm_base_url=http://localhost:1234/v1`

## 关闭思考与思维链剥离（重要）

Qwen3 / Qwen3.5 这类**混合推理**模型默认会先写一大段思维链再给答案。实测（Qwen3.8-27B-IQ3_XS，RTX 3090）：
模型把 900～1500 字符的英文推理**直接写进正文**，只输出一个孤立的结束标签，再输出中文答案。
若输出预算不够，正文会在思维链中途被截断 —— 用户就只能看到英文独白（`We need answer user's request ...`）。

插件对三级防线都做了处理，三处入口（本地 GGUF / Ollama / OpenAI 兼容 / Qwen Llama TE）统一生效：

| 机制 | 说明 |
| --- | --- |
| **追加 `/no_think`** | 「功能配置」里勾选**关闭思考**（默认开）后，指令末尾自动追加 `/no_think`，并换成强约束 system（禁止输出推理过程）。本机实测可把思维链砍掉约一半、耗时从 ~31s 降到 ~16s |
| **后端剥离思考块** | `text_utils.strip_think()` 处理四种形态：成对标签、**孤立的结束标签**（模型只输出 `</think>` 的情况，丢弃其前全部内容）、未闭合的开始标签（截断）、`Thinking Process:` 命名段落。剥离后还会去掉「答案是：」类前缀与整段引号 |
| **预算 + 自动重试** | 默认「最大输出长度」3072（可在面板调整）；若结果疑似仍是思维链（空／纯英文独白／被截断且思考块未收尾），会**自动加大预算重试**最多 2 次，仍失败则抛出带解决建议的错误，绝不把英文思维链当结果返回 |

> 补充：`reasoning_budget=0`（llama.cpp 原生「出现思考块立刻收尾」）也已接入，对会输出开始标签的模型有效；
> 对上述 27B（不输出开始标签）实测无效但无害。`llama-cpp-python 0.3.49` 无 `chat_template_kwargs`，
> 因此无法从 Python 侧直接传 `enable_thinking=False`，故采用「软开关 + 剥离」组合。

## 排错：面板显示的是旧版界面

如果刷新后看到的面板明显是**旧版**（例如「生成规则」还是一个下拉框、没有「📁 Skill 库」页签），
而 `curl http://127.0.0.1:8188/extensions/comfyui_prompt_builder/prompt_generator.js` 拿到的却已经是新文件，
那多半是 **`custom_nodes/` 里残留了插件的历史备份目录**（如 `_bak_pb_*` / `_backup_*`）。

ComfyUI 会把 `custom_nodes/` 下的**每个**含 `__init__.py` 的子目录都当插件加载，备份目录同样会注册
`app.registerExtension({name: "PromptGenerator.Panel"})`——两个**同名扩展**抢注同一个 `#pg-launch`
按钮，谁先注册谁的 JS 生效，于是出现「有时新、有时旧」的随机现象。

处理办法：把备份目录**移出** `custom_nodes/`（例如挪到 `ComfyUI/custom_nodes/../` 之外），再刷新页面。
可以这样自查：

```bash
ls ComfyUI/custom_nodes | grep -E "^_bak|^_backup|^_old"      # 应为空
curl -s http://127.0.0.1:8188/api/extensions | grep prompt_builder   # 应只有 comfyui_prompt_builder 一条
```

## 常见问题（先看这里，多数 Issue 属于这几类）

| 症状 | 大概率原因 | 怎么解决 |
| --- | --- | --- |
| 面板能打开，但**生成/反推时报错、日志里 `ModuleNotFoundError`** | 没装依赖（视频/本地模型相关的包不在 ComfyUI 核心） | `pip install -r requirements.txt`（见「安装 · 第 2 步」）；装完**重启 ComfyUI** |
| `pip install llama-cpp-python` **编译失败 / 装不上** | 裸装会尝试本地编译，Windows 上常失败 | 用预编译 wheel：`--extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124`（CPU 用 `whl/cpu`） |
| 装了 OpenCV 后 **`cv2` 相关报错 / 重复定义** | `opencv-python` 与 `opencv-python-headless` 同时存在 | 只留一个：`pip uninstall opencv-python-headless`（或反过来） |
| 面板**有时是新版、有时是旧版**（随机） | `custom_nodes/` 里残留了备份插件目录 | 见上一节「排错」——把备份目录移出 `custom_nodes/` |
| **找不到启动图标 / 面板打开是空白** | 前端扩展没加载（老版本或整合包路径差异） | ① 确认 `__init__.py` 里有 `WEB_DIRECTORY = "./web"`；② `Ctrl+F5` 强刷；③ 打开浏览器控制台看有无 JS 报错；④ `.py` 改动必须重启 ComfyUI |
| 选了视频但**反推失败 / 抽不出帧** | 缺解码器；或视频太大 | 装 `av` 或 `opencv-python` 或 `imageio-ffmpeg`；把视频**裁到 10-15 秒**再传 |
| 提示「视频超过 48 MB 上限」 | 面板侧的硬限制 | 先在 ComfyUI 里剪辑/压缩，或换更短的片段（见「视频反推 · 体积上限」） |
| 生成结果是一段**英文独白**（`We need answer…`） | 混合推理模型的思维链泄漏，预算被思维链吃光 | 在「功能配置」勾选 **关闭思考**；仍出现就把「最大输出」调大（如 4096） |
| 「自动获取规则」**提炼出来的规则很空 / 跑偏** | 目标网页是 SPA，`urllib` 抓不到正文 | 自己在浏览器里复制网页正文，**直接粘贴进规则框** |
| NSFW 选项生成了却**被模型拒绝** | 本地模型做了强 NSFW 对齐 | 换一个未强对齐的模型；这是模型侧拒绝，不是插件问题 |
| 分享插件时担心**泄漏自己的 API Key** | `models.json` 会保存 OpenAI 兼容 / Ollama 的 `api_key` | 仓库已带 `.gitignore` 排除 `models.json`；分享前**再手动确认**一次没有提交它 |
| 生视频**没有分镜 / 只有一段话** | 没填时长，或模型没按指令分段 | 在面板顶部填**「时长(秒)」**（生视频必填）；分镜由推理模型按时长生成 |
