# dsh-longing（暗涌）

**让她有「今天」。**

同一个角色，昨天刚亲过，今天第一句还是客客气气；凌晨三点和下午三点一个语气；
哄十句和冷落三天，态度一模一样 —— 这是「在提示词里写一段人设」永远补不上的地方。

暗涌在提示词前面加一层**会自己走的数值**：七个 0–100 的维度互相牵制，被你说的话推动，
没人理就慢慢回到日常，再渲染成一段只给模型看的内心状态。模型拿到的不是台词，是**此刻的处境**。

不绑定任何平台：它只维护状态、渲染文本、提供一个面板。谁发消息，是你通道插件的事。

---

## 一、它跟「提示词里写人设」差在哪

| | 写一段人设 | 暗涌 |
|---|---|---|
| 连续 | 每次从同一个基线出发，要么一直黏、要么一直冷 | 七个值随对话走。同一张牌，昨天的她和今天的她打出来不一样 |
| 会累 | 半夜和下午一个语气 | 疲劳压性欲：凌晨三点，「想要」会变成「想被抱着」 |
| 会忍 | 想要就写「想要」，然后一直想要 | `（性欲 − 理智×权重）× 意愿`。理智高就嘴上硬；**占有 90 时理智最多撑到 30**；意愿由好感给 —— 她想不想给，和你想不想要是两件事 |
| 会散 | 提一次别人，吃醋就永远锁在那 | 每维有自己的半衰期和日常值。**时间推得到日常，推不到 0**，也不会永久高位 |
| 有后果 | 说错话靠模型自己记得 | 23 个事件各自改几个值：说一句涨一点好感，说错一句掉得更多；说要走会压三天，第二天说话还带着 |
| 可调 | 改人设 = 改提示词，还要担心跟别处冲突 | 面板上拖一个数，说话方式跟着变。哪个事件动哪几维，文档里逐条列着 |
| 不绑死 | 提示词挂在某个客户端里 | 状态、面板、注入文本三件事；换成 QQ、网页、还是自己写的通道，都不改插件 |

放在一起就是一句话：**别人的角色是被描述的，这个角色是被算出来的。**

## 二、具体会变成什么样

- 它会**累**。熬夜到两点，欲望会转成「想被抱着」而不是「想要」；
- 它会**忍**。理智还高的时候，明明想要，嘴上还是硬的；
- 它会**熟**。同一个动作，关系远的时候是躲，关系近了才是给。**没到门槛不是一句「不行」**——差得远就真拦住，差一点就半推半就；
- 它会**记**。说过要走会压三天；第一次被碰、被要、被说走，各只发生一次；
- 它会**淡**。没人理，七个值各自回落到日常；占有欲会自己散掉；
- 它会**分场合**。身体冷、话冷、心冷是三件事，可以同时出现也可以互不相干；三样一起冷，它才像秘书；
- 它会**有事后**。做完那 45 分钟不是回到日常，是软下来、话变少、羞回来。

## 三、装完什么都不做也安全

默认值是按「陌生人装上」来定的，不是按作者自己用的状态定的：

- **不联网**。好奇心（第八条驱动力：多久没换过新东西）默认关；打开才搜，且判据是「失败即关闭」——配置缺一个键就当关。
- **无成人内容**。`nsfwEnabled` 默认关：露骨措辞、娇喘、亲密事件、诱惑图全部不给，只留日常互动。
- **不自己发消息**。主动开口默认关，得你在面板上打开。
- 面板数据接口要令牌，只绑回环地址，跨源请求直接被拒。

## 四、它不做的事

不生成内容、不替你绕过任何模型的安全策略、不自己发消息、不假装能测量真实情绪。它只是一个状态机 + 一段注入文本。

## 五、能做什么

| 能力 | 说明 |
|---|---|
| 七个维度 | 性欲 / 色情 / 占有 / 羞耻 / 理智 / 疲劳 / 好感，0–100 |
| 互相牵制 | 占有压理智、色情压羞耻、疲劳压性欲、好感撑占有。**软上限**：能越界，但每小时往回掉 |
| 回到日常 | 每维有各自的「日常值」和半衰期，没人理就慢慢回去；**时间永远推不到 0** |
| 有效欲望 | `（性欲 − 理智×权重）× 意愿`，意愿由好感决定——她想不想给你，和你想不想要是两件事 |
| 四档 | 心里想 / 暗示 / 开口要 / 直接上手，每档可以单独关，关掉高档会自动退回下一档 |
| 渐进解锁 | 抱抱 30 / 接吻 45 / 说露骨的话 50 / 脱 65 / 要她 70 / 绑住 80（好感为主） |
| 23 个事件 | 夸奖、哄、亲密、拒绝、提别人、凶、撒谎、说要走…改值也改语气；同类重复递减，单次封顶 ±6 |
| 余怨 | 有些事会在心里压 1–3 天，跨天不散 |
| 第一次 | 第一次被碰、第一次被要、第一次听说要走——各只触发一次 |
| 事后余韵 | `climax` 之后 45 分钟进「软下来的那段」：话少、想被抱、羞回来 |
| 三种冷 | 身体冷 / 话冷 / 心冷，分开说；三样同时冷才公事公办 |
| 负面阶梯 | 45 / 40 / 35 / 25 / 10 / 5 / 0，断点可配（`negBreakpoints`） |
| 被晾着 | 超过 `lonelyHours` 每天记一次失望；**睡眠窗内不算**（默认 23:30–08:00） |
| 心情日记 | 只写不推：事件进「让我高兴的 / 让我难受的」，日记正文只有她自己写的那几句话；写完进注入块影响语气 |
| 养成模式 | 调试模式默认关，数值只能靠聊天养；打开才能直接拖 |
| 注入块 | 每分钟生成 `欲望注入.txt` + 每通道一份，同时挂在 `globalThis.__dshDesireBlocks` |
| 网页面板 | 状态、软上限红线、解锁进度、事件按钮、日记、曲线、全部参数 |
| 令牌保护 | 数据接口要 `x-desire-token`；令牌放 `sessionStorage`，只绑回环地址 |
| 工具 | `longing`：`get / set / bump / preset / pause / event / events / diary / thought`，改值只在主人私聊（勾了 `qq` 通道时旧名 `qq_longing` 同时注册，v1.12 之前一直叫这个） |
| 生图后端（可选） | 探测 ComfyUI 是否在线，用状态影响画什么；未知态不会乱发指令 |
| 处境化描写（v1.13.0） | 注入的不是整句模板，而是「数值档位 + 当场处境（时间/在做什么/身体）+ 让她自己先想一遍」，同一个档位不会重复同一句 |
| 好奇心（v1.13.0，默认关） | 只看「多久没换过新东西」的第八条驱动力；打开后会自己联网搜一条话题，等到下次主动开口时讲；**默认关 = 默认不联网** |
| 成人内容总闸（v1.13.0） | `nsfwEnabled`：一个开关管住露骨的话、诱惑图、娇喘、亲密事件；默认关 |

## 六、安装

### 6.0 装之前确认

| 需要 | 说明 |
|---|---|
| DSH 0.2+ | 桌面版或命令行版都行 |
| Node 20+ | DSH 自带的就够（用到 `fetch`、`AbortSignal`、`Object.hasOwn`） |
| 一个 profile | 通常是 `~/.dsh/profiles/<名字>`，桌面版默认叫 `desktop` |
| 可选：通道插件 | 例如 `dsh-qq-onebot`。**不装也能用**面板和工具，只是它不会自己发消息 |
| 可选：ComfyUI | 只有「主动发图」需要，不装不影响别的 |

### 6.1 把代码放到 profile 能看见的地方

**推荐 symlink / junction**：复制出来的副本会跟本体分叉，改一处另一处不生效。

```powershell
# Windows（管理员或开启开发者模式）
git clone https://github.com/mearihaka/dsh-longing.git <代码目录>\dsh-longing
New-Item -ItemType Junction `
  -Path '<profile目录>\node_modules\dsh-longing' `
  -Target '<代码目录>\dsh-longing'
```

```bash
# Linux / macOS
git clone https://github.com/mearihaka/dsh-longing.git <代码目录>/dsh-longing
ln -s <代码目录>/dsh-longing <profile目录>/node_modules/dsh-longing
```

### 6.2 挂进 profile 的 `bundles`（**漏了这步，插件等于没装**）

编辑 `<profile目录>/package.json`，把包名加进 `bundles`：

```json
{
  "dsh": {
    "profile": {
      "bundles": ["…原来就有的…", "dsh-longing"]
    }
  }
}
```

为什么必须：DSH 启动时会逐个读 bundle 自带的 `cordis.patch.yml`，里面那条 `- insert:` 才是
「把插件插进配置树」。漏了这一步，插件一次都不会启动，而日志里只有一行
`patch: entry "dsh-longing" not found` —— 这是本插件最容易踩的坑。

### 6.3 重启，确认它真的起来了

重启 DSH（桌面版直接关掉重开）。启动日志里出现下面这行就算成功：

```
[dsh-longing] 状态目录：<状态目录>
```

没有这一行 → 回到 3.2 检查 `bundles`。

**状态目录**（插件所有文件都落在这里）按下面的顺序决定：

```
statePath（显式配）> DSH_LONGING_DIR 环境变量 > DSH 给的插件家目录
                                                （$DSH_HOME / ~/.dsh 下的 dsh-longing）
```

1.11 及以前默认是「进程工作目录 / workspace」，换个目录启动就是另一份状态。1.12 首次启动会把
老的 `<cwd>/workspace` 里的状态搬一次过来（新目录已有文件则不覆盖）。

建议显式配一个（profile 的 `cordis.patch.yml`）：

```yaml
- id: dsh-longing
  name: dsh-longing
  config:
    statePath: <绝对路径>/欲望状态.json
```

从旧版本迁移（只搬一次，没配 `statePath` 时生效）：

```yaml
- id: dsh-longing
  config:
    migrateFrom: <旧的状态目录>
```

| 文件 | 用途 |
|---|---|
| `欲望状态.json` | 七维数值、事件、余怨、主动与发图账本 |
| `欲望注入.txt` | 每分钟刷新的注入块（给「不认识自己名字」的老式通道插件读） |
| `欲望注入.<通道>.txt` | 分通道的注入块：`qq` / `bili` / `web` … |
| `欲望面板配置.json` | 面板配置的**全量快照**（schema 默认值 + 改过的值都写进去），`__panelKeys` 记着哪几个键是面板亲手设过的，用来给旧面板文件里的死键做过滤 |
| `欲望历史.json` | 24 小时曲线 |
| `心情日记.json` | 高兴的 / 难受的 / 心里想的 |
| `面板令牌.txt` | 面板鉴权令牌 |
| `活动时间.json` | 通道插件回报的「主人最后一次活动」 |

> 这些文件全是明文，含亲密偏好。**放本机，别同步网盘、别提交仓库**（`.gitignore` 已排除运行期文件）。

### 6.4 打开面板

```
http://127.0.0.1:<DSH端口>/dsh-longing
```

首次打开要粘一次令牌（内容在 `<状态目录>/面板令牌.txt`），存在 `sessionStorage` 里，关掉标签页就没了。
也可以直接带参数进：`…/dsh-longing?token=<令牌>`。

### 6.5 装完自检（四条，都能过就算装好了）

```bash
# 1) 注入文件在 10 分钟内刷新过（Windows）
(Get-Item <状态目录>\欲望注入.txt).LastWriteTime

# 2) 内容是「真换行」，不是字面 \n
node tools/preview.mjs [状态目录] qq unknown

# 3) 体检（含面板可达性，需要令牌文件）
node tools/doctor.mjs --panel http://127.0.0.1:<端口>/dsh-longing

# 4) 自己的测试套件
node --test --test-concurrency=1
```

面板能打开、滑块有值、「主动行为」卡底部那行不是「判据加载中…」→ 全部就绪。

## 七、配置

### 7.1 三层，优先级从高到低

| 层 | 在哪 | 说明 |
|---|---|---|
| 面板 | 状态目录的 `欲望面板配置.json` | 只保存「你在面板上真改过」的键，`__panelKeys` 记着是哪几个 |
| DSH 插件配置 | profile 的 `cordis.patch.yml` → `- id: dsh-longing` 的 `config:` | 推荐在这里配；改了要重启 |
| 代码默认值 | `src/config.js` 的 schema | 兜底 |

面板改动**不会**被「设置页改了」覆盖，反过来也一样 —— 想回到设置页的值，点面板「恢复默认」。

### 7.2 常见改法

```yaml
- id: dsh-longing
  name: dsh-longing
  config:
    statePath: /path/to/workspace/欲望状态.json   # 状态放哪
    channels: [qq]                                # 只对 QQ 注入
    personaName: 小满                              # 面板标题和工具说明用这个名字
    autoInitiate: true                            # 允许她主动开口（默认关）
    idleTriggerMin: 30                            # 冷场 30 分钟才考虑
    proactiveMaxPerDay: 6
    quietHours: 02:00-09:00                       # 她几点该安静
    activeHours: 09:00-02:00                      # 几点的对话带欲望
    debugMode: true                               # 想直接拖滑块改数值时
```

### 7.4 哪些键不能当配置改

`lust / lewd / possess / shame / resist / fatigue / affection / scene` 是**状态**，不是配置：

## 八、使用

### 8.1 面板

| 做什么 | 怎么做 |
|---|---|
| 临时改状态 | 拖滑块 → 点「保存」。没保存前 8 秒轮询不会覆盖你的拖动 |
| 套预设 | 平静 / 黏人 / 发情 / 病娇，一键 |
| 让她安静两小时 | 点「暂停」。暂停期间数值冻结，注入改成「正常聊天，不要撩」 |
| 恢复运行 | 暂停后按钮栏会多出「恢复运行」，点一下立刻解冻 |
| 调主动频率 | 「主动行为」卡：冷场分钟、每天/每小时上限、安静时段、性欲地板 |
| 看此刻能不能主动 | 同一张卡底部那行：能/不能、为什么、最早什么时候能 |
| 调语气档位 | 四档阈值（在心里想 / 暗示 / 开口要 / 直接上手） |
| 调负面敏感度 | **故意不在面板上**，见「为什么负面阈值不给你看」 |
| 记一件事 | 「刚刚发生了什么」卡：好话、坏话、她说停、事后，点一下记一次 |
| 看日记 | 只有你主动打开才看得到，她不会自己念 |

**只有行为参数会被保存**：点「保存设置」绝不会把当时的状态快照写进配置 —— 否则重启就会把数值
倒回上一次保存设置那一刻。

### 8.2 工具（给模型用的）

工具名默认 `longing`（勾了 `qq` 通道时旧名 `qq_longing` 同时注册）：

```
longing(action="get")                    # 读七维 + 档位（非主人只给一个档位词）
longing(action="event", name="praise")   # 把刚才发生的事记进数值
longing(action="events")                 # 列出所有事件名
longing(action="diary", minutes=3)       # 读最近几天的日记
longing(action="thought", text="…")      # 记一句她的心里话
longing(action="set"/"bump"/"preset")    # 直接改值，只在 debugMode 打开时可用
longing(action="pause", minutes=120)     # 暂停
```

`ownerOnly` 为 true 时，只有被通道插件登记过的主人会话能改值（见 5.3）。

### 8.3 让通道插件接上它（写通道插件的人看）

**A. 读注入块 —— 三选一**

```js
// 1) 分通道文件（推荐）
const mine = readFileSync(join(stateDir, '欲望注入.qq.txt'), 'utf8').trim()

// 2) 主文件：只有 channels 里勾了 qq 才给欲望块，否则是中性块
const main = readFileSync(join(stateDir, '欲望注入.txt'), 'utf8').trim()

// 3) 同进程零 IO
if (globalThis.__dshDesireBlock) systemPrompt += '\n' + globalThis.__dshDesireBlock
// 分通道版本：globalThis.__dshDesireBlocks.qq / .bili / .web
```

**B. 每句话推高数值**

```js
globalThis.__dshLongingNote?.()          // 默认就当「主人说话了」
```

**C. 登记主人会话（`ownerOnly` 的判据）**

```js
globalThis.__dshLongingOwnerSession?.(sessionId, 3600_000)   // ttl 默认 1 小时，最多 7 天
```

不登记也能跑，但那就是「没有通道在管主人」的状态 —— 插件会放行并打一条日志，
`ownerOnly` 等于没生效。dsh-qq 用它自己那张 `__dshQqOwnerSessions`，本插件继续认，两套共存。

**D. 主动开口：先问再发，发完回报**

```js
const gate = globalThis.__dshLongingProactive?.()
if (gate && gate.allowed === false) {
  // 别投这一轮；gate.nextAt 是「最早什么时候值得再问」
  return
}
// …真的发出去了之后
globalThis.__dshLongingMarkInitiate?.({ channel: 'qq' })
```

**E. 主动发图**

```js
const img = globalThis.__dshLongingImageGate?.()   // { allowed, kind, kindLabel, score, threshold }
// 出图 + 发出去之后
globalThis.__dshLongingMarkImage?.({ channel: 'qq' })
```

**F. 安全词**

```js
const stop = globalThis.__dshLongingPauseWord?.()  // 面板里配的那个词，默认「停」
```

拿不到任何钩子（没装本插件 / 热重载空窗）时请自行降级，别把主动说话整条功能弄没。

### 8.4 手动喂一次（不写代码）

面板「刚刚发生了什么」卡就是全部事件的入口；`longing(action="event")` 是给模型用的同一个表。
同一件事一小时内重复递减（1 → 0.5 → 0.33），单次封顶 ±6。

## 十、常见问题

**Q1 面板打不开 / 一直 401**
端口对不对（看 DSH 启动日志）；令牌是不是 `面板令牌.txt` 里那串；面板只允许同源请求。

**Q2 面板能开，但「判据加载中…」不动**
插件没起来或版本太旧。看日志有没有 `[dsh-longing] 状态目录：…`；没有就回去查 3.2 的 `bundles`。

**Q3 `欲望注入.txt` 不更新了**
插件进程没跑（tick 每分钟一次）。看日志；通道插件只认 10 分钟内的文件，超时它会跳过。

**Q4 开了 `autoInitiate` 她还是不主动**
按判据逐条对：`ownerOnly` 有没有把通道登记上（5.3 C）、冷场够不够 `idleTriggerMin`、
性欲有没有到 `initiateThreshold`（时间地板 30、高峰 +25，默认 45）、是不是在 `quietHours`、
当天/当小时额度用完没。面板「主动行为」底部那行直接给原因和 `nextAt`。

**Q5 她不主动发图**
`autoInitiate` 要开、`imagesPerDay` > 0、`性欲+色情` ≥ `imageThreshold`、而且必须聊过
（`everContacted`）。成人向还要 `nsfwImages: true`。

**Q6 在 DSH 设置页改了配置，像没反应**
1.12 起面板改动和设置页改动分开了（`__panelKeys`）。如果这个键以前在面板上存过，面板优先 ——
点面板「恢复默认」清掉它，就回到设置页的值。

**Q7 工具叫什么？为什么提示词里是 `qq_longing`**
1.12 起主名是 `longing`；勾了 `qq` 通道时旧名继续注册，老提示词不用改。

**Q8 换机器 / 搬家**
拷整个状态目录过去，在新机器上配 `statePath` 指过去；或者用 `migrateFrom` 让它在首次启动时搬。

**Q9 上下文被压缩（第 N 次）连发，一条回复都发不出来**
不是本插件的问题：`compaction-basic` 用了绝对值 `retainTokens` 会和阈值打架，改成比例制
（`thresholdRatio` + `retainRatio`）。

**Q10 ComfyUI 点「现在拉起」没反应**
`comfyLaunchScript` 路径要存在、扩展名是 `.ps1/.bat/.cmd/.exe`；填了 `comfyLaunchAllowDir`
就必须在它下面；10 分钟内只拉起一次。

**Q11 会让模型说更露骨的话吗**
它只维护状态、渲染提示词。真正露骨与否取决于你用的模型和通道有没有过滤 ——
默认 `nsfwImages: false`、`explicitThreshold: 55`，都在你自己手上。

## 十一、依赖与环境要求

**运行必需**

| 依赖 | 版本 | 谁提供 |
|---|---|---|
| Node.js | ≥ 20 | DSH 自带（用到 `fetch` / `AbortSignal` / `Object.hasOwn` / `node:test`） |
| DSH | ≥ 0.2.0 | 宿主 |
| `@deepseek-ai/schemastery` | ≥ 3.18.1 | DSH 自带（`peerDependencies`，不需要你装） |
| `@deepseek-ai/cordis` | ≥ 4.0.1 | DSH 自带（同上） |

**可选**

- 一个通道插件（例如 `dsh-qq-onebot`）—— 要它真的发消息；
- ComfyUI（本机回环地址）—— 要「主动发图」；
- TTS —— 只有通道插件实现了语音条才用得上。

**明确不需要**

外部数据库、Python、云服务、任何 API key。所有数据都是本地 JSON，面板是一条本地 HTTP 路由。

**联网（只有两处，都不默认发生）**

| 出口 | 什么时候 | 默认 |
|---|---|---|
| 探测 `comfyBaseUrl`（本机回环） | 开了 `comfyEnabled` 时按 `comfyProbeSec` 探一次 | 只探本机地址 |
| 好奇心搜索：`https://cn.bing.com/search?q=…` | 只有 `curioEnabled: true` 且攒够好奇心、过了冷却与每日上限才会发一次 | **`curioEnabled` 默认 false = 一次都不发** |

日记自写（v1.14.0）是第三条出口，但它走的是 DSH 自己的模型通道（`ctx.llm`），
不是插件直接发请求：一次一条、`diaryMaxTokens` 封顶（默认 260），
`diaryPerDay` / `diaryMinGapMin` / `diaryMinEvents` 三道门挡在前面。
不想要这条出口有两条路：`diaryAutoWrite: false`（只留模板），或者干脆不配模型。

好奇心那一处的查询词由**最近的对话内容**生成（技术词优先，撒娇词与名字会被剔掉，剔不动就退回
`curioTopics` 或通用词），一次最多 2 个 query、每天最多 `curioPerDay` 次（默认 6，约 2000~4000 token/次）。
关掉的方式有三种，任选：`curioEnabled: false`、`curioPerDay: 0`、或面板「好奇心」卡上的开关。
搜到的只是一条标题，挂在状态下等下次主动开口时讲；**搜不到就什么都不发生**，不会报错也不会卡住注入。

**和 DSH 版本的兼容性（实测，不是「应该可以」）**

`package.json` 里写的是 `engines.dsh >= 0.2.0`、`@deepseek-ai/cordis >= 4.0.1`、`@deepseek-ai/schemastery >= 3.18.1`。
下面是实际跑过的记录：

| DSH | Node | cordis | schemastery | 结果 | 日期 |
|---|---|---|---|---|---|
| `0.2.1-rc.3` | v24.21.0（DSH 自带） | 4.0.5 | 3.18.5 | 面板 200、注入正常、单测 155/155 全过 | 2026-11-08 |

同一份代码（差别只有 `curioEnabled` 的默认值）挂着跑的那台就是这个版本，所以「能装」不是推断，
是从在跑的进程里量出来的（`GET /dsh-longing/` → 200）。

三点提醒：

1. **`0.2.1-rc.3` 是候选版。** `engines.dsh` 只写了下限、没写上界，将来 DSH 0.3 改了面板或 HTTP 的契约，
   这个包也会照装不误 —— 那时候必须重跑 `node --test` 和 `node tools/doctor.mjs` 才能确认没断。
2. **装完要重启 DSH。** 插件是启动时按 `dsh.bundle.patch` 挂进配置树的，热挂不生效。
   重启后 `欲望注入.txt` 的 mtime 应该在 10 分钟内（见 6.5）。
3. **`GET /dsh-longing/api/config` 返回 401 是正常的** —— 面板接口要 `x-desire-token`（读 `<状态目录>/面板令牌.txt`）。

**平台**

Windows 上验证过；路径全部走 `node:path` / `fileURLToPath`，Linux / macOS 理论上可用。
拉起 ComfyUI 那段用 `powershell.exe`，在非 Windows 上会静默失败（不影响别的功能）。

## 十二、数值怎么影响说话

### 七个值

| 键 | 含义 | 默认 | 高了会怎样 |
|---|---|---|---|
| `lust` | 性欲 | 30 | 主动、贴上来、句子带呼吸 |
| `lewd` | 色情值 | 35 | 说得更直白 |
| `possess` | 占有 | 55 | 试探、吃醋、阴阳怪气 |
| `shame` | 羞耻 | 45 | 欲拒还迎，话说一半 |
| `resist` | 理智 | 50 | **刹车**，扣性欲，忍住不说 |
| `fatigue` | 疲劳 | 20 | 想要转成想被抱 |
| `affection` | 好感 | 30 | 亲近 / 依赖 / 客气 |

### 有效欲望

```
有效欲望 = （性欲 − 理智 × resistWeight）× 意愿
意愿     = 1 − affectionWeight × (1 − 好感 / 100)
```

`resistWeight` 默认 0.5，`affectionWeight` 默认 0.4。展开就是：

| 好感 | 意愿 | 性欲 92 / 理智 15 时 |
|---|---|---|
| 10 | 0.64 | 54.1 → 黏人 |
| 30 | 0.72 | 60.8 → 主动 |
| 50 | 0.80 | 67.6 → 主动 |
| 70 | 0.88 | 74.4 → 主动 |
| 90 | 0.96 | 81.1 → 发情 |

**这是整套里最关键的一个乘数**：没有它，性欲 90 就会直接推到「上手」——可一个关系疏远的人不会因为性欲高就扑上来，只会烦躁、躲开。**她想不想给你，和你想不想要，是两件事。**

设 `affectionWeight = 0` 可以退回纯数值口径。

理智是刹车：性欲 90 / 理智 90 时 eff 只有 45 —— **想，但忍着**，嘴上不承认。不是靠加一句「你要忍住」，是算出来就被压下去了。

### 四档

| eff | 行为 |
|---|---|
| < 40 | 想到，但不提 |
| 40 | 会暗示 |
| 55 | 会开口 |
| 70 | 主动靠近 |
| 85 | 直接要 |

### 负面阶梯

默认断点 **45 / 40 / 35 / 25 / 10 / 5 / 0**，每个值在断点间各有不同描述，越低越偏。低维度的描述会**压住**高维度的（互斥，不叠加）。

断点可改：配置项 `negBreakpoints`（六个降序数字，逗号分隔，默认 `45,40,35,25,10,5`）。改这一串就能整体重排敏感度，不用动代码。

**只有 `lust` 和 `affection` 归零会变「冷」**（语气淡、像陌生人、不接梗、不给台阶）。其它维归零各有自己的语义，注入里会点名：

| 归零的维 | 会变成什么 |
|---|---|
| `lust` / `affection` | 整个人是冷的，像对陌生人 |
| `resist` | 没有一丝自持，像换了个人 |
| `fatigue` | 亢奋得不正常，眼神发直 |
| `shame` | 完全不在乎体面 |
| `possess` | 你在不在都一样，她当你是外人 |
| `lewd` | 连调情都嫌多余 |

### 好感

- 主人每说一句：`+affectionGain`（默认 1）
- 每小时自然衰减 `affectionDecay`（默认 0.3）
- ≥ 60 亲近，≥ 80 依赖，< 30 客气

### 维度之间怎么互相压（v1.1.0）

七个值不是七个独立滑杆。越像人的地方在于**它们会互相牵制**：一个拉满，另一个就撑不住。

**关键是：上限不是墙，是「撑不久」。**

手动照样能把理智设到 100，只是接下来每小时往回掉一点。所以「占有 95 + 理智 90」不是不可能，是**只能维持一两个小时**——这比直接禁止更像人。

四条压制关系（全部单向，避免互相踩到 0）：

| 谁压谁 | 公式 | 按这个调 | 意思 |
|---|---|---|---|
| 占有 → 理智 | `理智上限 = 210 − 2 × 占有` | 占有 80 → 撑到 50<br>占有 90 → 撑不过 30<br>占有 100 → 撑到 10 | 独占的念头会烧掉自制。占有一高，就再也端不住 |

四条自然演化（每小时，慢到分钟级看不出来）：

- `色情` 向 `性欲` 靠拢：每小时追 15% 的差距（身体先热，嘴才会松；性欲退了它还会滞留一会儿）
- `疲劳`：睡前时段每小时 `+2.5`（熬夜是债），平时每小时 `−1.5`，但停在基线 20 —— 掉到 0 会变成「亢奋得不正常」，那是 bug 不是性格
- `理智` / `羞耻`：没被压着时每小时各回 `1.5` / `0.6`，但**不会超过各自的上限**
- `占有`：好感 60 以上才慢慢长，每小时 `(好感 − 60) × 0.02`

两条反向消耗：

- **性欲烧理智**：性欲 80 以上，每小时额外掉 `(性欲 − 80) × 0.04`
- **占有磨好感**：占有 85 以上，每小时额外掉 `(占有 − 85) × 0.03`

最后这条是有意的：**病娇是不稳定状态**。占有欲拉满靠的是好感在撑，不经营就会反过来把好感磨掉，然后占有的上限跟着掉，人自己退回普通关系。

**关掉**：`couplingEnabled = false`（七个值各自独立，只保留时间衰减）；或者 `couplingRate` 调小（`0.5` = 一切慢一半，`0` = 等价于关掉）。

**面板上怎么看出来**：滑块上拉不过去的那段标红，下面一行小字写清「上限 30（占有压着）」。超出时变「现在超了，正被往回拉」——那就是她在硬撑。

### 一句话、一个举动，都会改值（v1.2.0）

光靠时间演化，人是不动的。所以加了一层**事件**：他说了什么、做了什么，直接落到七个值上。

二十来种，分两类：

| 好的 | 效果 | 不好的 | 效果 |
|---|---|---|---|
| `praise` 夸奖 | 好感 +2，性欲 +2，羞耻 +2，理智 −1 | `cold` 冷淡 | 好感 −2，性欲 −3，占有 +1 |
| `comfort` 哄她 | 好感 +3，疲劳 −4，理智 +2 | `reject` 拒绝 | 性欲 −6，理智 +8，羞耻 +3 |
| `intimate` 亲密 | 性欲 +4，羞耻 −3，好感 +2 | `ignore` 无视 | 好感 −3，占有 +2 |
| `desire` 直白要 | 性欲 +5，色情 +3，羞耻 −4 | `mentionOther` 提别人 | 占有 +5，好感 −2 |
| `protect` 护着 | 好感 +3，疲劳 −2 | `compare` 和别人比 | 好感 −4，占有 +3 |
| `apologize` 道歉 | 好感 +2，占有 −2 | `blame` 凶她 | 好感 −4，性欲 −4，羞耻 −3 |
| `promise` 承诺 | 好感 +3，占有 +2，理智 +2 | `lie` 撒谎 | 好感 −5 |

| | | `neglect` 晾着 | 好感 −3，占有 +2 |

全部事件名用 `qq_longing action=events` 能列出来。

**三条规则，缺一条这套就会失控：**

1. **冲击会自己退。** 事件只推一把，剩下的交给上面那套演化——性欲会衰减、理智会回到上限、疲劳会落回基线。所以「一句夸奖让她热一晚」是自然发生的，不需要额外写规则。
2. **同一件事一小时内重复会递减。** 第 n 次效果是 `1/(1+n)`：说一遍 1，说三遍加起来 1.83，不是 3。**骂十句不会把好感一次打穿。**
3. **单次封顶 ±6。** 一句话改不了关系。

**唯一例外是安全词** `stop`（「停」「停一下」「不要了」）：不封顶，性欲直接 −30、理智 +20，并且**立刻暂停 30 分钟**。她说停就是停。

**三个入口**（都能用，互不冲突）：

- **通道插件自动**：dsh-qq 在主人私聊里扫一遍原话，命中就调用 `globalThis.__dshLongingEvent(name)`。保守匹配，宁可漏判不误伤；疑问句（「我好看吗」）不算夸奖。
- **模型自己登记**：拿不准的让模型判断，它读得到上下文和语气 —— `qq_longing action=event name=blame`。
- **面板手动**：卡片「刚刚发生了什么」里点按钮，用于补记和测试。

**还有一层**：值变了、语气不变，读起来就是失忆。所以最近 30 分钟的事件会写进注入块：

```
刚才的事还留在心里：他刚提到别人，心口一直发紧；被凶过，眼睛还酸着。
```

一小时之后自动消失（不会一直记仇）。

**关掉**：`eventGain = 0`（事件只记录不改值），或者干脆不接通道插件的那一行调用。

### 养成模式：数值只能养，不能调（v1.3.0）

默认 **调试模式是关的**。关着的时候：

- 面板滑块全部只读，预设按钮和「保存状态」都收起来；
- `qq_longing` 的 `set / bump / preset` 一律拒绝，返回「调试模式没开」；
- **只能靠聊天里发生的事改数值** —— 夸奖、冷淡、拒绝、提别人、说要走……就是上一节那张表。

想直接改：面板右上角勾上「调试模式」。勾上之后一切照旧，滑块可拖、预设可用。

为什么这样：能随便拖的时候，人就会把数值当滑杆试，角色变成参数实验台。关掉之后你只能通过「怎么对她」来影响她 —— 那才是养成。

### 每一档正反馈都能单独关（v1.3.0）

四档：**在心里想 → 暗示 → 开口要 → 直接上手**。每一档一个开关：

| 开关 | 关掉之后 |
|---|---|
| `feedbackThink` | 连「偶尔走神」都不会有 |
| `feedbackHint` | 不会用暗示、靠近、眼神试探 |
| `feedbackSpeak` | 不会直接开口要 |
| `feedbackAct` | 不会上手 |

关掉高档时**往下退一档表现**，不是突然沉默 —— 到了「上手」档但那一档关着，她就按「开口要」的样子来。这样不会出现「数值很高但人像断线」。

### 心情日记：她自己写（v1.3.0 只写不推；v1.14.5 起一天一篇）

`心情日记.json`，最近 30 天。两样东西分开存：

- **事件**：`recordEvent` 按事件表归到「让我高兴的 / 让我难受的」，带 `detail`（他到底说了什么原话）和
  `src`（面板 / 工具 / 日志）。它只当材料，不当正文——面板上已经不再把固定文案摊成一屏。
- **她写的**：模型写的那两三句话，`thoughts`。**一天一篇**：再写一次是覆盖，不是往后追加。
  面板里手写的「记下一句」标 `kind: mine`，不会被覆盖。
  写完的这两句会进注入块（`你自己今天写下的：「…」`），下一轮说话就带着这个心气。

写之前只喂「她今天知道的」：当天事件（`detail` 优先，带时间）、七维状态、之前写过的句子。
事件清单是**闭集**：每句要标 `[编号]`，或者与某条事实有 ≥2 个实词字重合，否则这句进不了日记——
心情可以自由，事实必须有出处。

写日记不设内容审查（脏话、旁白、短句、半句都留）。唯一的判断在流结束时：
`finish.reason.kind` 是 `length` / `error` 才算真截断，才砍最后一片。

### 被晾着（v1.3.0 / v1.4.2 修睡眠）

超过 `lonelyHours`（默认 6 小时）没有主人消息，**只算清醒时段**：

- **每天最多记一次**失望（不是每小时，那样一天就掉穿了）：好感 −3、占有 +2、理智 +1，写进日记的「难受」栏；
- 注入里多一句：`他已经很久没动静了，心里一直发慌——是不是不要我了；想问又怕太黏，只能自己憋着。`
- **睡觉不算**：`sleepWindow`（默认 `23:30-08:00`）里的沉默不计数、不扣好感。凌晨一点聊完、早上八点起床，她要到下午才会开始想你。

「清醒时长」是算出来的，不是按墙上的钟：总时长减掉落进睡眠窗口的那部分。所以白天真的半天没消息才算数。

这句不是模板消息推给你，是她这段时间的**状态**。通道插件主动开口时（dsh-qq 的 `proactive`）会自然带出来；不主动开口的话，下一条回复里也会带着这个底子。

`__dshLongingState().lonely` 就是给通道插件看的信号 —— 想让别的通道也用，读这个值就行。

`sleepWindow` 和 `quietHours` 都默认 `23:30-08:00`，但管的事不一样：`quietHours` 是「这段时间不主动找你」，`sleepWindow` 是「这段时间的沉默不算冷落」。

### 主动开口的判据归这里（v1.11.0）

v1.10.0 及以前，面板「主动行为」那一栏的**频率类键**（`autoInitiate` / `idleTriggerMin` /
`proactiveMaxPerDay` / `quietHours` / `cooldownMin` / `urgeRepeatMin` / `proactivePerHour` /
`proactiveCooldownMin`）只写在配置 schema 和面板可写清单里，**代码里没有任何读取点**——
面板改了不生效，真正限速的是每个通道插件自己写的定时器。dsh-qq 那边一个
`proactiveSilentMs: 120000` 就能把它刷成 3 分钟一次，一小时烧掉一百多万 token。

现在判据统一在 `src/proactive.js`，一句话分工：

```
longing  = 她现在想不想、能不能、多久一次     （主观世界）
通道插件 = 真的发出去、真的花钱               （执行层，只问一句门开没开）
```

怎么用（通道插件侧）：

```js
// 发之前问一句
const gate = globalThis.__dshLongingProactive?.()
if (gate && gate.allowed === false) return          // gate.reason 说明原因，gate.nextAt 是最早可再试的时间
// 真发出去之后回报一笔（[SILENT] 不算，别占额度）
globalThis.__dshLongingMarkInitiate?.({ channel: 'qq' })
```

HTTP 也有：`GET /dsh-longing/api/proactive`（带 `x-desire-token`），返回同一份判据：

| 字段 | 含义 |
|---|---|
| `allowed` | 现在能不能主动 |
| `reason` | 不能的原因：`off` / `paused` / `never` / `quiet` / `inactive` / `cold` / `lowlust` / `cooldown` / `hourly` / `daily` |
| `nextAt` | 最早什么时候值得再问（毫秒时间戳），通道插件可以直接睡到那时候 |
| `usedToday` / `limitToday` | 今天已经开口几次 / 上限 |
| `usedLastHour` / `limitPerHour` | 这一小时 / 上限 |
| `coldMin` / `idleTriggerMin` | 冷场多少分钟 / 门槛 |
| `tier` | 当前档位（0 没有 / 1 心里想 / 2 暗示 / 3 开口 / 4 上手） |

判定顺序（先到先否）：`autoInitiate` 关 → 暂停 → 没聊过 → 安静时段 → 活跃时段 →
冷场不够 → 性欲低于 `initiateThreshold` → 两次太近（发情档位用 `urgeRepeatMin`，
平时用 `cooldownMin`/`proactiveCooldownMin`）→ 这小时次数满 → 今天次数满。

冷场只从**你最后一次说话**算起；两次主动之间的间隔由 `cooldownMin` 单独管。
这样「你一直不回」和「她刚说完」是两件事，不会互相顶掉。

「今天开口几次」记在状态文件的 `proactiveLog`（最近 64 次时间戳），跨天自动归零。
面板那张卡底部会直接显示**此刻能不能主动、为什么不能、下次最早多久**——
不再是「改完像没反应」。

### 处境化描写：不再念稿（v1.13.0）

以前每个档位吐一句写死的话，模型拿到只能照抄或改几个字，换十套文案照样像在念设定稿；
而且干跑发现 `lust 45 / resist 55` 算出来 `eff≈14`，绝大多数时间走的都是写死得最厉害的那一档。

现在注入块拆成三层：

| 层 | 给什么 | 例子 |
|---|---|---|
| 数值 | 只当参数选档，不当句子 | `lust 62` → 落 60 档 |
| 处境 | 时间 / 在做什么 / 身体，各抽一条拼起来 | `外面在下雨，你站在窗边，看着窗外的车灯发呆`／`坐久了腰发酸` |
| 自述 | 要她在开口前先在心里过一遍 | `先在心里过一遍：这会儿身体是什么感觉、想不想开口、为什么还不动` |

关键在于第三层：**想法由模型当场产生**，上面给的只是处境和参数。处境按「分钟数 + 数值和」做种子抽取，
所以同一档位十分钟内不会重复同一句；抽签代码在 `src/mood.js`（纯函数，无 IO）。

### 好奇心：她会自己去翻点新东西（v1.13.0，默认关）

原来的主动开口只有性欲和色情两个动机 —— 数值一被满足就掉下去，结果「陪得越久越不会被主动找」，
正好反着来。好奇心是第八条驱动力，**不看亲密，只看多久没换过新东西**：

```
没有新东西 → 每小时 +curioGainPerHour      说过一次话 → −curioDropOnTalk
涨到 curioSearchAt（默认 65）→ 允许去搜一次  冷却 curioCooldownMin(90 分) / 每天 curioPerDay(6 次)
搜到一条 → 挂成 pendingTopic（6 小时内有效）→ 下次主动开口时讲，讲完作废
```

四道门全过才发请求，心跳里只做算术（`tickCurio` / `shouldSearch`）；真发请求的只有 `searchTopic`
一处，超时或解析不到就返回空，**不会卡住注入**。

**隐私与成本，写在明面上**：

- `curioEnabled` 默认 **false**，也就是装完默认一次都不联网；
- 查询词由最近一句对话生成：技术词优先，名字、撒娇词、纯符号会被剔掉；剔不动就退回 `curioTopics` 或通用词；
- 发往 `cn.bing.com`（与你浏览器搜同一类请求，不带任何状态文件内容，只带那几个词）；
- 每次约 2000~4000 token（抓回来的标题要进上下文），每天上限默认 6 次；
- 不想要就 `curioEnabled: false`（默认）或 `curioPerDay: 0`，两者都能立刻停。

### 成人内容总闸（v1.13.0）

`nsfwEnabled` 默认 **false**，是唯一的成人内容开关：关着时不说露骨的话、不发诱惑图、不发娇喘、
不记亲密事件；`nsfwImages` 只对图片生效，总闸关着时它没有意义。
以前这两处判据口径不一致（判据按 `!== false`、注入按 `=== true`），会出现「她既不敢发诱惑、

> 通道应当退回自己的规则，不能因为依赖方缺位把主动说话整条功能弄没。

### 渐进解锁：她肯到什么程度（v1.4.0）

数值到了不等于什么都能做。**关系到了一定程度，才轮得到那件事**：

| 能做什么 | 门槛 |
|---|---|
| 抱抱、摸头 | 好感 ≥ 30 |

### 余怨：一件事能压好几天（v1.4.0）

`说要走(3天) / 撒谎(2) / 硬来(2) / 嫌身材(2) / 凶(1) / 和别人比(1)` 会留在 `state.grudges` 里，注入变成：

一小时就忘掉的话，昨天闹的别扭今天就没人记得——养成游戏最缺的就是「昨天那件事还在」。

### 第一次（v1.4.0）

第一次被碰、第一次被要、第一次听他说要走、第一次没被听、第一次说「不要」——各触发一次，24 小时内带专属语气：

```
这是第一次被他这样碰——手不知道往哪放，心还在抖。
```

之后的每一次都回到日常。养成游戏的分量全在这种「只发生一次」的地方。

### 想要，和敢说（v1.4.1）

`lust` 和 `lewd` 是**两个不同的东西**，以前它们会互相趋同，现在故意分开：

| | 含义 | 由什么驱动 | 决定什么 |
|---|---|---|---|
| `lust` 性欲 | **想要**（身体） | 事件、聊天、高峰、性欲本身 | `urge` 四档：想不想主动 |
| `lewd` 色情 | **敢说敢做**（尺度） | 事件推高、慢慢忘记 | `expr` 四档：能说到多露骨 |

三条机制保证它们不趋同：

1. **单向带动**：`lust` 高的时候只把 `lewd` 往上带一点（0.05/h 系数，原来 0.15）；
2. **尺度会忘**：`lewd` 高于 `lust` 时反而每小时回缩 0.3 —— 做过的事不会一直算数；
3. **冲突就是状态**：两个值打架时，注入给的不是两条独立描述，而是一句矛盾：

```
想要，可说不出口：嘴上绕开，身体先出卖你——呼吸、躲不开的眼神、抓紧的手指。
嘴上没刹车：什么话都敢撩，身体却是凉的，逗完自己也不接——像拿他试手。
```

对照关系：

| | `lewd` 低（不敢） | `lewd` 高（敢） |
|---|---|---|
| **`lust` 高（想要）** | 憋着，身体先于嘴 | 直白地要 |
| **`lust` 低（不太想）** | 淡 | 嘴上野，身体懒 |

**`interactionLust` 默认改成 0.1**：说十句话才推高 1 点。以前是 1，聊几句就把性欲顶到 100，`lewd` 跟着涨，两个值就分不开了。

## 十三、为什么不把情感塞进 RAG

这个项目最早不是从「状态机」开始的。

一开始也走过检索那条路：切块、向量化、按需召回，把相关记忆拼回提示词。为了让检索「更懂情绪」，里面加过情感标签、情绪权重、关系衰减，越加越多。结果是系统越来越大，角色却越来越不像同一个人。

问题不在于检索不准。问题在于：**当你太怕上下文太长、压缩得太狠，最先被洗掉的恰恰是情感连续性。** 一段带着语气、停顿、没说完的话，被压成一句「用户表达了不满」——信息还在，语感没了。下一次开口，模型知道设定，却接不住上一刻的情绪。被销毁的不只是操作上下文，还有关系状态赖以维持的那些条件。

社区里更常见的做法是：发现检索不够「有情」，就往检索里继续加情感模块。情感分类、情绪打分、人格注入、分层记忆抽取，一层一层叠上去，想让检索管道自己「长出」情感能力。这个方向也试过。后来发现，臃肿不是因为功能多，而是因为**把情感当成了一种需要被索引和召回的对象**。情感不是一条记录，不是一个标签，不是向量空间里能 top-k 捞出来的碎片。你越把它往检索管道里塞，就越需要更多后处理去修补它造成的断裂，系统也就越脆。

所以这里换了一条路：**不存情感事实，只维护情感状态。**

七个维度互相牵制，被一句话推动，没人理就慢慢回落到日常；状态渲染成一段第一人称的内心处境，直接注入给模型。模型拿到的不是「检索到的过去」，是此刻的她。

RAG 适合做外挂知识库：文档、规范、长期不变的事实，检索得很好用。但情感连续性不该从数据库里查出来——它应该顺着完整的上下文流，从一个会自己流动的状态里长出来。这就是砍掉那条管道、只留一个状态机加一段注入文本的全部理由。

## 十四、为什么这样设计

### 1. 为什么模型会「配合」数字

它看到的不是 `lust: 87` 这个数字，而是这段：

```
[底层状态·第一人称]
身体先热起来，注意力总往她身上跑，但还在硬撑，用别的话题盖过去…
写法：2~4 句，动作放（），不解释为什么。
```

数字只是输入，模型读到的是**第一人称的当下状态 + 写法约束**。它不需要理解公式，只需要照着这段演。

所以调数值有用——但前提是**这段真的进了提示词**。检查方法：看 `欲望注入.txt` 的内容，和通道插件实际拼进 prompt 的东西是不是同一个。

### 2. 为什么负面阈值不给你看

面板上能看到档位（40/55/70/85），看不到负面那七个断点。

原因很简单：**看见了就会去卡点**。知道 25 是「明显冷淡」、24 是「只是平」，就会忍不住把自己调到 26 试效果，角色就变成了参数实验台。

藏起来之后，你只能描述感受（"今天怎么这么淡"），然后调一个数看它变不变——这才是它该有的用法。

想要具体值：`src/prompt.js` 里的 `NEG` 表，或 `src/config.js` 的 `coldLust / shyLewd / distantPossess / numbAffection`。

### 3. 为什么「暂停」要真的停

早期版本的暂停只是写了个 `pausedUntil` 时间戳，没人读它——数值照样衰减，注入照样生成。

现在的暂停：`tick()` 冻结、`__dshLongingNote` 不涨、注入层出一段「已暂停，正常聊天」。**暂停不是关插件**，是让它这两小时别演。

手动操作不受暂停影响：面板滑块和 `qq_longing` 工具照常能改——那是你直接的意图，不该被自己设的暂停挡住。冻结的是「自动演进」。

### 4. 注入块为什么永远不为空

更早的版本在低欲望时返回空字符串，本意是「没什么可说的」。

结果是：通道插件拿到空字符串，退回它**自己那套旧模板**，于是你以为关掉了，其实换了个更差的模板在说话。

现在任何状态都有一段非空文本，最差也是「没什么欲望，语气平，1~2 句」。

### 5. 串话是怎么修掉的（真实踩坑）

现象：它会自己写对方的台词，再回答自己编的那句。

排查中发现两个真凶：

1. **框架句**。私聊规矩里写着「这是两个人的对话」——模型把它读成「写一段双人对话」，于是两边都写了。改成「你在给她发消息，只写你自己要回的那一句」；
2. **注入缺约束**。防串话的那句只写在完整版注入块里，低欲望走的是短块，被提前 `return` 掉了。现在每个分支都带「只写你自己说的话」。

顺带把拆条正则里的 `…` 去掉——省略号单独成一条气泡，看起来就像两个人在轮流说话。

**教训**：抽象禁令打不过具体框架。「绝不替对方说话」不如「只写你自己这一句」。

### 6. 为什么衰减不能取整（v1.0.0 最严重的 bug）

1.0.0 的 `clamp()` 内部带 `Math.round`，而 tick 每 60 秒算一次衰减：

```
decayPerHour 3 × (60s / 3600000) = 0.05  →  round(91.95) = 92
```

**每次衰减量小于 0.5，全被取整抹平，而且 `updatedAt` 每轮重置，残差永远攒不起来。** 结果：性欲只能靠聊天和高峰期加成往上涨，一到 100 就再也下不来，注入永远停在最高档。

好感更惨：`0.3/h ÷ 60 = 0.005`，同样永远是 0。

修法两条一起上：**内存里保持浮点**（`clampFloat`，不取整），只在落盘和展示时取两位小数。现在 `node --test` 里有一条用例专门守着它：连跑 120 次 tick，性欲必须掉掉 6 左右。

### 7. 为什么「没探测到」不等于「图床没开」

1.0.0 里 `comfy.up` 初始是 `false`，探测又是异步的，而第一次注入块在探测之前就生成了。于是**首帧永远写「生图后端没在跑，别调 generate_image」**——哪怕 ComfyUI 就在 8188 开着。

更糟的是探测可以被 `comfyEnabled: false` 关掉，而注入层把「没探测」也当成「不可用」，这两个概念被混成了一个。

现在生图后端是三态：

| 状态 | 注入里写什么 |
|---|---|
| `true` 在线 | 按 `nsfwImages` 给生图指令 |
| `false` 确定连不上 | 才说「图床没开，别反复重试」 |
| `null` 没探测 / 探测关了 | **什么都不说**，交给她自己判断 |

关掉探测 ≠ 关掉生图。

### 8. 为什么「保存设置」不能顺手存状态

面板的「保存设置」以前会把 `Object.keys(配置)` 全量提交，而 `lust`/`lewd`/`affection`/`scene` 当时也被算成「可写配置」。于是每次保存设置，都会把那一刻的数值快照写进 `欲望面板配置.json`；下次启动时 `base` 又反过来覆盖状态文件——**重启就倒回上次保存设置那一刻**，还附带 `scene: 0` 这种脏值（清空输入框时 `Number('') = 0`）。

现在状态键和行为参数彻底分家：`/api/config` 的白名单里没有状态键，启动时合并方向是 `{...base, ...state}`（状态优先），旧的脏快照会被自动清掉。
